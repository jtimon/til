** FIXED #341 Leading-dot enum variants in switch/match cases: `case .Body:`

*** Post-mortem

    Nothing was broken; the enum name was just redundant. Every arm of a
    switch repeated a name the subject expression had already fixed:

    #+begin_example
    switch e.node_type {
    case NodeType.Body:
    case NodeType.Decl(dd):
    case NodeType.FCall:
    case:
    }
    #+end_example

    Fix: the enum name may now be elided in a case pattern, so
    ~case .Body:~ means ~case NodeType.Body:~. Jai has the form and Odin
    picked it up.

    Split across the two passes that each know half the answer:

    - Parser ([[file:../../src/self/parser.til][src/self/parser.til]],
      ~parse_primary~): a leading ~Dot~ produces an ~Ident("")~ receiver
      and is deliberately NOT consumed, so the existing postfix chain
      builds ~FieldAccess("Body")(Ident(""))~ -- byte for byte what
      ~NodeType.Body~ builds -- and the FCall form for a payload binding
      ~.Decl(dd)~ falls out of the same loop with no new code. An empty
      Ident cannot come from source (the lexer needs at least one
      character), so it is an unambiguous marker rather than a guess.
    - Typer ([[file:../../src/self/typer.til][src/self/typer.til]],
      ~qualify_dotted_case_patterns~): fills the name in from the
      subject's type once the subject is inferred. Every later pass keeps
      seeing the fully qualified pattern it always saw.

    Two call sites, both necessary, and finding the second was the one
    real trap: ~infer_switch_stmt~ handles statement switches, but a
    ~match~ types its arms in ~infer_match_expr~ BEFORE the shared switch
    desugar ever runs, so a dotted arm there failed with "undefined
    function ''" until it got its own call. In ~infer_switch_stmt~ the
    call must also sit BEFORE the ~switch_is_clike~ dispatch, which
    returns early for payload-free enums.

    Scope: the first commit did switch/match case patterns only; the
    follow-up widened it to every position that knows the type it expects,
    which is Swift's answer rather than Rust's (Rust has no shorthand at
    all). ~qualify_dotted_expr~ is the shared "fill the name in from the
    expected type" step, called from six places:

    - a typed declaration's RHS -- ~s : Shape = .Nothing~
    - an assignment to a typed target -- ~s = .Circle(5)~
    - an argument at an enum-typed parameter -- ~f(.Nothing)~
    - a return in an enum-returning function -- ~return .Nothing~
    - an enum-typed struct field default -- ~kind : Shape = .Nothing~
    - a constructor argument -- ~Holder(kind = .Nothing)~

    Not the argument of a VARIADIC or kwargs callee: there the positional
    argument-to-parameter mapping is not reliable, and qualifying against
    the wrong parameter could silently name a different enum that happens
    to have a variant of that name. Those still need the name written out,
    and say so.

    Template enums need no special casing: by the time the typer runs,
    ~Option(I64)~ is already ~Option__I64~, which is exactly the name the
    pattern wants.

    Failure modes, both of which used to surface as a symbol named "" --
    the empty receiver leaking into a diagnostic, which reads like a
    compiler bug:

    - In a case pattern over a non-enum subject: "a leading-dot pattern
      needs an enum subject". The receiver is then filled with the
      subject's type name anyway, purely so the follow-on diagnostic reads
      "struct 'I64' has no field 'Nope'".
    - Anywhere with no known enum type (~x := .Nothing~, a variadic
      argument): ~infer_ident_expr~ recognises a surviving empty receiver
      and reports "a leading-dot enum variant needs a known enum type in
      this position". One catch-all, so no position can leak the marker.

    Regression tests in [[file:../../test/enums.til][test/enums.til]]:
    ~test_dot_pattern_payloads~, ~test_dot_pattern_mixed_with_qualified~,
    ~test_dot_pattern_payload_free_enum~,
    ~test_dot_pattern_shared_and_guarded~, ~test_dot_pattern_in_match~,
    ~test_dot_pattern_template_enum~, ~test_dot_typed_decl_and_assign~,
    ~test_dot_call_arg_and_return~ and
    ~test_dot_field_default_and_ctor_arg~; the non-enum-subject,
    unknown-variant, no-expected-type and variadic-argument cases in
    [[file:../../test/typer_errors.til][test/typer_errors.til]].

*** Original report

   Instead of repeating the type in all cases:

   #+begin_example
   switch e.node_type {
   case NodeType.Body:
   case NodeType.Declaration:
   case: // etc
   }
   #+end_example

   could be:

   #+begin_example
   switch e.node_type {
   case .Body:
   case .Declaration:
   case: // etc
   }
   #+end_example
