** FIXED #463 Call til from the JVM through generated bindings

*** Post-mortem

The JVM half is done and the BEAM half is split into #479. Every ~mode lib~
build generates a plain-Java class (Java 8 source level, so every JVM
language and Android's toolchain take it) and a C bridge against ~jni.h~;
~til build --jni~ / ~til install --jni~ compile the bridge and jar the class
with the host JDK. Scalars of every width, Str, Vec(Str), Vecs of scalars
(primitive arrays) and of structs or enums (handle arrays), structs and
enums (AutoCloseable handle classes), globals, throws (~TilError~) and
FuncSigs (functional interfaces both ways: Java lambdas called from til,
til closures as ~<F>.Til~ called from Java) cross in every ownership mode
-- borrowed, ~own~, ~mut~, ~returns ref~ -- as parameters, results, fields,
payloads, globals and callback arguments. What stays unbound (Dynamic,
shallow Str, other collections, variadics, a FuncSig global or field, a
throw type a ~TilError~ cannot build) is a comment in the generated class
and a ~note:~ on stderr when the library is built. The tests are
~test/jni.til~ (jni_lib, with ~test/JniLibTest.java~),
~test/library_namespace.til~ (the library the Python binding checks) and
~test/install.til~ (an installed compiler's ~install --jni~), each with a
Linux ASAN leak run; ~make test NO_JVM=1~ skips the JDK runs. Android
packaging stays with #462.

Along the way the leak runs found two compiler bugs, fixed in the commits
that exposed them: an ~own~ closure parameter was never dropped
(~test_own_closure_param_dropped~), and assigning a closure to a ~mut~
closure parameter emitted invalid C (~test_mut_closure_param_assigned~,
both in test/closures_compile_escape.til). Still open in til itself, outside
the binding: a ~mut~ local initialised with a capture-free ~func~ is lifted
to a top-level function (so it cannot be reassigned or passed ~mut~), and
passing a struct's closure field as a closure argument crashes the compiler.

Make til libraries usable from the JVM (Java and every JVM language, Android
included) the way Python already uses them: a native ~mode lib~ library plus
generated bindings, without translating til to the VM. The managed backend
is cancelled (JVM #375): til's raw-memory and ownership model maps down to
machine targets and fights managed VMs, while a binding keeps til native
and lets the VM keep what it is good at. The BEAM (Erlang, Elixir) half,
originally part of this issue, is #479.

*** The bridge each VM needs

Python's bindings use ~ctypes~: plain source that loads the library at run
time, nothing compiled. The JVM has no portable equivalent:

- JVM: JNI is the bridge that works on desktop JVMs and Android alike (the
  JDK's FFM, ~java.lang.foreign~, is desktop-only; ART has none). JNI needs a
  small C bridge compiled against ~jni.h~, which only a JDK or the Android
  NDK provides. The generated side is plain Java, which every JVM language
  (Kotlin, Scala, Clojure, ...) calls natively, so no language gets wrappers
  of its own ([[../cancelled/454.org][#454]], cancelled).

Til already emits C, so the bridge itself can be generated C compiled into
the library (or beside it). Generating its sources needs no JDK; compiling
it does.

*** Scope

  - Reuse the library's exported interface and native ABI as the single
    source of truth, as the Python bindings do; no hand-maintained
    declarations per language.
  - Specify numeric widths (unsigned types included), strings,
    aggregates, enums, borrowed and mutable references, owned results and
    explicit release, callbacks, and throws. Reject unsupported signatures
    with diagnostics rather than changing their semantics.
  - Keep generating binding sources separate from compiling the bridge, so a
    default build never needs a JDK or the NDK.

*** Decisions needing approval before implementation

  Generated file names and layout, package/module naming, which builds
  generate which bindings by default, how the bridge is compiled and where
  the result is installed, and the tools each step requires.

*** Progress

  - JNI, first slice (scalars of every width, Bool, Str, throws): every
    ~mode lib~ build writes ~gen/til/java/til/<pkg>/<Cls>.java~ and
    ~gen/til/<name>_jni.c~ (layout and bridge command in doc/ffi.org,
    "Calling a library from the JVM"). Unbound signatures are listed in the
    class as ~// <name>: not bound: <reason>~. ~test/jni.til~ checks the
    generated text in the suite; a Java caller ran through a JDK on demand
    (now in the suite, below).
  - JNI, second slice: public structs as AutoCloseable handle classes
    (owned results, borrowed / ~mut~ / ~own~ parameters, inline scalar and
    Str field accessors, a default constructor from literal defaults),
    public globals and namespace data (getters, setters when ~mut~, borrowed
    handles for struct globals), and the cage ABI (~TIL_CPTR32~, now the
    default) in the bridge. The JDK run also drove
    library_namespace_a, the library the Python binding test checks, which
    completes the first JVM acceptance item.
  - JNI, third slice: enums (tags, payload getters, variant constructors),
    ~mut~ scalar / Str / Vec(Str) parameters as one-element arrays,
    ~returns ref~, ~own~ and ~ref~ fields, Vec(Str) as String[], function
    aliases, default constructors through nested constructor calls and own
    boxes, and FuncSigs as Java functional interfaces (callbacks through a
    TilClosure over a JNI global reference). The JDK run also reran
    both callers with ~--asan~ libraries and bridges, so the cage's leak
    report covers every bridge path. What stays unbound is listed in
    doc/ffi.org and in each generated class.
  - The JVM checks run in ~make test~, like the Python ones: the ~jni~ test
    (jni_lib) and library_namespace (library_namespace_a, beside its Python
    check), each with a Linux ASAN leak run. A JDK is an optional
    dependency: ~make test NO_JVM=1~ (~bin/tests --no-jvm~) skips the JDK
    runs on hosts without one.
  - Vec(T) of a scalar as the primitive array (parameters, ~mut~ holders,
    results, fields, globals, callbacks) and of a struct or enum as a handle
    array (element clones in, owned handles or borrowed views out).
  - Callbacks with ~own~ parameters (owned handles, copies the bridge then
    deletes), ~mut~ parameters (one-element holders read back after the
    call, borrowed handles for structs and enums) and ~throws~ (a Java
    ~TilError~ naming a declared type becomes the til throw, its payload the
    type's default with the detail as ~msg~); ~TilError~ gains public
    constructors and ~detail()~.
  - ~til build --jni~ / ~til install --jni~ compile the bridge
    (~gen/lib/lib<name>_jni~) and jar the class (~gen/lib/<name>.jar~) with
    the host JDK; install puts both beside the library in ~<prefix>/lib/~.
    The suite's JVM checks build through it, and test/install.til runs a
    Java caller against an installed compiler's ~install --jni~. That run
    found the bridge declaring its callback machinery over ~TilClosure~ in
    libraries without the closure runtime; it is now emitted only with it.
  - Callbacks take ~Vec~s of structs or enums (borrowed views, or owned
    handles for ~own~) and return them (each handle moved into til).
  - ~mut~ Vecs of structs or enums, for functions (the caller's handles
    move in, the library's Vec comes back as new owned handles) and
    callbacks (the elements move to Java as owned handles and back); every
    unbound item is also a ~note:~ on stderr when the library is built.
  - Callbacks taking and returning callbacks, and functions returning
    them: til closures reach Java as ~<F>.Til~ (call() runs the closure,
    close() drops an owned one), Java objects and owned ~<F>.Til~ values
    move into til; FuncSigs are settled as a fixed point, so they may refer
    to each other in any order. This found that the garbager never dropped
    an ~own~ closure parameter (every capturing closure passed ~own~ leaked
    its environment and box); fixed, with
    ~test_own_closure_param_dropped~ in test/closures_compile_escape.til.
  - ~mut~ FuncSig parameters (functions: a holder whose replaced closure
    comes back as an owned ~<F>.Til~, an untouched one leaving the caller's
    object; callbacks: the slot as a borrowed ~<F>.Til~ in a holder whose
    replacement moves into til), ~returns ref~ of a FuncSig (a borrowed
    ~<F>.Til~), and Vecs of structs or enums as fields, payloads and
    globals (borrowed views). Assigning a closure to a ~mut~ closure
    parameter emitted invalid C; fixed in the codegen, with
    ~test_mut_closure_param_assigned~.
  - Android packaging stays with #462; the BEAM half is #479.
