** FIXED #370 til embeds in the lua/lisp sense: host program, guest til

*** Post-mortem

The interpreter existed, but its CLI-owned lifetime, error handling and native
setup were not an installed embedding contract. A retained callable also needs
its program/captures alive, and native values cannot retain VM-owned literal
buffers. Composition exposed compilation-local exception IDs, missing callable
clone roots, dangling command-table copies, malformed generated defaults and
duplicate dependent schemas.

The delivered interface is ~std/tilvm~: ~TilVm.new~, one successful ~load_file~,
checked ~lookup~, and owning ~TilVmCallback~ handles borrowing their VM. Calls
return owned diagnostics/results, preserve surviving sessions on failure, and
need no compiler executable. The installed SDK includes the private interpreter
sources and native support. Fresh candidate VMs support reload replacement;
host-side staging/publication and rollback of native effects remain application
responsibilities.

Host APIs use prebuilt shared libraries and their generated bindings, not the
unimplemented manual registration/snapshot API proposed below. Optional source,
logical-name and base-directory prelude arguments provide that API to config and
user helpers through the existing implicit-import machinery. Code/source and
input-string ownership, filenames, relative imports, collisions, retry and
independent VMs have installed-host coverage.

The final native follow-ups add by-value enum ABI layouts, active-payload
conversion, boxed ownership/reference handling and error-result cleanup.
Generated bindings import canonical dependency APIs instead of redeclaring them;
imported native globals keep their linker identities. Native owned-argument
value moves also release their otherwise-orphaned outer boxes. Callable enum
payloads are explicitly unavailable through FFI, not mistaken for compatible
native closure pointers.

Regression coverage: ~test/install_tilvm.til~ builds separate ASAN hosts; its
native/prelude host uses empty PATH and private HOME. ~test/tilvm.til~,
~test/tilvm_native.til~ (including
~editor_buffer_test~, ~native_config_test~, ~host_prelude_test~ and
~native_enum_test~), ~test/tilvm_lifetime_error.til~, ~test/interp_session.til~,
~test/stored_callbacks{,_error}.til~, ~test/errors.til~, and
~test/library_namespace.til~ cover the delivered contracts. The current API,
ownership and packaging details are in ~doc/ffi.org~.

Closing this embedding contract does not close the shared compiler defects in
[[../open/443.org][#443]] (nested propagating reference results),
[[../open/445.org][#445]] (builtin SIMD binding generation), or
[[./446.org][#446]] (discarded owned results on early-return edges, fixed separately).
Their reproducers are distinct from this issue's native return decoding,
dependency composition, and owned-parameter wrapper cleanup regressions.

*** Original problem and design history

The narrative and milestones below record how this feature evolved. Earlier
"next" steps and the registration proposal are historical, superseded by the
delivered contract above and the completed acceptance checks below.

[[https://github.com/jtimon/tiled/blob/master/issues/open/1.org][Tiled #1]] (formerly Til #83) is emacs/neovim done without the split brain:
til for the host AND til for the guest. That only works if til can be EMBEDDED the
way lua and lisp are -- a running program creates an interpreter, feeds
it source it did not know at build time, and the two exchange values
and functions. Which language a file is "in" stops being a question;
what matters is only WHEN it is loaded: compiled into the host, or
interpreted into it at startup from ~/.tiled/init.til the way emacs
loads init.el and neovim loads init.lua. Same language on both sides is
the point -- past the editor wars and past the eclipse: no elisp/vimscript
/ lua / json split, and no IDE-platform bolted onto a different
language than the one it edits.

At filing time, the gap to embedding was:

  - The interpreter is ordinary til code (src/self/interpreter.til)
    linked into bin/til, with reusable session machinery driven by
     cmd_interpret / the REPL. It was not yet an embedding library:
    process-wide state, exit/error handling, native binding setup and
    installation also need explicit embedding contracts.
   - What was missing was the API AROUND it: create a session from inside
    a running program, eval a string or file into it, look a symbol up,
    call it, and register HOST functions the guest can call. The REPL
    has internal machinery for several of these operations, but there
     was no supported installed host-facing API for them.
  - The FFI already crosses the other direction (guest calls C via
    ext_func + libffi), so "host function visible to the guest" has
    machinery to build on rather than invent.

Original sketch (superseded by TilVm and generated native bindings):

  #+begin_src til
  mut vm := Interp.new()
  vm.register("buffer_insert", buffer_insert)  // host fn, guest-callable
  vm.eval_file(home.concat("/.tiled/init.til"))
  on_key := vm.lookup("on_key")                // guest fn, host-callable
  #+end_src

Original design questions:

  - Ownership across the boundary: what does a guest-returned Str mean
    in the host's single-owner model? (The #275 line of work is where
    those rules live.)
  - Does the embedded interpreter share the host's type scope or get a
    fresh one per session? tiled wants fresh-per-config-reload.
  - Sandboxing: init.til probably runs trusted, but a buffer-local
    script should not get free rein over the process.

*** Additional diagnostic and output coverage

- Source diagnostics carry phase/severity metadata, including semantic
  notes and ownership help, through the existing collection policy.
- Internal sessions can optionally collect ordered stdout/stderr events.
  ~interp_session_result~ extracts those events without clearing abort
  state or exit status that ~TilVm.load_file~ still needs. The installed
  TilVm API and its default use of host stdio remain the authority.
- An exit while computing another exit's argument preserves the first
  exit status and diagnostic. The existing embedded policy and teardown
  handle recovery; there is no second embedding-policy flag.
- ~test/interp_session.til~ covers owned diagnostics, ordered output,
  nested exits and result lifetime after session teardown. Its static
  diagnostic-vector case also covers the C call inventory: children of
  a PrecomputedSequence describe static data, not runtime clone calls.

*** Checked lookup foundation using existing function signatures

- Named function-signature Type arguments retain their existing
  ~Type.FuncPtrSig~ name, rather than becoming bare ~Type.FuncPtr~.
  ~til_type_name(Signature)~ can therefore feed ~func_sig_of~; both
  interpreted and compiled ~dyn_type_to_str~ still classify it as ~Fn~.
  The scavenger keeps signatures reached through these type tokens.
- ~interp_session_lookup_function~ checks a live guest callable against
  the host's ordinary reflected ~FuncSig~. Guest aliases and symbol-pool
  IDs are normalized to core type spellings; the existing ~FuncSig.eq~
  checks parameter/result types, own/mut, func/proc, variadic/kwargs
  indices, and ordered throws. Hidden throw ABI slots are excluded using
  the same rule as function-signature reflection.
- Lookup rejects missing/private/core names, non-callable values and
  bodyless signature declarations with owned diagnostics. Function
  aliases and capturing callable values use the actual live binding.
  Failed validation does not evaluate code, reset the module, or discard
  the session's globals. User-layout parameters/results require host
  registration; matching an unregistered record's spelling is not proof
  of its layout or ownership contract.
- The result is an internal borrow of the session's HeapBinding. It
  keeps the existing owner of code/captures; it is not exposed as a
  native function pointer or a new public callable type. At this foundation
  stage, public invocation and its error/lifetime contract were the next boundary.
- ~test/first_class.til~ checks signature reflection through a Type
  argument while preserving ~Fn~ classification. The installed ASAN
  host in ~test/tilvm.til~ exercises successful and rejected lookups
  with empty ~PATH~, including aliases, scalar widths, strings, ownership,
  mutability, variadics, kwargs, throws, borrowed results, and captures.
- ~make clean && make test_two_pass~ passed 520/520. Two-pass verification
  makes the compiler's signature-token rewrite part of its self-applied
  bootstrap output. JVM callable tests also retain the signature name
  while preserving dynamic ~Fn~ classification.

*** Checked evaluator invocation

- ~interp_session_call_function~ connects checked lookup to the existing
  callable evaluator. It builds a typed call expression, not guest source
  text, and uses the existing Tuple for typed native inputs/results. No
  new signature-description or value-wrapper format is introduced.
- The engine validates the signature, arity, element types and byte widths
  before executing guest code. The current invocation slice supports fixed
  core-scalar/Str arguments and results; variadic, kwargs and throwing
  invocation ABI marshalling is explicitly rejected for now, even though
  lookup can already compare those contracts.
- Native Tuple inputs remain owned by the host. Independent snapshots are
  passed to the guest; an own parameter consumes its guest snapshot.
  Borrowed mut parameters copy their updates back into the input Tuple,
  including on abort. An own mut parameter mutates the transferred snapshot,
  not the original host value. This is explicit copy-in/copy-out, not native
  reference borrowing.
- Results are independent host values. Str copies include views and literal
  buffers that may belong to the LoadedProgram; a general evaluator clone
  is insufficient at this boundary because it can share those buffers.
  Borrowed guest results are copied before temporary argument scopes die.
- Diagnostics, output events, exit status and abort state remain available
  to the driver. Each invocation starts a new operation on the existing
  guest globals; the engine neither reloads initializers nor rolls back
  earlier effects. The later public TilVmCallback API preserves the session
  and handle on invocation failure; it does not unload or roll back globals.
- The installed ASAN host tests now perform repeated and aliased calls,
  captured callables, packed scalar arguments, owned/mutable/borrowed Str
  results, validation failures, panic and exit(0), and independent live
  sessions. Results are read after session destruction with empty PATH.
- Verification also exposed a bootstrap call-site error after stored
  callback mutability became enforced: make.til's dispatch parameter must
  be ~mut Build~ when passed to its ~proc(mut Build)~ handler.
- ~make clean && make test~ passed 524/524, including the installed
  compiler-free host under ASAN with the new invocation cases.

*** Callback argument/result preparation

Exposing Tuple results through a throwing callback method found two lowering
bugs: positional overrides of trailing defaults collided with hidden error
slots, and a synthetic error-path Tuple() was rejected because Tuple has new().
Error slots are now bound by name while source positional arguments skip those
ABI positions. Synthetic error-result constructors explicitly initialize fields
without invoking application new() methods. test_throwing_tuple_defaults and
test_throwing_constructor_result in test/errors.til cover both cases.

The bootstrap compiler rejected the new callback method before a self rebuild
("struct 'Tuple' has a new() constructor"), so this is a preparation/use pair
as documented in doc/self.org. The preparation's make clean && make test passed
456/456; the callback API extension follows on its regenerated bootstrap.

*** Historical findings from Tiled's original startup workaround

The separate [[https://github.com/jtimon/tiled][tiled repository]] first exercised this use case with
installed til ~0.0.1-2827886a4~. Its host checked for
~$HOME/.tiled/init.til~, prints a defaults notice when absent, and opens
an unnamed ~*scratch*~ editor buffer unless a file was requested.

At that revision, the workaround for an existing init file was to generate a small
~mode gui~ entry point importing the editor and user config, then invoke
the installed ~til run~ to compile and execute it in a child process.
The config defines ~init(mut config: TiledConfig)~, changing window size,
scratch text or the initial file. This has been exercised with a copied
example config, command-line file precedence and a failing config.

That proves the config can be ordinary til, but it is NOT Lua-style
embedding: it recompiles source and launches another program instead of
evaluating the file inside the existing host. It also requires the
editor's source checkout and the compiler at runtime. The startup
workaround cannot install a guest callback into the already-running
host's keymap or change its existing buffers.

At that point, the installed support tree lacked the interpreter implementation
needed by an embedding host. The later ~std/tilvm~ slice installs private
~src/self/~ sources and libffi support through ~install_compiler_support~;
applications no longer need to vendor compiler internals.

*** Concrete host/guest requirements

- A compiled Til application owns an interpreter session in its own
  process. Loading user code does not invoke the ~til~ executable or a C
  compiler, generate a new entry-point program, or start a replacement
  editor process. The host supplies the event loop and window lifecycle.
- Make host functions and types available to the guest. The first small
  case is passing mutable host-owned configuration to ~init~; the next
  is registering commands such as ~find-file~, ~save-buffer~ and buffer
  insertion. Establish which values cross by copy, borrow or ownership
  transfer, including when a guest may retain a host reference.
- The host can retain a guest callable after init returns and invoke it
  later for a keybinding, hook or timer. Specify how callable handles
  keep their session alive, and how they are released or invalidated on
  reload. Registered callbacks must not outlive their captured state.
- Evaluation and calls return structured diagnostics to the host,
  including source path and location. Syntax/type errors and ordinary
  guest evaluation failures must not terminate the application. Define
  how guest ~panic~ and ~exit~ interact with this boundary; this is not a
  promise to recover from arbitrary native FFI crashes.
- A failed load must leave the host able to show the error and continue
  accepting input. Reload needs an explicit policy for session and
  callback replacement. Fresh-per-reload scope alone cannot roll back
  side effects already performed through host functions; decide which
  configuration changes are staged and when they become active.
- Keep the API usable by a separately built application against an
  installed Til distribution, with its required runtime assets and
  version/ABI relationship documented. A compiler-checkout-relative
  import of interpreter internals is not the installation contract.

*** Approved first slice: TilVm loading and destruction

Historical first-slice contract; native libraries and host preludes were
enabled later as described in the post-mortem and doc/ffi.org.

The public module is ~std/tilvm~, with type ~TilVm~. The approved first
slice is ~TilVm.new(support_root)~ and ~vm.load_file(path) throws TilVmError~.
~support_root~ explicitly names the installed ~lib/til~ SDK used to compile
the host. One ~mode lib~ entry module loads per session; failed candidates
are discarded and the same session can retry. Successful reload uses a
fresh session. Guest output uses the host's standard output; failures return
owned diagnostics (path, line, column, message) and an optional exit status.

There is no public ~close~: a private helper holds resource teardown and
~delete(own self, call_free)~ calls it. ASAP inserts destruction after the
last use; explicit ~own vm.delete()~ performs early teardown. This follows
~File~'s pattern, now documented in ~doc/concepts/ownership.org~.
Cloning is private too: a fieldwise clone would duplicate raw program owners.
The initializer recognizes a declared clone as a meaningful override of
automatic generation, even when no source call uses it. All VM operations
must be serialized on one thread; independent sessions can coexist and be
loaded/destroyed in either order.

Installation includes private ~src/self/~ implementation sources and the
existing native libffi archive. The host compiles the engine into its own
binary; runtime loading needs the matching SDK source assets but neither
a compiler executable nor generated entry-point code. The first slice
rejects guest native declarations and native link directives. It is not a
sandbox and does not recover from arbitrary native faults.

Verification at that stage used ~test/tilvm.til~, a separately compiled ASAN
host built by ~test/install.til~ through the installed ~std/tilvm~ module.
The installed SDK checks now live in ~test/install_tilvm.til~. The host writes its
guest configs after compilation and runs with empty ~PATH~. Regressions
cover lexical/syntax/type/import errors, mode/native-declaration rejection,
both exit statuses, panic, bounds failure, abort with owned string arguments,
reflection errors, division by zero, retry, independent live sessions, and
implicit/explicit destruction. The installer also checks that ~close~ and
~clone~ remain private and restores the missing-libffi test fixture now that
the real installation supplies the archive.

~make clean && make test~ passed 498/498. An additional independent copy of
the installed SDK and host source under ~til_worktrees/tmp/issue-370-host/~
(outside either compiler checkout) compiled the host with ASAN and ran it
with empty ~PATH~, without ASAN errors. Logs are that project's
~tmp/build.log~ and ~tmp/run.log~. No system installation was changed.

At this milestone host-function registration and value interchange were the next
decisions. Later work selected generated shared-library bindings and retained
typed callbacks. The broader registration proposal below was not adopted;
its ~Interp~ spelling is superseded by ~TilVm~.

*** Approved callback slice: borrowed VM, owning callable

~vm.lookup(name) throws TilVmError~ returns ~TilVmCallback~ for an exported,
live guest func/proc with no arguments, result or throws clause.
~callback.call() throws TilVmError~ invokes it repeatedly through the typed
evaluator call path. Lookup reuses the checked export/binding lookup; native
symbols and signature-only declarations are not guest implementations.

The handle owns a clone of the existing evaluator callable/environment and
borrows the VM session. Its private ~close~ helper is called by ~delete~;
ASAP extends the VM lifetime through retained handles. Normal handle copies
clone captures independently while borrowing the same VM; guest globals are
shared through that VM. There is no reference count, runtime handle registry
or second value representation. The default error-path result represents
absence with ~Option(ref InterpSession).None~, never a null VM reference;
calling that absent result reports a lookup-required error.

Invocation failure preserves the session and callback state, returns owned
diagnostics/exit status, and permits another call. Earlier guest mutations
are not rolled back. Signature diagnostics for imported callbacks report
their defining file. Calls are still serialized on one thread.

Lifetime regressions exposed a destruction-pass discrepancy: it merged
alias/into/carried return summaries, so an independent callback copy kept
its original handle alive. The pass now rebuilds local borrow provenance,
follows carried owners, and retains them through the result's actual last
use. Assignments union acquired owners, and replacing an owning value while
a call-produced borrower remains live is rejected. The build dispatcher
also now declares its ~Build~ parameter ~mut~, as its command signature
already required after the stored-callback fix.

~test/tilvm.til~ exercises retained closures, copies, host-owned binding
records, independent sessions, implicit/explicit teardown, and recovery
after callback panic/exit. ~test/tilvm_lifetime_error.til~ checks seven
escape, destruction and replacement violations. ~test/install_tilvm.til~ compiles
both against the installed SDK, checks private callback cleanup, and runs
the ASAN host with empty PATH. ~make test_two_pass~ passed 524/524; two-pass
regeneration is required because the corrected ASAP lifetimes move two
compiler destructors earlier.

The updated SDK/host were also copied to ~til_worktrees/tmp/issue-370-host/~
outside the checkout: the ASAN host passed with empty PATH, and its installed
compiler rejected all seven lifetime violations. Logs are ~tmp/run.log~ and
~tmp/lifetime-error.log~ in that independent project.

*** Checked arguments and results on retained callbacks

~vm.lookup(name, Signature)~ now checks an ordinary named function-signature
Type against the guest contract. Omitting Signature (Type.None) preserves the
existing no-argument, no-result func/proc lookup. The same TilVmCallback owns
its cloned callable/captures and borrows the VM; there is no second handle or
signature format.

~callback.call(arguments) returns Tuple throws TilVmError~ accepts an existing
mutable Tuple. Omitting arguments supplies an empty Tuple, so existing call()
sites still work. A no-result guest returns an empty Tuple; other calls return
one independently owned scalar/Str value. For example:

#+begin_src til
Transform := func(Str) returns Str
mut transform := vm.lookup("transform", Transform)!
mut arguments := Tuple.new()
arguments.push(Str, own format("host", " input"))
result := transform.call(arguments)!
ref text : Str = result.get(0)
#+end_src

The shared evaluator marshaller invokes the handle's retained slot, never a
fresh lookup of its original global. Copies keep independent captured state
even when the original guest binding is replaced. Lookup rejects unsupported
variadic, kwargs, throwing and unregistered record contracts; the fixed
scalar/Str boundary permits at most 63 arguments.

Arguments remain host-owned. An own parameter consumes its guest snapshot;
borrowed mut parameters copy changes back, including on panic/exit. Results
copy literals, views and borrowed strings before guest storage can die.
Validation errors run no guest code. Runtime errors preserve the VM/handle,
return owned diagnostics/status and permit another call without rollback.

The installed host exercises signature/count/type/width rejection, packed
scalars, width aliases, owned/mutable strings, independent cloned captures,
rebinding, panic/exit recovery and results after explicit VM destruction.
These tests also exposed two evaluator/lifecycle bugs: an owning scalar
capture's return used its cloned block address instead of the scalar word,
and outer callable replacement failed to drop its previous capture environment.
test/closures.til covers both on interpreter/C; test/tuples.til also checks
width-alias reads against the primitive tags used by reflection/Type pushes.

Verification: make clean && make test_two_pass passed 456/456, including
install_tilvm's independently compiled ASAN host with empty PATH and its seven
callback lifetime rejections. The use commit is Two-pass so the emitted
ownership cleanup is regenerated with the corrected compiler at merge time.

*** Stored callback analysis (Tiled #5)

Both reported limitations reproduced on master ~f24e6004c~, independently
of the installed ~b444d7223~ compiler. Calls through stored proc pointers
returned before procedure-effect checking. Field and expression callees
also inferred arguments without running the normal signature validator,
losing mutable-write evidence and permitting invalid arguments.

The typer now accounts for the stored signature's proc effect and uses the
ordinary argument validator for field, returned and cast callables. This
both credits real writes and rejects immutable arguments. A proc cannot
be stored in a func-typed slot to hide its effect; named-function signature
checks now cover constructor fields as well. The interpreter dispatches
its proc handlers directly inside its existing proc dispatcher rather than
through a func wrapper that depended on the same checking hole.

~test/stored_callbacks.til~ exercises parameter/local/field/nested-field/
returned/cast calls, mutation of the original state, pure mutable callbacks,
and contextual enum/generic arguments. ~test/stored_callbacks_error.til~
checks purity, mutability, argument types, redundant mut and effect-erasing
assignments on both backends. The existing ~test/fn_ptr.til~ helper now
correctly spells ~proc~ because ~Fn(...)~ without a returns clause is a proc
signature.

Verification: ~make clean && make test~ passed 524/524, including the four
new stored-callback runs and the existing function-pointer/ABI regressions.

Tiled handoff: a proc wrapper containing only ~binding.action(state)~ can
now retain its proc and mutable-state contracts without a dummy direct proc
call or extracting the callable to a local. Application edits stay in the
Tiled session; this compiler change adds no embedding API.

*** Superseded API and ownership proposal against master b201ae5d5

Historical proposal, not the shipped API or a list of unfinished acceptance
work. This is the original design discussion, not a description of current APIs.
~std/tilvm~, borrowed owning callback handles, generated native bindings and
host preludes supersede several choices below, including ~std/interp~, runtime
handle tokens, public close/release and the blanket native-library restriction.
This history does not authorize new public names or installation paths.

The initial target was a compiled Til host using the
C backend. Tiled's configuration remains ordinary Til, including its
existing ~init(mut config: TiledConfig)~ function. This proposal changes
how the host invokes it, not the user's configuration file format.

**** What can be reused, and what cannot simply be exposed

- ~InterpSession~ already owns the global scope, evaluated-unit set and
  retained programs. ~interp_session_start~, ~prepare_context~,
  ~eval_core_once~ and ~free~ are useful implementation seams.
- Persistent bindings borrow canonical types from Contexts; interpreted
  callables borrow AST FuncDefs and can own captured scopes. The REPL
  retains LoadedPrograms for precisely these lifetimes. Returning an
  Expr pointer, raw heap block or InterpCallableBox to a host would not
  create a safe callable/value API.
- The existing REPL's ~h_exit~ only intercepts nonzero exits.
  ~exit(0)~ still terminates the process. Several evaluator handlers and
  loader paths also call ~exit~ or ~panic~ directly. Setting ~is_repl~
  is therefore insufficient to keep an embedding host alive.
- ~load_program~ reads an entry file; the REPL writes scratch source
  and captures process stdout/stderr to files. Embedding needs an
  in-memory entry-source path and structured diagnostics/output, not
  generated source files or process-wide stdio redirection.
- ~interp_session_prepare_context~ resets FFI state and can compile a
  ~link_c~ shared library. ~ffi_init_link_libs~ can load libraries into
  the process. Neither operation belongs in the first compiler-free
  guest-loading contract.
- Interpreter dispatch scratch depth and the Scope reuse pool are
  global; ~src/c/ext.c~ has a process-global user-FFI library handle.
  A source-level InterpSession alone is not proof of independent or
  reentrant VMs. Audit these lifetimes before exposing sessions.
- ~struct_def_of~ and ~func_sig_of~ in ~src/core/dyn.til~ provide
  reflection to build on. Struct reflection currently supplies field
  names, types and mutability, not a complete ownership/layout contract;
  it cannot justify arbitrary native struct memcpy or borrowed-pointer
  interchange. [[../fixed/275.org][#275]] explains why a second, manually owned runtime
  value representation must not be introduced around the evaluator.

**** Proposed public operations

Use ~import("std/interp")~ as the supported entry point. Names below
specify the proposed contract, not APIs that already compile today.

- ~Interp(HostContext).new~: create an owning session. Its default SDK
  root is captured at host build time; an explicit ~support_root~
  argument permits relocation.
  HostContext is the host's type for per-call callback context; the VM
  does not own or retain an instance of it between calls. An application
  with no callback state can use an empty context type.
- ~register_type(T)~: make a supported host type visible to guest
  typechecking. Derive its contract/adapters from the actual host type,
  not a handwritten second definition of TiledConfig in guest source.
- ~register_proc(Signature, name, handler)~: bind a guest-visible name
  and checked signature to a native host adapter. The adapter receives
  the current HostContext plus checked argument values; its hidden
  context parameter is not part of the guest signature. Registration
  retains the callable/code, not a borrow of the host's live editor.
- ~load_source(source, virtual_path, import_base, mut host_context)~
  and ~load_file(path, mut host_context)~: load/typecheck a module and
  initialize its globals/imports. The first milestone loads one entry
  module per session, then supports repeated calls. Failed preparation
  discards its candidate program; it does not publish partial symbols.
- ~lookup(Signature, name)~: return a checked guest-function handle.
  Wrong names or signatures are structured errors, not null pointers.
- ~copy_in(T, value)~: clone supported host data into a guest-owned root
  and return its typed value handle.
- ~call(function, arguments, mut host_context)~: invoke an already
  checked function. Arguments explicitly select guest value, guest
  mutable borrow or guest ownership transfer. This must use a typed
  evaluator call path, not synthesize and evaluate source text for
  every invocation.
- ~copy_out(T, handle)~: create an independent host-owned result.
- ~release(handle)~ and ~close~: release one guest root or the whole
  session. Owning session destruction also performs teardown.

Handles are opaque, session-tagged identities with lifetime generations,
not exposed AST/raw-memory pointers. Operations always take a live VM
and reject stale, released or other-session handles before using their
storage. Copying a token does not clone its guest object; releasing a
root invalidates its token aliases. Guest-function handles root both
the callable environment and the program/type information it borrows.

The first data boundary supports core scalars, owned Str copies and
plain value records containing those fields, sufficient for today's
TiledConfig (I32, Bool and Str fields). Registration must reject types
whose ownership/layout the adapter cannot faithfully support: raw
pointers, ref/own fields, arbitrary containers, custom lifecycle and
interface values are not silently treated as plain records. Existing
compiler declarations remain the authority for qualifiers and layouts;
extend the registration metadata deliberately where current reflection
does not expose enough information.

**** Ownership: explicit snapshots first, not disguised native borrows

Recommendation for the first boundary: guest roots and explicit copies.
The host copies its candidate config into a guest-owned value, calls
~init~ with a mutable borrow of THAT guest value, then copies the result
back on success. Finally the host replaces its candidate configuration.
The guest's existing ~mut config~ semantics are real within the guest;
the API must not claim it is aliasing the original native host object.

This deliberately creates an independent config snapshot during the
call, rather than a second owner of the same Str buffers. Typed clone,
move and delete behavior must flow through the existing evaluator and
compiler lifecycle machinery. Do not recreate the removed Value /
StructInstance shadow heap or byte-copy managed records.

- Borrowing or mutating a guest argument leaves its session root owned
  by the VM. Guest callbacks may retain guest data according to normal
  Til ownership rules; retaining it cannot retain a native stack borrow.
- An ~own~ argument consumes its guest root once invocation begins,
  including if evaluation later aborts. Validation failures before
  entering the function consume nothing. Every abort path must drop or
  preserve transferred values exactly once.
- ~copy_out~ returns host-owned strings/records, independent of VM
  closure, reload or destruction. No borrowed Str view escapes through
  a public result. Closures stay as checked guest handles, not native
  function pointers with an invented ABI.
- Host callbacks receive HostContext only for the dynamic extent of
  ~load~ or ~call~. Guest code cannot retain that native context pointer.
  A later editor key event supplies the current host context again.
  Any native callback captures obey normal host ownership rules.

Direct shared native ~mut T~ / ~ref T~ arguments are a later contract,
not an implicit optimization of copying. They need escape/lifetime
enforcement and alias-preserving layout/writeback semantics. In
particular, the existing FFI's foreign-place tracking is not by itself
a guarantee that an arbitrary guest-held native reference cannot
outlive its host owner.

**** Errors, output, sessions and reload

Public operations report ~InterpError~, an owned structured error with
phase, diagnostics and optional guest exit status. Frontend diagnostics carry
source path, line and column; text output is a separate host sink.
Do not infer error categories by parsing printed panic messages.

An embedding execution policy must unwind EVERY guest exit status,
including zero, to the host. Guest panic/assert/uncaught-throw paths
must reach the same cleanup discipline. Audit direct evaluator exits
and loader error paths as well as ~h_exit~. Internal compiler invariant
failures and arbitrary native FFI faults are not recoverable guest
errors. CLI/REPL drivers can retain their current exit/printing behavior
through their own policy around the reusable machinery.

Initially sessions are thread-confined and calls are serialized. A host
callback attempting guest re-entry receives a clear busy/re-entry error;
there is no recursive evaluation through unsaved global scratch state.
Two independent sessions must still alternate calls and tear down in
either order without affecting each other. Move session-owned scratch,
pools and callback state under the correct owner; do not unload another
session's FFI library during reset/free.

First guest profile: library modules, normal source imports, supported
core/std operations and explicitly registered host calls. Reject runtime
~link_c~, undeclared native bindings and new native-library loading with
structured unsupported-operation diagnostics. Registration must keep
the required native functions reachable in compiled hosts; relying on
whatever happens to survive linker dead stripping is not registration.
This profile is not a sandbox for hostile source or unsafe native code.

Reload constructs a fresh session and candidate config while the old
session remains live. After load/init succeed, the host switches its
config and callback handles together and then closes the old session.
Failure discards the candidate and preserves the old active session.
Host callback side effects are not automatically transactional: during
configuration the host must route them to candidate state or document
their immediate effects. A runtime abort need not roll back earlier
guest-global mutations either.

**** Packaging and installation proposal

- Add ~src/std/interp.til~ as the public source facade; keep engine,
  loader, typing and lifecycle work in the existing ~src/self/~ modules.
  Do not expose their Context/Expr layout as the public ABI.
- Extend ~install_compiler_support~ to install ~src/self/~ as private
  implementation sources and the already-built native libffi archive
  at the relative path selected by ~target_ffi_lib~. Bindings already
  install under ~vendor/bindings/~. The normal build produces the
  archive; installation copies it; the application build reads/links
  it. Existing installed core/std sources alone cannot compile the
  interpreter implementation today.
- The host compiles the facade and private implementation through the
  existing Til build path. No separate libtilinterp binary, alternate
  source tree, serialized AST, generated documentation cache or runtime
  compiler subprocess is proposed for the first version. The tradeoff
  is a larger host build/binary and private SDK source installation.
- Host registration needs runtime type/signature descriptors and typed
  adapters derived at host build time. These repeat facts from the
  compiler's declarations inside the host binary so guests need neither
  Tiled's source nor manually maintained schemas. Reuse existing
  reflection inventories; do not add a second persistent metadata file.
- Core/std/mode sources remain runtime SDK assets. Capture the selected
  support root at HOST BUILD time using the compiler's existing root
  resolution, with an explicit constructor argument for relocation.
  Running ~get_bin_dir~ on the Tiled executable is not equivalent to
  finding the compiler SDK that built it.
- The host, embedded engine, native runtime and libffi must agree on
  target and USize/UPtr widths and supported binding layouts. Validate
  native contracts; a revision string alone is not ABI proof. The
  current single-version installation still replaces one support tree:
  upgrading it may require rebuilding embedding hosts. This proposal
  does not introduce side-by-side compiler installs or promise arbitrary
  cross-revision compatibility.

These proposed registration descriptors and snapshot operations were not
introduced. The supported route uses existing generated native bindings,
ordinary ownership and an optional host prelude; no second value/schema format
was added. This proposal remains here as design history.

**** Delivery and acceptance

First extract structured diagnostics and an embedding abort policy,
then implement session ownership/typed guest-root calls, then host
type/callback adapters, and finally installation and an external host
acceptance test. Use the existing self-hosting workflow to determine
whether an eventual emitted-metadata change needs preparation; the
feature is not automatically blocked on a multi-commit bootstrap.

The first installed-host acceptance must keep compiler executables OFF
PATH and perform no C compilation or generated-entry-file writes while
loading a config edited after host build. Exercise TiledConfig's actual
I32/Bool/Str shape, snapshot mutation and copy-out, a host callback with
per-call state, and a retained guest closure called after load returns.

Also test syntax/type/import failures, guest ~exit(0)~/~exit(1)~/panic,
host callback failures, stale/cross-session handles, multiple sessions,
reload failure/success, abort during ownership transfer, and session
destruction with retained values. Strings copied to the host must remain
valid after VM teardown. Unsupported native borrowing must fail
explicitly, not silently become copying. These checks precede claiming
the full set of requirements above complete.
