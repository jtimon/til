** FIXED #251 `interface` keyword: an abstract-class-like contract, desugars to a fieldless struct

   FIXED. Implemented incrementally: the ~interface~ keyword (desugars to a
   fieldless StructDef), abstract-class member kinds (~ext_func~/~ext_proc~
   = abstract, ~func~/~proc~ = concrete default), the no-fields and
   no-~namespace:~ rules (typer-enforced), and ~struct implements Iface
   { ... }~ / ~enum implements Iface { ... }~ conformance: the typer
   (interface_method_conforms / infer_type_def_expr) verifies a conforming
   struct or enum provides every abstract method the interface lists, with a
   matching signature -- the interface's own name is "Self" and substitutes
   to the implementing type. Structs and enums both carry methods in their
   namespace, so the conformance check is shared; only where the interface
   name is recorded (StructDef.implements_name / EnumDef.implements_name)
   differs.

   Regression tests: test/interfaces.til (positive -- abstract ext_func
   methods, a callable concrete default, ~Circle implements Drawable~ (a
   struct) and ~Polygon implements Drawable~ (an enum), each with a callable
   provided method, on both backends); test/typer_errors.til (interface
   field / namespace / bad-kind rejections, and the implements missing-method
   / wrong-signature / not-an-interface rejections for both structs and
   enums).

    method's normalized ABI, and avoids dependence on namespace typing order.
    The original declarations are not mutated. Inherited concrete defaults
    and explicit overrides both go through the same check.

*** Assignment and collection follow-up (based on master 1299f248c)

    Reproduced three gaps:

    - Assigning a conforming concrete value to an interface local/field
      passed the typer's aggregate-kind check without boxing, then failed C
      compilation with incompatible struct assignment/initializer errors.
    - Inserting a borrowed interface from an inner block into an outer Vec
      compiled but produced ASAN stack-use-after-scope after leaving that
      block. The existing return checker already rejected returning a Vec
      holding a borrow of a function local; it did not cover this deposit.
    - Interpreted field replacement reclaimed an owned interface payload
      through raw heap cleanup, skipping the concrete type's custom delete.
      Compiled replacement executed that destructor. The new destruction
      counter regression exposed the difference.

    Changes:

    - Local assignment uses the same boxing rule as local initialization:
      fresh concrete values are owned, existing concrete storage is borrowed.
      Non-ref value-field replacement owns concrete payloads, like field
      construction. Both paths validate the actual named interface type.
      Assigning a ref-returned interface into a value field clones its box.
    - An owning interface parameter (including Vec.push / Array.set /
      Map.set) receives an owned heap clone when coercing a concrete value,
      even a named one. Passing an already-boxed borrowed interface keeps
      its borrow; owning the box does not promote its payload to owned.
    - Call deposits are recorded AFTER argument coercion, so their roots
      describe the box actually stored. For interface assignments/deposits,
      concrete local owners must not be outlived by an enclosing-scope or
      caller-owned destination. Ref aliases of the destination are followed.
      These checks use interface payload provenance; general conservative
      write-credit summaries are not treated as proof of a lifetime escape.
    - Live interpreted aggregate replacement executes the language delete
      method instead of substituting raw interpreter heap cleanup. An owned
      struct RHS transfers into an inline field without an extra clone/drop.
      Raw heap cleanup still handles interpreter storage teardown.

    ~test_interface_reassignment~, ~test_interface_field_reassignment~,

    ~test_interface_collection_borrows~ and

*** Argument lifetime follow-up (based on master b444d7223)

    Reproduced compiled ASAN stack-use-after-return in
    ~return relay(make_concrete())~, where ~relay(d: Iface) returns Iface~
    returns its argument. Argument coercion borrowed the temporary concrete
    value's hoisted stack slot. Passing a concrete constructor instead also
    failed typing: the boxing rewrite re-inferred its lowered arguments.

    Changes in ~src/self/typer.til~:

    - ~box_inferred_interface_value~ is shared by argument and local
      coercion. Fresh concrete values get owned boxes; existing storage and
      ref-returned values keep borrowing. The operand is already typed:
      ~infer_interface_payload_call~ fills defaults and validates only the
      generated ~to_ptr~/~dyn_call_ret~ call, without retyping that operand.
      This replaces the local path's earlier pre-inference snapshot.
    - An interface parameter lends the BOX, regardless of whether that box
      owns its PAYLOAD. Storing it in a non-ref interface field must clone the
      box. A plain value copy reproduced heap-use-after-free when the caller
      destroyed its owned argument box. The interface's clone deep-copies
      owned payloads and preserves genuinely borrowed payloads; owned local
      boxes can still transfer into fields.
    - Constructor borrow summaries now distinguish a ref field's pointer
      into argument storage from a value field's carried borrows. Treating
      both as pointers into argument storage incorrectly rejected returning
      a holder built from a local owned interface box passed to a helper.

**** Implemented after the original closure

    - [[./268.org][#268]] (~1b4509b10~): concrete defaults are copied into
      each implementer's namespace by ~gen_implements_defaults_for_stmt~

      ~gen_substitute_self_type~ substitutes the interface name in direct
      parameter/return types; a default calling ~self.draw()~ therefore
      resolves to the concrete implementation. There is no inheritance
      chain or shared method table.
    - [[./269.org][#269]] (~cc8a1da72~): interface-typed arguments accept
      conforming structs/enums. Abstract calls through the interface lower
      to ~dyn_call~/~dyn_call_ret~ using the concrete type's name and value
      pointer. This is runtime string-name dispatch, not a vtable.
    - ~e7c786a4d~: interface-typed local declarations box a conforming
      concrete value by borrowing it, like argument coercion.
    - ~1e316e3b7~: boxes gained ~iface_owned~ and ownership-aware generated
      clone/delete methods. The runtime representation now has THREE
      synthetic fields: ~iface_type_name: Str~, ~ref iface_val: Dynamic~,
      and ~iface_owned: Bool~. "Fieldless" describes user declarations and
      the parser's initial AST, not the final layout.
    - ~e6779b494~ and ~642442380~: concrete values returned as an interface
      or supplied to an interface-typed struct field at construction are
      boxed as owned heap clones (~make_owned_iface_box~ in the typer).
      Owned-box clone/delete dynamically clone/free that concrete payload;
      borrowed-box clone retains the borrow rather than upgrading ownership.

    Interface box/lifecycle/default synthesis is currently invoked from
    ~type_methods_from~ in ~src/self/typer.til~; the generation
    helpers themselves remain in ~src/self/initer.til~.

**** Current limits and gaps

    - Defaults called through an INTERFACE-typed receiver are still static
      calls to the interface's default, even when the concrete type has an
      override. Only abstract calls dispatch dynamically. Thus the concrete
      ~Labeled.label()~ override and ~Drawable.label()~ through a boxed
      Labeled do not have the same dispatch semantics. A default's inner
      abstract call (~describe -> self.draw()~) does dispatch dynamically.
    - Abstract dispatch supports at most ONE argument besides self.
      ~infer_field_access_fcall~ diagnoses larger calls explicitly. Ordinary
      calls on the concrete type do not go through this interface limit.
    - ~interface_method_conforms~ compares parameter count, declared type
      names and return type, with exact-name Self substitution. It does not
      compare parameter ownership/mutability, func/proc effects or throws.
      It checks abstract methods only, not overrides of concrete defaults.
      This is narrower than full function-signature compatibility.
    - Self substitution does not recursively rewrite nested generic types
      or explicit interface-name references inside a copied default body.
    - The parser records one ~implements_name~ on a struct/enum. Multiple
      implemented interfaces, interface inheritance and interface bounds on
      generic parameters are not provided by this syntax.
    - Boxing is implemented at argument, local-declaration, return and
      constructor-field sites, not as a general assignment conversion.
      Interface field/local reassignment and heterogeneous collection
      storage need separate verification and lifetime handling. In
      particular, a container method's interface-typed argument follows the
      borrowed argument path; that is not evidence of owned element boxing.
    - Borrowed boxes require their concrete payload to outlive them.
      Returning or storing an ALREADY boxed borrowed interface does not
      trigger the concrete-to-interface owned conversion: ~box_return_value~
      and constructor boxing only convert conforming concrete types, and
      borrowed-box clone preserves the pointer. The existing positive tests
      do not establish safety for these escaping-borrow cases or temporaries
      bound to interface locals.
    - Empty ~Iface()~ construction remains legal and is tested for passing
      through functions and calling a default that ignores self. It supplies
      no concrete target for an abstract call. User-declared ~clone~/~delete~
      still suppress the generated box lifecycle methods; the original
      auto-generation collision caveat is not a resolved feature.
    - Vtable/monomorphization performance work remains separate from the
      already implemented dynamic dispatch. The original "no dynamic
      dispatch" non-goal below is historical, not current behavior.

*** Original issue (historical design and implementation plan)

    The "next step" and "non-goals" wording below predates #268/#269 and
    the later boxing changes summarized above.

   A top-level type keyword, ~interface~, modelled on Java interfaces and
   C++ abstract classes. An interface is a NAMED, fieldless contract of
   methods. It DESUGARS to a struct with EMPTY fields; the methods live in
   the struct's namespace. Two hard prohibitions: an interface cannot have
   instance fields, and it cannot carry a ~namespace:~ marker (there are no
   fields to separate from the methods).

   A member is one of two kinds:

   1. *Abstract* -- declared with ~ext_func~ / ~ext_proc~ and an empty
      ~{}~ body. It has no implementation here; a type that declares it
      implements the interface MUST provide it. This reuses the
      ~ext_func(...) returns T {}~ shape (a declaration whose body is
      supplied elsewhere), so abstract interface methods read exactly like
      external declarations.

   2. *Concrete (default)* -- an ordinary ~func~ / ~proc~ WITH a real body.
      The interface supplies the implementation itself; conforming types
      inherit it (like a non-pure method on a C++ abstract class). These
      are regular namespace methods.

*** Example

    : Drawable := interface {
    :     // abstract: every implementer must provide `draw`
    :     draw := ext_func(self: Drawable) returns Str {}
    :     // concrete default: provided by the interface
    :     label := func(self: Drawable) returns Str { return "shape" }
    : }
    :
    : Collection := interface {
    :     get := ext_func(self: Collection, i: U32) returns Dynamic {}
    :     len := ext_func(self: Collection) returns USize {}
    : }

    ~Collection~ names the ~get~/~len~ pair a ~for ... in~ loop relies on
    (both abstract). ~Drawable~ shows the mix: ~draw~ is abstract, ~label~
    a concrete default.

*** Conformance (`implements`) -- next step

    A type declares it satisfies an interface with ~implements~:

    : Circle := struct implements Drawable {
    :     r := 1.0
    : namespace:
    :     draw := func(self: Circle) returns Str { return "circle" }
    : }

    The typer verifies ~Circle~ provides every ABSTRACT (ext_func/ext_proc)
    method ~Drawable~ lists, with a matching signature; concrete defaults
    are inherited and need not be re-declared. A missing or mis-typed
    abstract method is a type error. Conformance checking is the NEXT step;
    the interface-definition side -- the two member kinds plus the
    no-fields / no-namespace rules below -- comes first.

*** Semantics

    - ~Name := interface { ... }~ desugars to a ~StructDef~ flagged
      ~is_interface~, with EMPTY ~fields~ and ~ns_decls~ = the members.
    - Members must be ~ext_func~/~ext_proc~ (abstract) or ~func~/~proc~
      (concrete). All of these are reported by the TYPER (not a parser
      panic) so the diagnostics aggregate in test/typer_errors.til:
      - a non-func member (a "field") is a type error;
      - a ~test~/~macro~/~lazy_func~/~lazy_proc~ member is a type error;
      - a ~namespace:~ marker is a type error.
    - The interface type is usable anywhere a (fieldless) struct type is:
      as a parameter / field / variable type annotation.

*** Non-goals (future issues)

    - No dynamic dispatch / vtables / interface values that erase the
      concrete type.
    - Edge case: an interface that re-declares ~clone~/~delete~/~size~
      suppresses the compiler's auto-generated versions for that empty
      struct, so INSTANTIATING such an interface leaves it without real
      clone/delete/size bodies. Only instantiate interfaces whose method
      names do not collide with the auto-gen trio.

*** Implementation (touch points)

    1. *Lexer* (src/self/lexer.til): ~TokenType.KwInterface~ keyword.

    2. *Parser* (src/self/parser.til): ~parse_interface_def~ produces a
       ~NodeType.StructDef(is_interface = true)~ with empty fields; each
       member parsed like a namespace decl, NO validation here (a
       ~namespace:~ marker sets ~StructDef.interface_ns_marker~ for the
       typer to reject). Hook ~KwInterface~ into ~parse_primary~.

    3. *Typer* (src/self/typer.til, ~infer_type_def_expr~): enforce the
       member-kind rules and the no-namespace rule as aggregatable type
       errors. Auto-generated clone/delete/size members are skipped.

    4. *Pipeline guards.* Abstract (ext_func/ext_proc) and bodyless
       members must not crash the namespace-method walkers
       (ffi_init_scan_program, emit_ns_method, the interpreter call path);
       each guards the no-body case.

    - Negative (test/typer_errors.til): a field, a ~namespace:~ marker,
