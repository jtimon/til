** FIXED #63 User-defined modes

*** Post-mortem

The original issue described a hardcoded mode table, which was replaced
by user-defined ~Mode(...)~ files in ~8cd7f3bff~. Remaining loader gaps
left mode-file imports and imported files' support incomplete; those were
fixed in the earlier #63 loader change. The last missing policy was
~decls_only~: it shaped generated code but never rejected executable
top-level statements. The GUI builder also inferred GUI dependencies from
the support filename, so custom modes importing the GUI module indirectly
missed target libraries and unrelated files named ~gui~ selected them.

The typer now checks each file's source-level statements under its own
~decls_only~ policy. The builder checks the resolved unit graph for
~src/modes/gui.til~ when selecting target GUI libraries and WASM HTML
output. Regression test ~mode_loading~ covers interpreter/translator
agreement, imported declaration-only files, custom GUI support imports,
and the unrelated-filename case.

*** Current implementation

The main feature landed in ~8cd7f3bff~ (2026-05-29). Built-ins are
~Mode(...)~ declarations in ~src/core/modes.til~, loaded by the same
mechanism as user definitions supplied through ~--extra-modes=<file>~.
Only the bootstrap ~mode~ mode is registered directly by the compiler.

There are nine declared built-ins: script, cli, gui, theme, test, pure,
pura, lib, and liba. All currently set ~decls_only = false~. The active
~Mode~ schema is ~src/std/mode_type.til~: needs_main, decls_only,
auto_import, is_library, is_pure, run_tests, and debug_prints.

~examples/custom_modes.til~ supplies four networking modes, covered by
four build tests and an interpreter smoke test. User documentation is
in ~doc/tutorial/2_modes.org~.

*** Agreed scope

Users define another mode and reuse support through ordinary imports.
No inheritance, derived-mode evaluation, special composition syntax, or
new configuration format is needed. Mode-definition files can import
other mode-definition files. A mode's support module can import other
support modules and carry ordinary ~link~ / ~link_c~ declarations.

#+begin_src til
mode mode
import("other_modes")
server := Mode(needs_main = true, auto_import = "server_support")
#+end_src

The application selects ~mode server~ and the compiler loads the
definitions through the existing ~--extra-modes~ option.

Loader regressions live in ~test/mode_loading.til~, registered as

initialization, legacy path resolution, and missing/conflicting definitions.

*** Scope boundary

~needs_main~ selects the compiler's existing entry contract; it does not
define an arbitrary entry signature. ~theme~ has a compiler-owned output
generator selected by its name, not by its ~Mode~ fields. User-defined
entry contracts and output generators require an explicit further design;
the loader work above does not introduce such a compiler-extension API.
