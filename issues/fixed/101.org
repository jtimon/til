** FIXED #101 Deterministic temp variable names in generated C

Post-mortem (2026-08-15, final): the goal, per Jorge, was always that a
til.c diff be USEFUL FOR REVIEW -- the C changes in it related to the til
edit, not label reorganizations rippling through the file. Landed across
six commits; the last piece was presentational and mattered as much as
the counters:

- Every synthesized-name family is per-scope (post-mortems below): body
  temps restart per definition as bare ordinals, builder ctor temps per
  emitted function, _lzr_ per definition via loader windows, file-scope
  symbols (_lambda_/closure_/body_) owner-qualified with per-owner
  ordinals, hoisted Str idents owner-qualified (their names are now
  file-scope symbols, so the qualifier is load-bearing).
- The pool holds ONLY multi-use non-loc literals in content-sorted order;
  single-use literals emit inline at their sites (rstil's model -- it
  pools nothing, which is why its diffs stayed local).
- The __LOC__ REGION, the finishing move: all 3,980 loc statics
  (`hoisted__Str_<owner>_<n> = "path:line:col"`) are defined in ONE
  contiguous file-scope block after the pool instead of inline in their
  functions -- same bytes, same names, different address for review. The
  registration walk also had to learn to descend into namespace member
  bodies (ns_decls are not AST children), which 52 loc statics and every
  other ns-body literal had been silently escaping.

Final probe shape (new function at the top of loader.til + a cross-unit
call): 31 diff hunks -- 9 are the probe's own compiled C (its forward
decl, its body, the function it modified), 22 land inside the loc region
block, which a reviewer skips wholesale. Zero unrelated hunks anywhere in
the file. The probe battery below (rename / new struct / new generic
instantiation / earliest-unit insertion) already showed zero unrelated
churn for every other edit shape.

Accepted residuals: the loc region's contents rewrite when line numbers
shift (real information, quarantined); parser anonymous types (zero
occurrences in the self-build); the constfolder's deref-of-a-scope-slot
as Expr in func_uses_unknown_globals predates this issue and deserves its
own issue.

Reopened (2026-08-15): the pool-block close below was premature -- its
probe changed no line COUNTS, so it never saw the __LOC__ cascade. A
7-line insertion at the top of loader.til shifted the line numbers in
~350 of that unit's __LOC__ strings; each shifted loc is a NEW pool
content, every one re-keyed the unit block, and 3,147 use-site lines
churned for a 7-line edit. Any dense index shared with loc-bearing
literals inherits their volatility.

rstil is the reference for the fix (per Jorge): it POOLS NOTHING -- every
literal is a self-contained compound literal at its use site, so a
literal has no index and no edit elsewhere can renumber it (its temps are
`_tmp_<func>_<n>`, equivalent to our per-definition ordinals; its diffs
were local for exactly this reason). The pool now follows that model
where it matters: only literals used MORE THAN ONCE are pooled (dedup and
TIL_LIT_GUARD exist for sharing; a single-use literal has no other user
to corrupt), laid out in CONTENT-sorted order so an index is a function
of the literal's own bytes; loc-shaped strings (".til:<line>") never pool
at all, multi-use or not, because their content embeds line numbers.
Single-use and loc literals emit through the fallback per-site inline
forms that always existed.

Re-measured with a probe the old one missed (new 5-line function at the
top of loader.til + a cross-unit call): 3,972 changed lines before, 1,052
after -- 100 the probe's own compiled code, 952 loc strings whose line
numbers genuinely moved (the same floor rstil pays; the information is
real), and ZERO lines of index churn anywhere. Cost: til.c 14.94MB ->
15.95MB (+6.7%), text only -- the binary is unchanged because cc merges
the duplicated string constants; pool 5,593 -> 951 entries.

The earlier close's post-mortem follows; its per-scope counter work all
stands, only the pool layout was redone.

Post-mortem of the first close (2026-08-15, superseded above on the pool
item): The issue split into two properties, and recognizing
the split was most of the work. REPRODUCIBILITY (same input, same bytes)
had been reached incrementally by earlier cleanups and #77's byte-identical
self-build -- the issue was even briefly closed on that basis, wrongly.
STABILITY (small source edit, small generated diff) is what the original
noisy-diff symptom was about, and every name family had to move from
whole-program ordinals to per-scope ones to get it:

- Body temps (hoist/va/kw/coll/bang families): counters restart per
  top-level definition, emitted as bare 1-2 digit ordinals; module-level
  temps keep a never-restarted `g`-marked sequence. Two program-wide
  tables had to stop keying on bare names first: the constfolder's known
  table leaked ns-member body locals (fold_body_scoped closed it -- a real
  latent bug unique names had been hiding), and the builder's pooled
  literal ident map still does, so `hoisted__Str_` alone carries a short
  owner (`<unit>_<orig_name>` via synth_owner_name; the initer's
  priv__<path>__ mangling spelled into every temp had cost 8.7MB).
- lazy `_lzr_` temps: the loader pass opens its own owner windows.
- Builder ctor temps (`_ctor_`/`_cs`/`_sc`/`_lit`): reset with the
  per-function scratch, save/restored around the NESTED closure emitters.
- File-scope symbols (`_lambda_`/`closure_`/`body_`): owner-qualified with
  per-owner ordinals from synth_symbol_seq (a Map, so a REPL redefinition
  cannot re-mint an existing symbol); replaced #328's lambda_counter.
- The string pool: two-phase registration lays out `_til_str_lits` as
  block 0 = literals used by more than one unit sorted by CONTENT, then
  one block per unit for its exclusive literals; use sites reference
  `_tl<block>(<rel>)` macros. One array still, so TIL_LIT_GUARD keeps its
  O(1) range test, and the C shrinks (the macro is shorter than the old
  absolute index). The common block exists because dedup made a shared
  literal live in whichever unit used it first: deleting loader.til's one
  use of "'" re-homed the literal and renumbered 1,297 use sites.

Regression coverage: self_translate cmps the fresh self-translation
against pass-1 boot/ (repeatability across processes AND the bootstrap
fixed point, every make test run); test_stmt_inline_two_results and
test_mixed_fold pin the moved counters' semantics; the gc_audit golden
pins garbager-visible names.

Measured arc (the same 3-line repl_prompt refactor in src/til.til):
4,737 changed lines of til.c before any of this; 103 after -- 26 __LOC__
line shifts (the floor), 4 pool lines, 19 the edited function's own
temps, 0 from anything else. An early-unit literal insertion went from
whole-program index churn to that unit's own block plus one #define line
per later block. til.c ended smaller than where master stood at each
step (names lost their 4-5 digit ordinals).

Accepted residuals, documented rather than fixed: within-unit pool
density (a literal added at the top of a big unit shifts that unit's own
block -- inherent to any dense array); parser anonymous types
(AnonStruct<N>, zero occurrences in the self-build, would need owner
threading through the parser, which runs before Context exists; rstil
accepted the same); the __LOC__ line-number floor (inherent to what
__LOC__ means); the hoisted__Str_ owner qualifier (~0.2MB, removable by
keying the builder's ident map by (definition, name)); and the
constfolder's deref-of-a-scope-slot-as-Expr in func_uses_unknown_globals,
which predates this issue, is unreachable at current known-ness, and
deserves its own issue.

*** Two different properties, and only one of them was ever fixed

  REPRODUCIBILITY -- same input, same bytes -- was reached incrementally:
  ~anon_type_counter~, ~lambda_counter~, ~bang_counter~, ~ctor_seq~,
  ~hoist_counter~, ~va_counter~, ~kw_counter~ and ~coll_counter~ moved onto
  ~Context~, ~Map~ became ordered, and [[../fixed/77.org][#77]] recorded a
  byte-identical self-build. This issue was briefly closed on that basis.
  That was wrong: reproducibility is not what makes a generated-C diff
  readable.

  STABILITY -- small source change, small generated diff -- was untouched,
  and it is the property the original symptom is about. Every counter was
  monotonic across the WHOLE program, so a synthesized name's suffix was
  really its ordinal in a whole-program walk. Anything that minted a temp
  renumbered every temp downstream of it. Measured on 2026-08-06:

  - a 5-line test appended at the very END of ~test/constfold.til~ (the
    cheapest possible insertion point) moved 80 of the 1180 lines of
    ~test/constfold.c~; only ~10 were the new test, the rest were
    ~assert_eq__I64~'s temps shifting by +5 and the ~_til_str_lits[]~
    indexes after the insertion shifting by 1;
  - a 3-line behaviour-identical refactor of ~repl_prompt~ in
    ~src/til.til~ (the LAST unit emitted, so the best case) moved 4,737 of
    the 267,001 lines of ~til.c~; 2,235 of the 2,364 removed lines carried
    a renumbered temp, against ~10 lines of real change. Churn ran from
    line 12,428 to EOF, every hoist temp after the edit shifted by a
    constant +3;
  - a 9-line addition to ~src/self/context.til~ (an EARLY unit) moved
    258,822 lines of ~boot/til.c~, 114,182 of them carrying a renumbered
    temp.

*** Determinism contract

  - A fresh ~LoadedProgram~ plus identical source/options must emit identical
    bytes, regardless of earlier compilations in the process, allocator
    addresses, or scheduling outside that compilation.
  - A synthesized name must not depend on how many names were minted
    earlier in the program. Its variable part is an ordinal within the
    definition that owns it, plus that definition's own unique name.
  - Counters may be monotonic across one definition; they must be fields
    of that program's ~Context~, never module globals.
  - Counter increments and indexed names must follow ordered AST, Vec, or
    sorted-Map walks. Do not derive names or emission order from addresses.
  - The contract covers every generated artifact, not only the main C file:
    for the compiler self-build that is ~til.c~ and ~til_forward.h~.
  - Bootstrap self-application is a separate half of the same check: the
    compiler built by ~til_boot~ must regenerate the bytes that pass 1
    produced. Comparisons must use artifacts generated under the same HEAD,
    because ~VERSION~ deliberately embeds the current git commit.
