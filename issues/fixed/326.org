# priority: high
# category: cleanups
** FIXED #326 Make unused diagnostics honest and scavenge all unreachable code

*** Post-mortem

Root cause, in one sentence: the builder papered over liveness with
blanket suppressors (~(void)hoisted__~ casts, ~__attribute__((unused))~,
unconditional underscore casts) while the scavenger's roots were blanket
too (every core value initializer, five lifecycle methods per reached
type, macro signatures, whole generated helper families), so dead code
neither failed the C build nor left the output.

What changed, by layer.  Builder: casts only on ~_~-prefixed names and
only when the body liveness scan finds them unread (name-keyed, with the
declared-twice safe side); no attribute anywhere; generated ABI slots
renamed ~_til_env~/~_argv~; pooled Str literals emit no placeholder; and
the generated families consume the reachability result through builder-
side inventories -- reflection (~builder_reflect_inventory~), dyn
dispatch targets (~builder_collect_dyn_fn_targets~), variant constructor
sites (~builder_collect_variant_ctor_sites~), inlined accessors.
Desugarer: the three hoists that created dead temps (is_n tag width,
swap_replace's swap_bytes size, malloc/calloc byte counts) no longer
create them -- fixed at the source instead of teaching liveness to mop
up.  Scavenger/loader: top-level values are graph nodes (core
unconditionally, user units when ~scav_value_decl_sweepable~ proves the
initializer effect-free); a reached type roots its layout, not five
lifecycle methods; macro signatures and field defaults are not edges;
libraries are scavenged with their exported ABI as roots; ns values
sweep like ns funcs; and the roots are defined centrally per mode in
~scavenge_visited_imported~ (FFI boundary = exactly the three symbols
~nm -u~ reports on ext.o; the runtime-name ~*.size~ wildcard is
unconditional; cli roots main plus its exact argv converters; test roots the
selected tests; script/cli/test root executable top-level statements;
libraries their exports).  Holes the sweep exposed got source-level
fixes: ~collect_refs~ now records assignment targets, and REPL full-load
turns no longer scavenge at all (~repl_finish_prepare_program~) -- a
session is an open world.

Numbers: ~test/constfold.c~ 9,390 -> 1,340 lines (961 -> 0
~(void)hoisted__~, 260 -> 0 attributes/til_env casts); ~println~-only
script 4,149 -> 249 lines; ~test/pure.til~ (mode pure) 21,264 -> 959;
~boot/til.c~ ~382k -> ~263k; underscore casts ~17k -> 2,338.  chess, go
and snake emit no never-called function at all.

Regression tests: ~dead_temps_*~ (4), ~minimal_reach_no_ast_model~,
~minimal_reach_no_dead_lifecycle~, ~minimal_reach_no_unread_global~,
~cli_args_exact_argv_roots~, ~cli_args_no_inlined_accessors~,
~first_class_no_unused_attrs~, ~first_class_no_dead_field_default~,
~pure_lib_no_ast_model~, ~pure_no_unbuilt_variant_ctor~, plus the
~both~ entries for the fixtures and ~test/constfold.c~ as the committed
broad baseline.

Deliberately out of scope, tracked elsewhere: #209 owns the stack-delete
storage decision (the old ignored ~call_free~ temp is gone -- the AST
carries a literal Bool and the #302 stage-1 asserts guard builder/
garbager drift); #302 owns the ownership authority a binding-dropping
rewrite of unread EFFECTFUL top-level initializers would need (they stay
roots by the script-mode policy: executable statements are the
program).  Scope-aware liveness became moot for the invariant: the dead
temps it was meant to find are gone at their source, ~-Werror~ guards
new ones, and the remaining name-keyed conservatism only adds casts #86
explicitly allows on ~_~ names.

The generated C still hides dead-code and liveness mistakes behind broad
warning suppressors.  The visible example in ~test/constfold.c~ is:

#+begin_src c
USize Str_size(void) {
    U32 hoisted__U32_503 = 16;
    (void)hoisted__U32_503;
    return hoisted__U32_503;
}
#+end_src

The temp is used by the return, so the cast is not suppressing an unused
binding at all.  It is emitted solely because the name starts with
~hoisted__~.  This defeats the reason hoisted temps deliberately do NOT
start with ~_~: a compiler temp that goes dead should expose a missed DCE
case through C's ~-Werror=unused-*~, not be silently accepted.

Til's source contract is already clear from #86: an unused parameter or
local is an error unless its name starts with ~_~.  Generated C should
preserve that contract.  Emit ~(void)name;~ only when the binding is truly
unread AND its name starts with ~_~ (including compiler-generated ABI slots
that are deliberately unused).  Every unread non-underscore binding must
remain a hard error that forces either the user or the compiler pass that
created it to be fixed.

*** Scale and concrete evidence

The current committed ~test/constfold.c~ is 9,390 lines and contains:

- 961 ~(void)hoisted__...~ statements.  Most sit next to real uses, so
  they are pure noise; any genuinely dead temps among them are hidden.
- 260 ~__attribute__((unused))~ declarations and 260 ~(void)til_env;~
  statements, largely from wrappers emitted without proving they are
  needed.
- All 13 core ~TYPE_*~ globals from ~src/core/ast.til~.  Each appears only
  as one declaration and one initialization in this output; none is read.
  In particular, dead ~TYPE_STRUCTDEF~ and ~TYPE_ENUMDEF~ initializers make
  the scavenger retain compiler-only ~StructDef~, ~EnumDef~, ~Expr~ and
  their ~Map__Str_USize~ / Vec dependency graph in a runtime constfold test.
- ~KeyNotFound~ appears only in its type/method definitions, dyn wrappers,
  dyn dispatch table, size/reflection branches and forward declarations.
  There is no runtime use outside that self-supporting generated island.

This is not only cosmetic C churn.  The suppressors remove the compiler's
best backstop for post-typer liveness bugs, while the retained declarations
increase compile time, binary size and the number of codegen paths every
change must keep valid.

*** Current root causes

1. ~emit_stmt_decl~ in ~src/self/builder.til~ emits a cast for every local
   whose name starts with either ~_~ OR ~hoisted__~ (both the Ref and
   non-Ref paths).  This directly contradicts ~hoist_to_temp~ in
   ~desugarer.til~, whose comment and non-underscore spelling exist so dead
   compiler temps are NOT exempted.

2. The pooled immutable-string path emits
   ~(void)_til_str_lits[n];~ as a placeholder for a declaration that it did
   not emit.  A used pooled literal needs no placeholder; an unused one
   should have disappeared before emission.

3. Function parameter emission scans the final body and casts every unread
   parameter, without also requiring the ~_~ prefix.  The typer checked the
   pre-constfolder body, so a transform can erase the final read and the
   builder will silently hide the stale signature.  Generated adapter slots
   such as ~til_env~ and no-argument-main's ~argv~ are also unconditionally
   cast despite not using the deliberate-unused naming convention.

4. The stack-local delete override casts away its now-ignored hoisted
   ~call_free~ temp.  That temp exists because the AST still says one thing
   and the builder emits another; #209 tracks moving this storage/delete
   decision into the AST.  The cast is a symptom, not a valid permanent
   fix.

5. ~scavenge_filter~ only sweeps declarations for which ~is_def~ is true
   (func/struct/enum).  Top-level value declarations are never candidates.
   ~scavenge_visited_imported~ then explicitly roots the initializer refs of
   EVERY core top-level value because all those values survive.  That is why
   dead ~TYPE_STRUCTDEF = Type.Struct("StructDef")~ keeps the compiler AST
   data model alive in ordinary user/test output.

6. Visiting any type unconditionally queues its ~delete~, ~clone~, ~size~,
   ~cmp~ and ~hash~ methods.  This turns "the layout is needed" into "the
   standard lifecycle/dynamic surface is needed" and lets those method
   bodies retain further declarations.  Actual AST calls, generated
   ownership operations and dynamic/reflection uses should root the exact
   methods they need instead.

7. Body DCE runs after the top-level reachability mark/sweep and recognizes
   only a narrow set of immutable literal or primitive-FCall temps.  A body
   reference that DCE later removes can therefore pin a top-level function
   or type during the earlier mark.  The broad builder casts hide any
   candidate shape the body pass does not understand.

8. The builder unconditionally emits dyn call bodies, dyn wrappers/closure
   values, dyn_has helpers, dyn_size_of and all reflection families after
   ordinary function emission.  Closure values and several static helper
   functions carry blanket ~__attribute__((unused))~.  These generated
   symbols are outside the scavenger's AST declaration sweep, so they can
   form dead self-referential islands even when their source declarations
   were pruned correctly.

*** Required invariant

- A surviving unread source parameter/local is legal only when its name
  starts with ~_~.  Emit exactly one cast for it if C needs one.
- A compiler-generated ABI parameter that must exist but is intentionally
  unread must also use a leading-underscore name (for example
  ~_til_env~ / ~_argv~), and gets a cast only when it is actually unread.
- ~hoisted__*~ and other non-underscore compiler temps never receive an
  unused cast.  They are either read, removed, or cause the C build to fail.
- Do not use ~__attribute__((unused))~ to make a dead generated function,
  closure value or helper compile.  Reachable static objects have a real C
  reference; unreachable ones are not emitted.
- Application/script/test output contains only declarations reachable from
  its mode roots.  Library output keeps its exported ABI as roots even when
  there is no internal caller.  Runtime-name dynamic/reflection dispatch is
  conservatively rooted according to the names or wildcards that can reach
  it.

*** Detailed implementation plan

1. Add focused output checks before removing suppressors.
   - Keep the existing #86 typer cases proving non-underscore unused
     params/locals fail and ~_~-prefixed ones pass.
   - Add a small compiled fixture with a used hoisted temp, a constfold-dead
     temp, an effectful call whose result is dead, and deliberate
     ~_~-prefixed params/locals.
   - Assert in its generated C that the used temp has no cast, the pure dead
     temp is absent, the effectful call remains without a dead result
     binding, and only the truly unread underscore declarations are cast.

2. Make local/parameter suppression obey the invariant.
   - Remove ~starts_with("hoisted__")~ from both ~emit_stmt_decl~ cast
     conditions.
   - Make the final-body parameter check require BOTH no reference and a
     leading underscore.  A non-underscore miss is intentionally left to
     GCC's ~-Werror=unused-parameter~.
   - Emit no statement for a pooled string-literal declaration that has
     been replaced by the literal-pool symbol; its real later references
     already name that symbol.
   - Rename generated, contract-forced unread C parameters to
     leading-underscore local names and cast them conditionally.  Remove
     redundant casts from parameters that are read by dispatch branches or
     error messages.
   - Resolve the stack-delete ~call_free~ mismatch in the AST as described by
     #209, then let DCE remove the ignored temp.  Do not replace its current
     cast with another guard.

3. Generalize body liveness before global reachability.
   - Compute reads/writes per declaration after constfolder and garbager
     rewrites, respecting nested scopes/shadowing rather than treating an
     equal name as proof of use.
   - For an unread pure binding, remove the declaration and its proven
     trivial cleanup.  For an unread binding with an effectful RHS, preserve
     the effect as a bare expression statement.  For an owning result,
     preserve the AST-recorded delete; never drop or invent ownership in the
     builder.
   - Handle compiler temps by their typed storage/effect/ownership facts,
     not by granting the ~hoisted__~ prefix a warning exemption.  Prefixes
     may classify origin, but they are not liveness.
   - Run body cleanup before top-level marking, then repeat body cleanup and
     declaration reachability to a fixed point if sweeping a function/member
     releases more references.  The final AST must contain no stale edge that
     keeps an otherwise unreachable declaration alive.

4. Extend the scavenger's declaration graph and root policy.
   - Put top-level values/globals in the same mark/sweep graph as functions,
     structs and enums.  Walk an initializer only after that declaration is
     reached; delete the current "all core value initializers are roots"
     rule.
   - Define roots centrally per mode: CLI ~main~ plus exact generated argv
     parsing helpers; all selected tests for test mode; executable top-level
     statements for script mode; and exported declarations/required init for
     library mode.  Preserve ext/FFI/link and mode-specific entrypoints as
     explicit roots, not accidental blanket retention.
   - A reached type roots its field/payload layout dependencies, but not five
     lifecycle methods automatically.  Concrete AST calls and garbager-
     inserted operations root ~clone/delete/size/cmp/hash~ individually.
   - Keep the existing literal dynamic target and ~*.method~ wildcard
     semantics, but expand them only across otherwise reachable runtime
     types.  Reflection-by-string must similarly record the exact type set or
     a deliberate wildcard root.
   - Sweep namespace values as well as namespace funcs, maintaining the
     member index exactly as the current in-place member sweep does.

5. Make generated C helpers consume the same reachability result.
   - Record which raw-C facilities are requested by the surviving AST:
     dyn_call/dyn_fn/dyn_has, dyn_size_of, struct/enum/FuncSig reflection,
     collection helpers, closure wrappers/values and print helpers.
   - Gate each ~emit_*~ family on that inventory.  Within dyn dispatch, emit
     wrappers and closure values only for marked ~Type.method~ targets; do
     not emit one for every surviving namespace function.
   - Emit a function's static closure wrapper/value only if the function is
     used as a first-class value.  A function reached only by direct call
     needs only its ordinary definition.
   - Remove blanket ~__attribute__((unused))~ after the inventory is exact.
     The C compiler then verifies every emitted static helper has a real
     consumer.

6. Add reachability regressions and a size/noise baseline.
   - A minimal app/test that mentions no compiler AST/reflection must not
     emit dead ~TYPE_*~ globals, ~StructDef~, ~EnumDef~, ~Expr~ or their
     container graph.
   - A dead public app-level func/struct/enum/global and dead namespace
     member must disappear; the same public declarations in library mode
     must remain exported.
   - Literal dynamic dispatch retains only its target; runtime-type wildcard
     dispatch retains the named method on every reachable candidate type;
     reflection fixtures retain the metadata they query.
   - Keep an effectful-unused-result test so DCE cannot turn liveness cleanup
     into silent side-effect removal or an owned-result leak.
   - Track ~test/constfold.c~ as the broad proof: zero
     ~(void)hoisted__...~, no unread ~TYPE_*~ init island, and a substantial
     reduction from the current 9,390 lines / 260 unused attributes.
   - Run the full suite with C warnings as errors.  Because this changes how
     the compiler emits its own C, use ~make test_two_pass~ and a
     ~Two-pass:~ commit (or a documented preparation/use sequence) for the
     implementation.

  gaps it had been covering, each fixed at its own level.  (a) The

  unconditionally: ~boot/til.c~ carried about 17,000 of them, most sitting
  next to a read on the very next line -- the same noise the ~hoisted__~
  exemption produced, which is where this issue started.
  ~builder_collect_body_liveness~ records, per function body, the names it
  READS and the names it declares more than once; the cast is emitted when
  the binding is unread, or when the name is declared twice (the ref set is
  name-keyed and cannot tell sibling-scope bindings apart, so it takes the
  safe side there).  Three exclusions make reads mean what C means: an
  assignment TARGET is a write, not a read (C has a separate
  -Wunused-but-set-variable); a ~T.delete(x, ...)~ cleanup is not a read
  (the builder elides whole classes of them, and when one IS emitted the
  name appears in the C anyway, so the missing cast costs nothing); and a
  Case node's PATTERN holds binders, not reads, which is exactly the
  ~case Option(T).Some(_v):~ shape the hatch exists for.
  ~src/til.til~ 281k -> 261.5k lines of C and ~17k -> 2,389 casts;
  ~examples/chess.til~ 7 casts, ~examples/snake.til~ 1,
  ~test/minimal_reach.til~ 0.

- [X] Step 5's last clause: a ~_dyn~ wrapper and its closure value are
  emitted only for the ~Type.method~ pairs dyn_fn can actually ask for.
  The family was gated as a whole (on ~dyn_fn~ appearing anywhere), so one
  ~dyn_fn~ call site meant a wrapper plus a closure value for EVERY
  surviving namespace method of every type -- ~test/first_class.til~
  emitted 610 never-called functions out of 1,310, most of them
  ~AnonEnumN_<Variant>_dyn~ for variant constructors nothing dispatches to.
  ~builder_collect_dyn_fn_targets~ records what each ~dyn_fn~ call names:
  an exact pair for ~dyn_fn("T", "m")~, and the ~*.m~ wildcard when the
  type is a runtime expression, which is the collection shape
  (~dyn_fn(elem_type, "clone")~ in std/dyn_array.til).  The wrapper, the
  closure value and the dispatch-table entry share one predicate, so a
  mismatch would be a link error rather than a silent hole.
  ~test/first_class.til~ 20,515 -> 18,340 lines of C,
  ~test/dyn_vecs.til~ -> 8,612.

- [X] Step 5 again, for the other generated per-variant family: an enum
  variant's C constructor is emitted only where some expression actually
  CONSTRUCTS it.  Surviving the scavenger's ns member sweep is not enough.
  An enum with any live value gets a garbager-inserted delete, and the
  generated delete/eq/to_str/clone switch over EVERY variant, so their
  ~is_n(self, E.V, w)~ tag checks NAME them all -- real references whose C
  lowering is a compound-literal tag compare, not a call.  So the blanket
  rule declared a constructor for each, and ~test/pure.til~ carried 23
  prototypes whose definitions the scavenger had already dropped: declared,
  never defined, never called.  ~builder_collect_variant_ctor_sites~ keys a
  namespace-shaped field access the way the CALL emitter names the C
  function -- ~til_type_name~ of the RECEIVER'S TYPE, not the receiver
  ident's spelling.  That is what makes ~Option(ref OptCell).None~, whose
  receiver is an FCall rather than an Ident, come out as
  ~Option__ref_OptCell_None~, and it is why the three definition branches
  and all four prototype loops agree by construction; keying on the
  spelling instead is a link error, which is how the first attempt failed.
  Two positions are skipped because the builder never lowers them to a
  call: ~is_n~'s tag operand (child 2) and a Case node's pattern (child 0).
  ~examples/chess.til~ now emits 43 functions of which the only never-called
  one is ~main~.

- [X] User-unit top-level values are no longer blanket roots.  A value
  decl whose initializer is provably effect-free -- a literal, or a bare
  ident -- is an ordinary graph node: the seeding skips it, the BFS walks
  its initializer only if the name is reached, and ~scavenge_filter~
  sweeps it otherwise (~scav_value_decl_sweepable~; the seeding and the
  sweep share the one predicate so the two sides agree on which decls are
  graph nodes).  Anything containing a call stays a blanket root -- in
  script mode a top-level ~x := foo()~ IS the program whether or not ~x~
  is read, so the conservative side needs no effect-preserving rewrite;
  only sweeping THOSE would, and their effects have to run anyway.  The
  win in real programs is std/raylib.til: every GUI program carried every
  unused ~SHADER_~/~TEXTURE_~/~KEY_~/... flag constant
  (~examples/snake.til~ 2,823 -> 2,203 lines of C, chess 7,786 -> 7,156).
  ~minimal_reach_no_unread_global~ is the regression; the fixture's
  ~both~ entry prints the surviving global to prove the sweep is
  reachability, not a blanket rule.  Two real holes surfaced and were
  fixed at their source rather than by narrowing the sweep: (1)
  ~collect_refs~ never recorded ASSIGNMENT targets -- the name lives in
  the Assign node's data, not an Ident child -- so a global only ever
  written by a reached function (std/doc's ~__doc_init__~ storing the
  registry blobs) was invisible to the reachability walk; and (2) the
  REPL's full-load turns ran ~finish_prepare_program~ and therefore
  scavenged, which is wrong by premise in a session: the next turn can
  name anything, and ~interp_session_eval_imported_once~ runs an imported
  unit's top-level once per session, so a turn with no ~help()~ in sight
  swept std/doc's blob globals and poisoned every later ~help()~ turn
  (~repl_finish_prepare_program~ now constfolds without scavenging, the
  same reasoning ~repl_init_cached_program~ already applied to the cached
  base; ~repl_help~ is the regression that caught it).

- [X] Step 4's root policy is defined centrally per mode.
  ~scavenge_visited_imported~ now reads as the policy table: the
  unconditional roots (Str, the three-symbol ext.c FFI boundary, the
  runtime-name ~*.size~ wildcard) followed by one seeding function per
  mode -- ~seed_library_roots~, ~seed_cli_main_arg_roots~ +
  ~seed_executable_stmt_roots~, ~seed_test_roots~ +
  ~seed_executable_stmt_roots~, or ~seed_executable_stmt_roots~ alone --
  with core units contributing only their executable non-Decl
  statements.  Pure extraction: the output is byte-identical across the
  corpus.

*** Closing note: where each half of the answer lives

The issue is one question in the text but two in the code, and the
difference only became clear at the end.

The SCAVENGER answers "is this declaration used" -- once, for every
backend, with no knowledge of who consumes the AST.  Dynamic references
count: ~T.size()~ resolved by runtime name is a real edge, so its root
is unconditional.  A first version conditioned that root on
~ctx.compile_mode~ and a later one moved C lowering predicates
(~is_pod_struct~, ~fcall_is_shallow_return~, the splice mirror) into
~scavenger.til~ outright; both were wrong in the same direction, and
both are undone.  More backends than C are coming, and none of them
should inherit C's rules.

The C BACKEND answers a question only it can ask: having spliced
~Color.Red~ into a compound literal and folded ~T.size()~ to a literal
at every site, does any emitted C still CALL the function?  That is a
fact about C lowering, so the emit inventory, the omission gates and
the splice mirror live in ~builder.til~ (~builder_fill_emit_inventory~).
A second backend writes its own; it does not reuse this one.

One constraint worth recording, because it looks like a layering
mistake and is not: the gate runs from ~build()~, not from
~scavenge_imported~, because its queries read the C-symbol aliases
~build_register_func_symbols_lp~ installs.  Asking earlier returns a
different answer -- ~EvalHeap_clone~ and ~CtorArg_clone~ became implicit
declarations when it ran at sweep time.

*** The loose end this work depends on -- and why it is not a small fix
    (attempted and measured 2026-08-04)

The site collector mirrors the emitter's stack-storage answer for the
POD-struct ctor Decl (~bvs_ctor_stack~ in
~builder_collect_ns_member_sites~) instead of reading ~gc_storage~,
because on that path the garbager records ~HeapBox~ while the builder's
compound-literal shortcut emits a stack value.  ~assert_gc_stack~ calls
it one of the paths that "stay unasserted until stages 4/6 collapse the
compensation".  #302 closed with it intact, and it is load-bearing:
deleting the mirror brings ~Point_clone~ straight back into
~test/aliases.til~'s output.

The obvious fix does NOT work, and the reason is worth recording so the
next attempt does not repeat it.  Teaching ~record_storage_decisions~ to
recognise the shape and record ~Stack~ builds and passes the fixture --
and then fails the suite on ~test/forward_refs.til~, ~test/constfold.til~,
~test/first_class.til~ and three more, all with the transition assert
firing.  ~record_storage_decisions~ runs PER BODY, DURING TYPING, so a
struct declared later in the file is not registered yet: ~is_pod_struct~
answers false, the record says ~HeapBox~, and the builder -- which runs
with the whole program resolved -- answers true and takes the shortcut.
The garbager cannot answer a whole-program type-shape question at the
time it currently records.

So the real fix is a pass-ordering change: settle ~gc_storage~ after
typing completes, when every declaration is resolvable, rather than
inside the per-body walk.  Only then can the mirror go, the ctor path
join the asserted set, and the ~is_pod_struct~ /
~pod_ctor_args_are_safe~ pair be shared with the garbager instead of
being re-derived behind its back.

A second path is knowingly divergent and will NOT be fixed this way even
then: the POD-struct user-clone value copy.  The builder's predicate for
it (~is_pod_struct_user_clone~) reads emit-time state -- ~stack_locals~,
which only exists once the body is being walked -- so no earlier pass has
anything to record from.
