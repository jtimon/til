** FIXED #429 no-shell-antipatterns.sh: tail -f check has false positives

*** Post-mortem

Root cause: the hook's ~[^|;]*~ ran across ~&&~ into later commands,
so any later ~-f~ (e.g. ~--force-with-lease~) matched. The check only
existed because a never-exiting ~tail -f~ was auto-backgrounded into a
ghost task.

Change: ~CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1~, already set in
~.claude/settings.json~, makes a command that reaches its timeout stop
instead of moving to the background, so the reason for the check is
gone. ~no-shell-antipatterns.sh~ is deleted (its ~git stash~ block is
now a ~permissions.deny~ rule), and the doc/bots/lessons_learned.org
workaround bullet is removed. No regression test: hooks are not part
of the suite; ~tail -1 && git push --force-with-lease~ was checked by
hand against the remaining ~block-background-bash.sh~ and passes.

*** Original report

~.claude/hooks/no-shell-antipatterns.sh~ blocks ~tail -f~ with

#+begin_src sh
grep -qP '\b(tail|less|more)\s+[^|;]*-[fF]'
#+end_src

on the command's first line. ~[^|;]*~ stops only at ~|~ and ~;~, so the
match runs across ~&&~ into later commands:

- ~git log --oneline | tail -1 && git push --force-with-lease ...~ is
  blocked: the ~-f~ of ~--force-with-lease~ matches.
- Any first line merely mentioning the text, e.g. a grep pattern
  containing ~tail -f~, is blocked.

Also, the comment above the check says "tail itself is already blocked
above", which stopped being true when plain tail/head/cat were allowed
(see the NOTE at the top of the file).

*** Fix

Match ~-f~ / ~-F~ / ~--follow~ only as tail's own option: stop at ~&~
as well as ~|~ and ~;~, and require the flag to be a separate word
(~\s-[a-zA-Z]*[fF]\b~ or ~--follow~), not a substring of a later long
option. Drop the stale comment. A workaround is documented in
doc/bots/lessons_learned.org ("Remote sessions: git recovery and the
shell hook"); remove that bullet with the fix.
