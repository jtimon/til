# category: optimizations
** FIXED #292 Intern identifier / type-name Strings (kills the #1 allocator and the #1 compare cost)

*** Post-mortem

  Root cause: compiler identifiers and field names were owned Strings copied
  throughout the AST and repeatedly compared through Str-keyed maps. Even
  read-only accessors cloned those names, so transient compiler operations
  paid for allocation, copying, comparison, and deletion.

  Fix: name accessors first became borrows, then a Context-owned SymbolPool
  replaced identifier and field-access payloads and compiler name registries
  with Sym values. TypeScope bindings and function-definition lookups use
  symbols directly, while compiler consumers resolve a borrowed Str only at
  string boundaries. The completed migration improved three self-translations
  from 19.07s to 18.17s (-4.7%); 50 maps.til translations remained at timer
  parity (8.12s versus 8.07s on the exact parent).

  A fresh full self-translation profile on 2026-08-18 measured Str_clone at
  13,804,221 calls, 12,908,281 allocations, and 168,531.4 KiB. Callgrind
  attributed 996,704 calls (7.7%) to cloning named Type payloads and another
  311,980 (2.4%) to til_type_name. Together they represented about 0.32% of
  74,650,850,663 measured instructions. Type.eq performed only 13 named
  Struct string comparisons. Converting the remaining public Type payloads
  would therefore add a private duplicate representation or change the public
  ownership API for a sub-percent CPU result, with no material comparison
  win. The profile rejects that final stage rather than justifying it.

  Regression coverage: parsing's identifier and field-access assertions and
  the enum_ctor_named_constructor_payload generated-code count, plus the full
  suite run for the symbol migration.

  After the cast Type_Primitive fix landed, a fresh --prof run
  (`bin/til run examples/profile.til src/til.til`; snapshot in
  doc/profiling.org "Hot functions") makes two costs dominate, and they
  are the SAME problem:
    - Str_clone is the #1 allocator: 11.8M allocs / 26M frees / 145 MB,
      ~3x the next entry.
    - Str_cmp is the #1 CPU cost: 20M calls, ~37s inclusive -- this is how
      ordered Maps compare Str keys.
  The compiler copies and compares identifier / type-name strings nonstop.

  Where the clones come from:
    - ident_name / field_access_name (src/core/ast.til) clone
      unconditionally on EVERY read: `return id.name.clone()`. There are
      ~495 read sites across src/self, the large majority compare-and-
      discard (e.g. `id.ident_name().eq("foo")`).
    - Expr_clone deep-copies every embedded name Str.
    - Every Type.Struct/Enum/Custom/FuncPtrSig carries a cloned Str name
      (til_type_name's .clone(), make_delete_call's Type.Custom(tname.clone())
      per cleanup site, etc.). NOTE: these are NOT garbager auto-clones --
      the garbager only inserts the matching deletes (the 26M Str_delete
      frees); the clones are hand-written because the signatures return /
      hold owned Str where a borrow would do.

  Structural fix (the real win): intern identifier and type-name strings
  into a pool held in Context. A Sym (small integer id) replaces the Str in
  the hot name positions: IdentData.name, FieldAccessData.name, the Str
  payloads of Type.Struct/Enum/Custom/FuncPtrSig, struct/func names.
  clone(Sym) = copy an int (no malloc); cmp(Sym) = int compare (no byte
  scan). This removes most Str_clone churn (memory #1) AND collapses
  Str_cmp into id comparison (CPU #1). #234 (HashMap for Str keys) largely
  falls out of it.

  Lighter first step (independently valuable, no Sym needed): change
  ident_name / field_access_name to `returns ref Str` (borrow) and drop the
  .clone(). Then walk the ~495 sites compiler-guided: compare-and-discard
  callers need no change; only callers that store/return the name keep an
  explicit clone. Best done in a fast LOCAL session -- it is a cascading,
  multi-build change -- and watch the interpreter/comptime paths that read
  these accessors (ident_name is used during comptime eval too).

** Progress

  - [X] Make identifier, field-access, numeric-literal, and expression
    type-name reads borrow; clone only at ownership boundaries.
  - [X] Reuse resolved scope entries and switch enum definitions instead of
    repeating string-keyed lookups.
  - [X] Add a Context-owned SymbolPool and migrate function-signature names
    to Set(Sym).
  - [X] Preserve insertion-order Sym -> Str resolution across Context clones.
  - [X] Migrate the remaining Context name registries (closure_emit_captures,
    closure_value_names, script_globals, ref_globals) to Set(Sym).
  - [X] Migrate the BuilderFunc per-function scratch registries (stack_locals,
    stack_local_types, ref_locals, ptr_locals, ref_dyn_locals,
    stack_lit_str_locals, unsafe_to_hoist, shadowed_params, body_refs,
    body_multi_decls) to Sym keys.
  - [X] Migrate FieldAccessData.name and IdentData.name to Sym together with
    TypeScope bindings and every compiler lookup. The initial AST-only form
    cut maps.til Str_clone calls from 545,149 to 484,866 and allocations from
    1,024,103 to 903,850 but was about 2% slower because consumers resolved
    names back through string-keyed tables. The completed migration uses a
    compiler-only open-addressed SymbolPool index, so core programs do not
    import the generic HashMap implementation or own duplicate name Strings.
    Against exact parent 80788b616, 50 maps.til translations are at timer
    parity (8.12s current vs 8.07s parent), while three self-translations
    improve from 19.07s to 18.17s (-4.7%).
  - [X] Migrate TypeScope.func_defs and binding-less C aliases to Sym keys;
    function scope walks now compare U32 symbols instead of function names.
  - [X] Migrate TypeScope.struct_defs to Sym keys; type-definition scope
    walks and local-definition probes no longer compare names.
  - [X] Reprofile compiler Type-name payloads. Their measured cost does not
    justify changing public Type ownership or adding a private duplicate type
    representation; retain Str payloads for runtime reflection and
    dyn_type_to_str.
