** FIXED #397 A Type carries its Sym: Struct/Enum/Custom payloads become symbols

*** Post-mortem

Root cause: the #292/#337 interning migration keyed the scope
registries by Sym but left the AST's Type payloads as spellings, so
every hot consumer hashed a name back into the symbol the Type had
been built from (71% of SymbolPool.lookup's 540K calls). Steps 1-3e,
kept below as the record, appended Sym twins to Type, taught every
reader both forms, flipped the FuncPtrSig producers, then the
Struct/Enum/Custom producers under ruling (a) -- type_kind_eq /
type_eq answer mixed-form equality, since core's runtime Str forms
stay forever -- and routed the hot consumers through the symbol.
Step 5 measured the whole arc against the pre-interning compiler on
ONE input and harvested the last round-trips that measurement
exposed, in the C backend's name classifiers.

Outcome, same input (9263b9c8's test/first_class.til) through three
compilers: 4,656M instructions before interning, 5,649M on the
master this closed from, 5,581M with this commit. The total is not
below the pre-interning figure and this design cannot take it there:
the name machinery itself is cheaper than it was (self cost ~1,055M
-> ~550M), and what remains above the baseline is other work the
compiler has taken on since. The hashes still standing all come off
Str FIELDS (Declaration.name, FuncSig.return_type, LocalInfo.name,
AssignData.name) or synthesized names, which is a different
migration; "Step 5 as it actually went" lists them with counts.

Regression tests: the full suite -- the corpus eqcheck covers the C
backend's classifiers byte-for-byte, and test/library_namespace.til
and test/enums.til are the two that caught step 3e's twin-arm drifts.

*** Why

The #292/#337 interning migration converted the scope registries to
Map(Sym, ...) keys, but the names that FEED the hot lookups still come
from the AST's type spellings: Type.Struct(Str) / Type.Enum(Str) /
Type.Custom(Str), read via expr_type_name_ref and friends. So
get_struct(name) and get_binding_name(name) hash a spelling to recover
a symbol that was known when the Type value was built.

Measured on `translate test/first_class.til` (2026-08-19, master
d125e36e): SymbolPool.lookup runs 540,767 times; get_struct is 41.6%
of the calls and get_binding_name 29.3% -- 71% combined. Each lookup
is fnv1a over the whole name (~15 instructions/byte at -O0) plus a
Str_eq bucket confirmation; fnv1a + Str_eq together are ~8% of the
run. This is the main remaining chunk of the interning migration's
half-way cost (the migration's maps got cheaper, but paying
hash+confirm at the door made hot paths NET slower than the
pre-interning Str-keyed binary searches).

Micro-alternatives measured and rejected before this design, so they
stay rejected:
  - first-byte fast path in Str.cmp: +4.5%;
  - value-form tag reads: +0.001% (noise);
  - wiring the never-read bindings_filt as a probe filter: the filter
    skipped 18.5% of probes and still cost +2.5% net (per-call
    fingerprint arithmetic on 826K calls outweighed the skipped
    searches). At -O0 the win comes from removing WORK, not from
    adding cleverness in front of it.

*** The design: replace, not duplicate

Type's name payloads become symbols:

    Struct: Sym,  Enum: Sym,  Custom: Sym   (FuncPtrSig: Sym too)

ONE representation. The alternative -- carrying {name: Str, sym: Sym}
side by side -- is a second representation of the same fact that must
never disagree, exactly what CLAUDE.md's duplication rule exists to
prevent, and is rejected here by design, not deferred.

Spellings come back through SymbolPool.resolve(sym) at the edges that
genuinely need text: diagnostics, name mangling, C emission, to_str.
A site that forgets resolve() prints a number instead of a name --
ugly and loud, not silently wrong.

*** Why this is NOT a single commit

doc/self.org "Staged migration across master merges" applies twice
over:

  - Type's own comment records the constraint: til_boot has Type's
    layout and tag values BAKED into its compiled C. Changing a
    payload from Str (16 bytes) to Sym (4) changes the variant's
    layout; a single commit would have master's til_boot mis-decoding
    Type values while bootstrapping the very compiler that defines
    the new layout. Pass 1 dies, so two_pass cannot rescue it (the
    CAP_INLINE lesson, which burned exactly this way).
  - The interpreter reads Type through its raw-bytes layout model
    (struct_layouts / enum payload slots), so both backends must
    switch understanding in the same step a value's bytes change.

*** Staged plan (each step merges to master before the next)

1. Preparation: teach the compiler to CONSTRUCT and MATCH both forms.
   Add Sym-carrying twins appended at the enum's END (tag stability,
   same rule Primitive followed): StructSym: Sym, EnumSym: Sym,
   CustomSym: Sym, FuncPtrSigSym: Sym. Nothing produces them yet.
   Shared accessors in context.til so consumers ask one question:
   type_sym(t, symbols) (interning the Str forms on demand) and
   type_name_ref(t, symbols) (resolving the Sym forms). Suite green,
   emitted C byte-identical. [plain commit]

2. Consumers that ALREADY hold a symbol stop round-tripping through a
   spelling. Correction to this step's original rationale, which was
   wrong: it claimed routing get_struct/get_binding_name callers
   through get_struct_by_sym(type_sym(...)) wins "because type_sym
   interns ONCE per call instead of per scope level". get_struct
   already hashes once per call, not once per level -- it does a
   single symbols.lookup and then walks the levels by Sym. Routing a
   Str-holding caller through type_sym therefore buys nothing: the
   hash simply moves. The only free win available before step 3 is
   the caller that never needed a spelling in the first place --
   IdentData.name has been a Sym since #292, so any site doing
   ident_name(names) purely to hand the result to a name-keyed lookup
   is resolving a symbol so the lookup can hash it back.

   Harvested here (measured, `translate --force-rebuild
   test/first_class.til`): fa_is_ns's Ident branch via
   fa_is_ns_named_sym, the interpreter's static_ns_func_def_sym /
   ns_func_def_sym, and the constfolder's two ns_func_def sites.
   get_struct 279,919 -> 146,155 calls, SymbolPool.lookup 592,240 ->
   546,825, fnv1a 860,686 -> 815,271: 6,374,349,409 -> 6,353,302,722
   instructions, -0.330%. Modest, and that is the honest size of it.

   What is left is NOT free and belongs to step 3: get_binding_name's
   top caller resolve_type_alias (97,283), get_struct's top caller
   name_is_interface (42,369), and fa_is_ns's other branch (88,349)
   all take their name off a Type payload. find_callee_fdef's 59,660
   are worse than free -- those names are SYNTHESIZED at emit time
   (type_name.format("_delete") and friends), so interning them would
   add a hash plus an insert where today there is one lookup.
   [plain commits]

3. Producers flip: infer/parse/init sites that build Type.Struct(name)
   build Type.StructSym(symbols.intern(name)) instead.

   Done for FuncPtrSig (step 3c): all 12 producers, all readers, in one
   commit -- eqcheck EQ_OK, so it landed as a plain commit, not
   "Two-pass:" (the twins' tags were appended in step 1 and are already
   in master's boot; no emit path changes).

   Reader preparation done for Struct/Enum/Custom (step 3d): every
   compiler-side switch arm, tag predicate and helper accepts both
   forms. Family predicates is_struct_type/is_enum_type/is_custom_type
   replace the 50 tag-exact .is(Type.Struct/Enum/Custom) sites, and
   type_from_sym_init(sym, scope, symbols) is the Sym twin of
   type_from_name_init_name -- it resolves through get_binding_sym /
   get_struct_by_sym without hashing a spelling, which is where this
   issue's payoff will come from once the payloads carry Syms.

   The Struct/Enum/Custom PRODUCER flip was blocked on a design
   question the FuncPtrSig flip did not have: MIXED-REPRESENTATION
   EQUALITY. src/core cannot intern (no SymbolPool at runtime), and
   core produces Str-form Types CONTINUOUSLY at compile time --
   Expr.til_type() lazily stamps every Str literal TYPE_STR =
   Type.Struct("Str") (ast.til), declaration_type_from_name builds
   Type.Custom(name), and the TYPE_MAP/TYPE_SET constants flow into
   inference. Flipping the ~150 src/self producers makes the typer
   compare Type.Struct("Str") against Type.StructSym(sym "Str") at
   every structural .is()/eq site -- unequal, so spurious type errors
   (loud, but everywhere: the first flipped build reported "'s'
   declared as Str but value is Str" 36 times on first_class alone).
   FuncPtrSig dodged this because its only cross-form comparisons
   already went through funcptr_eq, which compares by NAME.

   The options, and the ruling taken (step 3e):
     a. A family-aware equality used at every site that compares two
        Type VALUES (as opposed to a tag test), with an audit to find
        them all. funcptr_eq is the precedent. TAKEN: type_kind_eq(a,
        b) is `a.is(b)` modulo the twin split (the typer's shape checks
        compare tags alone, by design -- the aggregate NAME is checked
        separately), and type_eq(a, b, symbols) is value equality with
        the spelling compared when the forms differ. The audit found
        seven `.is(var)` sites (validate_fcall_arg, the variadic Str
        arg check, infer_and_validate_fcall_args's expected type, the
        two field-assign checks, check_declared_value_type,
        infer_assign_stmt) and five `.eq` sites (infer_decl_type_def,
        the ext_global type check, infer_match_expr's arm agreement,
        and the precomputed-sequence element check in the interpreter
        and the C backend). is_named_type(t) names the four kinds.
     b. Never flip the names core also produces ("Str", "Map", "Set",
        StructDef/EnumDef) and flip only user-defined type names --
        rejected on sight: the hot names ARE the core ones, and mixed
        forms per-name is worse than mixed forms per-phase.
     c. Make core's lazy stamps pool-aware -- rejected: core is the
        runtime library; threading a compiler structure through it
        inverts the layering.

   With (a) in place the flip is one "Two-pass:" commit (the
   compiler's own Type literals change tags, so pass 2 must see them):
   every Type.Struct/Enum/Custom(name) producer in src/self builds the
   twin -- symbols.intern where a mut pool is at hand, sym_of (lookup,
   panic on a miss) for the Struct/Enum producers holding a borrowed
   pool, since those name REGISTERED definitions. Custom is an
   unresolved spelling that may be a typo the typer has yet to report,
   so decl_type_from_name / decl_typed / set_decl_type take a mut pool
   and always intern; core's declaration_type_from_name keeps serving
   dyn.til's reflection Declarations. Core's pool-less accessors
   (til_type_name, Declaration.type_name) PANIC on a twin rather than
   answer "" -- a twin there means one leaked past a boundary.

*** Step 3e as it actually went

   The flip alone bought NOTHING: 7,127,947,052 -> 7,135,136,189
   (+0.1%, measured on the pre-#326 master this was first built on).
   Every producer built a twin, every reader matched it, and the hash
   count did not move, because the hot consumers never took a Type --
   they took the SPELLING the caller had just resolved off the twin
   (SymbolPool.resolve went 36,623 -> 409,286 calls) and hashed it
   back: fa_is_ns -> fa_is_ns_named(name), name_is_interface(name),
   resolve_type_alias(scope, name), raw_widen_numeric(target_name),
   type_carries_borrow(scope, tname), get_struct(expr_type_name_ref(obj)).
   The payoff is in routing those through type_sym:

     - fa_is_ns and fa_own_type key on type_sym(obj.til_type()) (the
       Ident branch already keyed on the ident's own symbol);
       fa_is_ns_named is gone.
     - name_is_interface gained type_is_interface(t); the callers
       holding a param or field Declaration use it. The namespace-call
       path computes the receiver's symbol once (stamp twin, else
       Ident symbol) and feeds get_struct_by_sym, def_is_interface and
       note_cross_file_type_use_sym.
     - resolve_type_alias gained resolve_type_alias_sym(scope, sym):
       the width aliases answer by spelling compare, an alias binding
       by get_binding_sym, everything else is the symbol's own
       spelling -- no hash on any path. The param loops of
       infer_func_sig_expr / infer_func_def_expr use it, and rebuild a
       param's Type only when an alias was actually followed.
     - type_carries_borrow gained type_carries_borrow_t(scope, t): a
       primitive or tag-only type never reaches the memo, a named one
       resolves its alias by symbol; the memo stays keyed by the
       resolved spelling (one Set(Str) probe, was three hashes).
     - constfolder_type_is_aggregate, fieldaccess_field_decl,
       field_assign_declared_type_name and the field-access /
       field-assign def lookups key on the stamp's symbol.
     - raw_widen_numeric takes the target TYPE instead of its
       spelling: named targets resolve by symbol, primitive ones never
       touch the binding registry (the name form hashed "I64" on every
       scalar widen).
     - type_from_name / type_from_name_init_name hash ONCE (they
       hashed two or three times); type_from_sym_init returns the
       twins and builtin_type_from_name_sym lets Str/StructDef/EnumDef
       take the symbol they were asked about.

   Measured on the pre-#326 master (8225629, --usize=32 build,
   translate --force-rebuild test/first_class.til): 7,127,947,052 ->
   6,894,811,944 instructions, -3.27%; SymbolPool.lookup 604,102 ->
   350,405 calls, fnv1a 944,646 -> 712,418, get_binding_name 207,007
   -> 104,772, get_struct 167,997 -> 76,840, Str.clone 1,498,436 ->
   1,335,969. The work was then ported onto 79a8304's reader
   preparation (same flips and harvest, his spellings: type_name_ref
   returning "" for no-name, decl_type_name, type_from_sym_init); the
   port is verified by the suite, not re-measured -- the numbers
   above stay the old-master figures until the next probe.

   What still hashes (350K lookups), from the raw callgrind `calls=`
   records: lookup_func_symbol_name 66K (find_callee_fdef's SYNTHESIZED
   `<type>_delete` names -- no Type holds those); get_binding_name
   105K on Str FIELDS (FuncSig.return_type in infer_func_def_expr and
   fdef_return_carries_borrow, generic_expected_arm's declared name,
   reregister_scope_defs and finish_hoist_temp on Declaration NAMES);
   get_struct 77K (c_codegen's find_struct_def on owned spellings, the
   interpreter's static_ns_func_def on dyn_call strings,
   fdef_return_carries_borrow again); sym_of ~8-17K for the three
   registered builtins reached by NAME; sym_or_zero ~5-10K for core's
   Str-form constants meeting type_sym. Moving the field-based ones
   needs FuncSig.return_type / TypeBinding.alias_target /
   Declaration.name to become symbols -- a different migration from
   "a Type carries its Sym". The 4,596M pre-interning figure is no
   longer a comparable baseline: the compiler is built --usize=32 now
   and carries the whole #344 borrow-tracking arc.

   Three traps for whoever measures next: callgrind_annotate's caller
   tree is NOT trustworthy on this -O0 binary (it showed Expr_delete
   calling SymbolPool.intern); the raw out-file's `fn=` / `cfn=` /
   `calls=N` records are exact. A reader written as "rebuild the
   Str form and recurse so the Str arm handles it" (the constfolder's
   raw_to_expr had two) becomes a twin recursing on itself the moment
   the producer flips -- a stack overflow, not a type error. And a
   Sym twin arm written as a COPY of its Str arm drifts: the port
   found heap_move_ptr_into_slot's StructSym copy without the Str
   arm's foreign-place branch (assigning a struct to an ext_global
   memcpy'd over the library's storage; the consumer test caught it),
   and elem_size_for_type with no EnumSym arm at all, so dyn_size_of
   on a one-byte enum fell to the `case:` default and answered the
   dispatch word (8). Neither is a compile error: the default arm
   absorbs the twin. Every such arm must do the work ONCE under
   `case .Struct, .StructSym:` with type_name_ref, never as two
   bodies kept in step by hand.

4. was retirement; superseded -- see step 3d above and the runtime-form
   note in step 4's original text below.
   The interpreter's layout tables pick up the new variants' sizes in
   the same commits.

   PREREQUISITE, learned by starting it: a producer flip is only safe
   once every reader that can see that variant handles both forms.
   Most Type switches carry a `case:` default (Declaration.type_name's
   `case: return ""` is the archetype), so a flip under a stale reader
   is not a compile error -- it is a silently wrong empty name. Four
   reader families stand between here and the flip, sized by call
   count and by the call SITES that must gain a SymbolPool:

     til_type_name      70,452 calls   ~60 sites   DONE (below)
     type_to_name       37,003 calls    65 sites
     Declaration.type_name 175,352      214 sites
     expr_type_name_ref 365,152 calls  118 sites

   The first is converted: src/self no longer calls core's cloning
   til_type_name except through type_to_name. context.til gained
   type_name_ref(t, symbols), the borrowing drop-in -- same answer,
   "" for a variant carrying no name, but the payload is borrowed and
   the Sym twins are read. Its argument must be a STABLE location (a
   field, a local, an x.til_type() stamp ref): the returned ref points
   into the Type's payload or the pool's names vector, so a Type that
   is itself a call result would dangle. That is the same hazard the
   comment on expr_type_name_ref already records.

   Measured cost of that conversion alone: 6,494,934,014 ->
   6,492,895,722, -0.031%. It is PREPARATION, not a win, and the
   prediction that it would save ~0.8% was wrong: only 13,701 of the
   33,449 converted calls actually dropped a malloc, because most
   sites still hand the name to something that owns it (a Set, a
   Map value, a returned Str). Do not expect the other three families
   to pay for themselves either -- they are the price of the flip.

4. Retirement: NOT POSSIBLE as originally written, and the plan was
   wrong to include it. The Str variants are the RUNTIME form and must
   stay forever. src/core/dyn.til is the introspection API -- til_type_name,
   type_storage_kind, struct_def_of, enum_def_of, func_sig_of -- and it
   reads a Type inside USER programs at run time, where no SymbolPool
   exists (SymbolPool is a compile-time structure in src/self/parser.til,
   and src/core cannot import src/self).

   So the two forms are not "old and new": they are compile-time and
   runtime. The compiler holds Sym forms internally; make_til_type_expr
   is the boundary that materialises a user-visible Type, and it already
   takes `mut symbols`, so it resolves back to the Str form there. Step 1
   left its four twin arms without payloads (variant_name only) -- that
   is the landmine step 3 must clear in the same commit as the flip, or
   reflection starts reporting Type.Struct with no name.

5. Measure at every step against the standing baseline (4,596M
   instructions at 9263b9c8, before the interning regression). Note
   for anyone re-running the numbers: since #170 landed, `translate`
   CACHES its output, and a warm cache turns the benchmark into a
   lex-and-exit that measures 177M instead of ~6,350M while printing
   the same "Generated:" lines. Always pass --force-rebuild.
   Step 2 removed 45K of get_struct's hashes (the ones whose caller
   held an Ident); step 3 is where the rest of get_struct and most
   of get_binding_name go. The success
   criterion is not "faster than yesterday" but BELOW THE PRE-INTERNING
   BASELINE, since that is what finishing the migration is for.

   OPEN QUESTION on whether this issue can reach that criterion. The
   self-cost profile at f1025673 (translate --force-rebuild
   test/first_class.til, 6,494,934,014 Ir):

     Str_cmp                    4.32%
     fnv1a                      4.16%
     Map__U32_TypeBinding_get   4.16%
     Map__U32_Dynamic_get       3.86%
     Str_eq                     3.42%

   Answered: TypeScope's three registries moved from the sorted-Vec

*** Risks

  - Forgotten resolve() at a text edge: symbol number in a diagnostic
    or, worse, in MANGLED C names. The corpus eqcheck catches the
    C-name case byte-for-byte; goldens and typer_errors.til catch
    diagnostics.
  - The Sym is Context-local: a Type value must never cross Contexts
    (REPL cached base vs deltas is the place to look; SymbolPool
    clone semantics already note "a cloned Context starts with a
    FRESH interner").
  - Map(Sym,...) iteration order is intern order, not alphabetical:
    anywhere a walk over a Type-keyed or name-keyed structure feeds
    OUTPUT, determinism must be re-checked (the #292 conversions are
    the precedent that this is manageable).
