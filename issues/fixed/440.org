** FIXED #440 Used private function-generator macros are reported as unused

*** Post-mortem

Generator expansion removed the factory call before ordinary usage checks,
and local private factories had not yet been registered or name-mangled.
Their actual compile-time uses therefore never reached the private binding's
used flag.

The preparation records successful expansion on the original Declaration.used
and preserves that flag in TypeBinding.used during registration. Imported
factories and retained generic type-dependency expansions record uses too;
mere lookups and unexpanded template bodies do not. The final migration now
marks core's ~make_usize_to_uptr~ private, removing the public workaround.

Regression tests: ~test_private_macro_generators~ in test/priv.til,
test/imports/priv_helper.til, the unused-generator case in
test/priv_unused_error.til, and the private size factory in
test/dynamic_widths.til. They cover used and genuinely unused private
generators, retained private FuncSig dependencies, ordinary private macros,
and imported/public generators. The core migration also exercises the fix
while bootstrapping the build driver and compiler.

Final verification on master ~beedf8556~: ~make clean && make test~ passed
458/458, including bootstrap, ASAN, the private/unused-generator regressions
and the issue-summary check.

*** Preparation history

Root cause: generator expansion runs before local private declarations are
registered or file-name-mangled. It replaces the call with a generated
definition, so the typer never sees the factory reference. Marking a binding
during lookup would be too early (and private factories have no binding yet).

Successful expansion now marks the original local Declaration.used; function
registration carries that flag into TypeBinding.used. Imported factories
already have bindings and are marked there. Retained generic type-dependency
expansion records the same use. Lookups and unexpanded template bodies do
not count; an actual expansion is a compile-time use. The existing local
macro map distinguishes local declarations from imports without a new cache.

Regression coverage: ~test_private_macro_generators~ in test/priv.til covers
a value-parameter factory, a type-parameter factory, a retained private
FuncSig generator, an ordinary private scalar macro, and imported generated
functions/public generators via test/imports/priv_helper.til. The existing
test/priv_unused_error.til checks an unexpanded private generator is still
rejected. test/dynamic_widths.til's size-based factory is now private,
exercising this shape across its existing target/width matrix.

~make clean && make test~ passed 456/456. The fresh ~bin/til~ also built
make.til with the core factory temporarily marked private. The core qualifier
must land after this preparation: HEAD's old til_boot still fails while
building bin/make with the same change:

#+begin_example
./src/core/numbers.til:877:6: error: unused priv func 'make_usize_to_uptr'; remove 'priv' to expose it
#+end_example

This required the staged source-level migration in doc/self.org: pass 1
rejected the consumer before it could build the new compiler. Core remained
public in the preparation; the final private qualifier followed its merge.

*** Original report

A ~priv~ macro returning ~FuncDef~ can be called to generate a function and
still be rejected as an unused private function. This was encountered while
implementing the compile-time specialization of ~usize_to_uptr~ for #400.

*** Observed reproducer

In src/core/numbers.til, change the existing factory declaration to:

#+begin_src til
priv make_usize_to_uptr := macro(SizeType: Type, PointerType: Type) returns FuncDef {
    // existing body unchanged
}
#+end_src

Its existing use remains:

#+begin_src til
usize_to_uptr := make_usize_to_uptr(USize, UPtr)
#+end_src

The bootstrap build (~bin/til_boot build -o bin/make make.til~) reported:

#+begin_example
./src/core/numbers.til:872:6: error: unused priv func 'make_usize_to_uptr'; remove 'priv' to expose it
#+end_example

The factory really is used at compile time. Requiring it to be public is
not an appropriate way to silence this diagnostic.

*** Investigation and fix direction

Function-generator calls are expanded during initialization, before the
ordinary function-body usage checks. Inspect ~init_expand_type_gen_decl~,
~init_lookup_type_gen_macro~, and the private-function usage accounting:
the expanded-away call must still count as a use of its macro declaration.
The exact missing bookkeeping edge has not yet been isolated.

Preserve private visibility and unused diagnostics for genuinely unused
factories. Also check imported/public generators and ordinary macros, but
do not assume that every macro form has this bug.

*** Workaround and regression coverage

~make_usize_to_uptr~ is currently non-~priv~ and works. Once fixed, make
that factory private again.

Add a focused regression where a private generator returns a function,
the generated function is called, and both interpretation and compilation
succeed. Include an unused private generator that must still be rejected.
Exercise the core factory through bootstrap as well as user-file expansion.
