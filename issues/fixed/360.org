** FIXED #360 An owned intermediate drops borrow provenance; the backends diverge again

*** Post-mortem

Root cause, two independent halves that only diverged together:

1. summary_walk's Decl arm forwarded roots for a ~ref~ local only, so a
   function parking a borrow in an OWNED local and returning it
   summarised as reaching nothing. Nothing credited the write, so
   nothing rejected it either.
2. fdef_return_carries_borrow -- the gate that keeps auto-shallow (#223)
   from value-copying a parameter whose borrow can escape -- did not
   count a returned STRUCT carrying a ref field. So the parameter WAS
   copied, and the returned borrow pointed into the copy: the write
   reached the caller's storage interpreted and a dead copy compiled.

Half 1 alone would have made the write visible without making the
accepted program correct; half 2 alone would have fixed the divergence
while still accepting a write through a read-only borrow.

Fixed across a master merge, the #344 ladder: the preparation commit
taught the tracking (owned locals forward the CARRYING relations -- a
copy cannot reach the source's storage, but holds the same pointers) and
widened the auto-shallow gate, crediting the write but skipping the
rejection behind a provisional marker. This commit removes the marker
and its two fields, so the write is rejected against the storage it
reaches.

The sweep the plan anticipated turned out to be empty. That is a result
of the preparation's own decision to SKIP typer-emitted temps rather
than forward through them: forwarding grew summaries past what the
expressions themselves say and would have flagged 7 src/self sites that
no write actually requires. Skipping keeps the summaries honest, and
src/self needed no qualifier changes at all.

Trap worth keeping: returns are hoisted into owned temps AFTER typing,
so treating temps as user intermediates marks every summary provisional
and silently disables the whole check. Two existing #344/#354 negative
cases going quiet is what caught it -- the reason those cases earn their
place in the suite.

Regression tests: test/ref.til's
test_borrow_root_through_owned_intermediate (honest form, both backends
agree the caller's storage changed twice) landed with the preparation;
test/typer_errors.til's terr360_poke (the non-mut form rejected, naming
s; count 210 -> 211) lands here.


~summary_walk~'s Decl arm forwards roots only for a ~ref~ local. An
OWNED local of a borrow-carrying type, built by a call, drops them -- so
a function that parks a borrow in a local and returns it summarises as
reaching nothing, and the write it hands back is neither credited nor
rejected:

#+begin_src til
Holder := struct { ref r : Inner }
a_of := func(s: Src) returns ref Inner { return s.a }

mk := func(s: Src) returns Holder {
    h := Holder(r = a_of(s))     // owned intermediate: roots dropped here
    return h
}
poke := func(s: Src) {           // accepted, no `mut s` demanded
    h2 := mk(s)
    h2.r.n = h2.r.n + 1
}
#+end_src

Verified on merged master: ACCEPTED, and interpreted prints ~2~ while
compiled prints ~0~. That is #344's own signature -- a write through a
read-only borrow that the two backends disagree about -- still reachable
through one owned local.

This is NOT the conservative direction. Under-crediting here means
ACCEPTING a laundered write, which is unsoundness; the arc's other
limits (unknown field paths, unresolved callees) merely demand a ~mut~
that is not needed.

*** Why it was left out of #354

#354's first cut propagated these roots and surfaced 11 genuine
rejections in src/self -- writes through ~scope.get_struct~ results --
that the then-current boot could not credit. Landing them needs the
#344 ladder: a preparation commit whose tracking becomes the boot, then
a use commit that turns on the rejection and sweeps. #354 was a
single-commit fix, so the arm was cut and recorded rather than half-done.

*** Plan

**** A. Preparation: owned intermediates forward what they carry

Forward roots from an owned Decl of a borrow-carrying type whose RHS is
a call, keeping only the CARRYING relations (into / carried) -- a copy
of a value cannot reach the source's own storage, only what the source
points at. Credit the resulting writes; do not reject on them yet, the
same seam #351 used. Positive regression proving both backends agree on
the honest ~mut~ form.

**** B. Use: reject, sweep, close

Remove the seam, sweep what it flags (the src/self scope.get_struct
sites and whatever else appears), add the probe above as a negative
case, close the issue.
