** FIXED #328 Infer omitted generic type arguments from value arguments

*** Post-mortem

   Root cause: a direct generic's type arguments were resolved in ONE
   place -- init, syntactically, from the call's leading arguments -- and
   init cannot type a value expression. Anything omitted therefore had to
   stay omitted forever, so ~assert_eq(I64, got, 42)~ repeated a type
   that both operands already carried. Worse, init accepted ANY Ident in
   a ~Type~ slot, so ~assert_eq(got, 42)~ was not merely unsupported: it
   was silently monomorphized into ~assert_eq__got~.

   What changed:

   - ~type_binding_is_type_token~ and ~init_func_is_generic~ moved to
     ~src/self/context.til~ so init, desugarer and typer classify a
     ~Type~-slot argument and a generic source by ONE rule. The
     predicate now tests a bodyless FuncDef (a FuncSig type name) BEFORE
     ~is_builtin~, because ext_func declarations (~vec~, ~array~,
     ~cast~) are builtins too and reading one as a type token turned a
     local named ~vec~ into a bogus type application.
   - Init keeps a same-unit source-name -> canonical-name map for the
     type declarations scope does not know yet (this unit's private
     structs, enums and FuncSigs, plus ~Alias := Ident~ decls resolved to
     a fixed point). A call whose first present ~Type~ slot holds a value
     survives init untouched.
   - ~generic_instantiate~ (initer.til) is the single concrete-
     instantiation path: it canonicalizes every type-argument spelling,
     drops the ~Type~ params while moving ~variadic_index~ /
     ~kwargs_index~ with them, copies source privacy, and keys cross-unit
     dedup by declaring path plus concrete name. Init's explicit
     expansion and the typer's inferred expansion both build their
     declaration there, so the two cannot drift.
   - Generic SOURCE declarations are retained through lazy expansion,
     throw preparation and body typing, skipped by every pass that would
     type or emit an unresolved ~T~ body, and retired (AST plus scope
     entries) in ~type_program_errors~ after an invariant scan proves no
     call is still bound to one.
   - ~infer_fcall_expr~ routes a callee still bound to a source through
     ~infer_generic_fcall~: it desugars the call ONCE against a
     value-only clone of the signature (so positional/named/default/
     variadic handling and the caller's ~__LOC__~ stay in the one
     existing matcher), collects evidence from the formals that ARE a
     type parameter, instantiates, queues the declaration, and continues
     down the ordinary concrete path.
   - Evidence rules: a typed non-literal operand is hard evidence and
     several must denote the same concrete type (exact primitive /
     aggregate-name / named-FuncSig equality only -- no interface
     conformance, no USize coercion, no wildcard funcptr match, no
     widening). Numeric literals are soft: they narrow against hard
     evidence through the ordinary ~validate_fcall_arg~, and with
     literals only pick I64, or F32 when any is fractional/exponent form.
     Dynamic, Unknown and null establish nothing.

   Three defects outside the feature surfaced and were fixed at the
   source rather than worked around:

   - ~Expr.take_children~ freed and nulled the source buffer but left
     ~cap~ behind, so a REUSED holder pushed straight into NULL.
   - ~init_substitute_idents~ never descended into a NESTED definition's
     own FunctionDef payload, so a local ~f := func(x: T)~ inside a
     generic body kept ~T~ in its signature after substitution.
   - A late concrete declaration is typed after the caller that queued
     it, so its return ownership is normalized (#223 auto-shallow) at
     queue time, and it registers against ~ctx.scope~ rather than the
     caller's body scope -- otherwise the garbager recorded a HeapBox for
     a call result the builder emitted as a stack shallow return (#302).

   Task 5's approval gate turned out not to be needed: the name-forming
   spelling of a call result is already preserved on
   ~FunctionDef.return_type~, because ~infer_func_def_expr~ leaves
   USize/UPtr alone when the two widths differ and a user alias
   canonicalizes to the same primitive ~resolve_type_alias_for_name~
   would pick. No new public AST field was added; ~TypeBinding~ gained
   the compiler-internal ~declared_type_name~ instead.

   Regression tests: ~test_generic_func_type_tokens~,
   ~test_generic_func_canonical_name~,
   ~test_generic_func_type_param_layout~,
   ~test_generic_infer_hard_evidence~, ~test_generic_infer_declared_name~,
   ~test_generic_infer_literals~, ~test_generic_infer_call_shapes~,
   ~test_generic_infer_ownership~ and ~test_generic_infer_lambda~ in
   ~test/first_class.til~; ~test_generic_infer_lazy_inline~ and
   ~test_generic_infer_lazy_thunk~ in ~test/lazy.til~;
   ~test_generic_infer_static_throw~ in ~test/errors.til~;
   ~test_generic_infer_cross_unit_dedup~ and
   ~test_generic_infer_private_isolation~ in
   ~test/generic_infer_imports.til~; and the return-only, local-struct,
   nested-return-only, Dynamic-only, conflicting-operand,
   out-of-range-literal, missing/extra-own, ref-on-value and
   dependent-throw cases in ~test/typer_errors.til~.

   Follow-up commits after the feature merge (both on master):

   - A thrown PARAMETER's type is resolved through the
     ~ctx.lowering_param_types~ map the typer seeds before throw
     lowering, and the prior-declaration scan starts at the last index
     instead of ~len()~ (an empty body no longer crashes the compiler on
     ~if fail { throw e }~). Together these make ~throws T~ generics work
     under EXPLICIT type application; omitted inference of one is still
     refused, since the caller's error slots are built before inference
     could resolve T. Tests: ~test_throw_param_first_stmt_of_nested_body~,
     ~test_throw_param_in_tail_position~ and
     ~test_generic_dependent_throw_explicit~ in ~test/errors.til~.
   - NESTED type arguments are deduced. ~init_func_is_generic~ matches a
     type parameter as a whole name SEGMENT of a generated instance name
     (the parser mangles ~v: Vec(T)~ to ~Vec__T~ before expansion), which
     also fixed the explicit form -- such a function was previously not a
     template at all. Inference lines the formal's spelling up against
     the operand's (~Vec__T~ vs ~Vec__I64~; ~Map__K_V~ binds K and V from
     their own segments), declining on any mismatch in base, argument
     count, ~ref_~ segments, or agreement. No late type synthesis is
     involved: the instance exists because the caller is holding one.
     Test: ~test_generic_infer_nested_type_args~ in
     ~test/first_class.til~. A parameter appearing ONLY in the return
     type still has nothing to line up against and keeps the explicit
     requirement (~g328_nested_return_only~ in ~test/typer_errors.til~).

   Known limitation, unchanged: an inferred-only call to a generic with a
   ~..T~ variadic needs the concrete ~Array__T~ instance, which only
   init's type-gen pass creates -- unlike a ~Vec(T)~ operand, the caller
   holds no ~Array__T~ value to read the name off -- so it asks for
   explicit type application when no explicit call in the program has
   created the instance.


   Core's ~assert_eq~ is a direct generic:

   #+begin_src til
   assert_eq := func(T: Type, a: T, b: T, loc: Str = __LOC__) { ... }
   #+end_src

   Every call therefore repeats a type already present in ~a~ and ~b~:

   #+begin_src til
   assert_eq(I64, got, 42)
   assert_eq(Str, got_name, "til")
   #+end_src

   The common form should infer the generic argument:

   #+begin_src til
   assert_eq(got, 42)
   assert_eq(got_name, "til")
   assert_eq(got, 42, loc = caller_loc)
   #+end_src

   Keep explicit type application for ambiguous or intentionally constrained
   calls. This is not just ~assert_eq~ sugar: it is the generic-argument
   inference deliberately left as a future issue by [[../fixed/58.org][#58]]. For example,
   ~gid := func(T: Type, v: T) returns T~ should be callable as ~gid(7)~ as
   well as ~gid(I64, 7)~.

*** Existing language pieces

   ~test/first_class.til~ exercises both current generic forms:

   - Direct generics put every type argument inline: ~gid(I64, 42)~.
   - Angle generics are macro-backed and curried: ~gid_angle(I64)(7)~.
   - Macros still declare explicit parameter types and have no operation that
     returns the static type of an arbitrary argument expression.

   The collection implementations provide useful boundaries:

   - ~Vec(T)~ and ~Map(K, V)~ carry their static type arguments in the
     instantiated receiver. Calls such as ~v.push(own x)~ and ~m.set(k,
     own v)~ consequently do not repeat them.
   - ~DynVec.new(T)~ and ~DynMap.new(K, V)~ take runtime ~Type~ values, turn
     them into names/sizes/method pointers, and store that metadata. Their
     ~Dynamic~ operations erase the source value's static type, so they are
     not a precedent for compile-time deduction.
   - The variadic ~vec(T, elements: ..Dynamic)~ also requires an explicit
     type today; inferring homogeneous collection literals could build on the
     same facility later, but is not required to fix ~assert_eq~.

   Ordinary optional arguments do not provide inference. A default is a
   concrete expression filled after call matching; ~loc = __LOC__~ works
   because it has a fixed ~Str~ value. There is no meaningful expression for
   ~T: Type = ...~ that denotes "the static type inferred from a later
   argument".

**** Current phase order

   ~type_program_errors~ currently reaches the relevant phases in this order:

   1. ~init_file~ seeds declarations and calls ~init_declarations_unit~.
   2. ~init_expand_generic_funcs~ expands explicit calls, recursively expands
      generic calls in concrete bodies, appends concrete declarations, and
      removes every generic source declaration. ~init_declarations_unit~ then
      runs ~init_lift_in_body~, private renaming, and final registration.
   3. Global initialization, alias retargeting, and binding normalization run.
   4. Lazy calls and thunks are expanded.
   5. ~extend_throwing_func_sigs~ extends/registers definitions. Later,
      ~process_throw_catch_in_func_body~ calls
      ~validate_one_fcall_consolidated~ and
      ~inject_err_args_on_one_fcall_consolidated~ to rewrite call sites before
      ordinary expression inference.
   6. ~type_check_unit~ lifts lambdas, repeats idempotent throw extension, then
      ~infer_body_unit~ classifies and types top-level declarations.
   7. Unused-private checks run, then ~type_file(mode_file, ...)~ types the mode
      file, scopes are refreshed, and only then do the builder/interpreter
      consume the concrete AST.

   The required order is therefore: retain prepared generic sources through
   lazy/throw preparation; skip their unresolved bodies; infer a call while
   typing its caller; queue a concrete declaration; flush it only after the
   current top-level statement returns; lift, throw-extend, classify, append,
   register, and type that declaration; then retire all generic sources before
   builder/interpreter preparation.

**** Important traps

   1. Init currently accepts any Ident in a ~Type~ slot. Thus
      ~assert_eq(got, 42)~ is misread as an explicit ~assert_eq__got~ call.
      Explicit-call recognition must use ~type_binding_is_type_token~ plus a
      same-unit fixed-point source-name -> canonical-name map for private
      types/aliases not registered yet before omitted calls can survive to the
      typer.
   2. Current monomorph names append raw argument identifiers. They do not use
      ~init_type_arg_name~, so alias canonicalization must be made common to
      both explicit and inferred application.
   3. Operand types are not authoritative until ~infer_fcall_expr~. Locals,
      calls, fields, numeric literals, and FuncSig values need the live
      function/body ~TypeScope~; do not duplicate expression typing in init.
   4. ~desugar_fcall_args_for_fdef~ owns positional/named/default/variadic
      alignment and call-site ~__LOC__~. Inference must reuse it with a
      value-only signature, not implement a second argument matcher.
   5. ~infer_fcall_expr~ rejects all remaining ~ref~ argument bits before it
      resolves the callee. Delay that rejection for Ident callees until the
      generic path has had a chance to consume explicit ~ref Type~ arguments.
   6. Throw call-site lowering precedes ~infer_fcall_expr~. Static throw types
      can use metadata registered for the retained generic source, but an
      omitted call to ~throws T~ cannot be safely inferred in the first slice.
      Detect it before throw output injection, defer that call to the typer,
      and require explicit type application there. Also recursively expand
      explicit generic calls in a late concrete body before that body reaches
      throw lowering.
   7. ~Context.generic_funcs~ contains seed-time clones made before private
      mangling, lazy expansion, and throw extension. Late inference must clone
      the live source from ~TypeScope.lookup_func~, never that stale clone.
   8. ~Context.generic_func_synths~ is keyed only by monomorphized name.
      Include declaring path/source identity so two same-named private
      generics cannot deduplicate to the wrong body.
   9. AST-backed FuncDef scope entries are raw pointers. Pending storage is
      stable only until its declaration is moved into the unit. Register the
      pushed node again and call ~init_refresh_seeded_scope_defs~ after append.
   10. Late declarations miss ~infer_body_unit~'s initial classification pass.
       Run ~constfolder_classify_stmt~ on every pending declaration before it
       enters the dynamic body loop.
   11. Removing ~Type~ parameters changes ~variadic_index~, ~kwargs_index~,
       and ownership bitmap positions. Adjust/remap all three explicitly.
   12. ~TypeBinding~ alone cannot preserve every declared spelling:
       ~infer_func_def_expr~ and ~infer_func_sig_expr~ normalize return aliases,
       while struct field ~Declaration.explicit_type~ remains available. A
       complete provenance task needs both binding provenance and retained
       source return-type spelling.
   13. Final retirement must erase generic entries from both
       ~TypeScope.func_defs~ and ~TypeScope.bindings~ before removing AST
       declarations. Refreshing pointers does not erase obsolete entries.
   14. Retained private templates did not previously reach
       ~init_lift_in_body~ or unused-private checks. Track template use or
       exempt template sources deliberately so retention does not lift
       unresolved nested definitions or create false diagnostics.

   These constraints rule out a default-argument tweak. The implementation
   needs typer-directed inference plus safe late monomorphization.

*** Recommended design

**** Keep generic sources until calls are typed

   Split today's init operation into "expand explicit calls" and "retire
   generic sources":

   - Continue expanding calls whose present ~Type~-parameter slots contain
     bindings accepted by ~type_binding_is_type_token~ or names in a same-unit
     fixed-point canonical type-name map built before the generic walk. A call
     that starts with a real type token remains explicit even when a later
     value argument is missing; normal call validation must report that missing
     value.
   - Do not mistake a value Ident for a type token. An explicit candidate is
     valid only when every present ~Type~ slot is a type binding accepted by
     the shared predicate. A ~ref~ bit may qualify that accepted type token; it
     must never make an arbitrary value Ident count as a type token.
   - Keep each source generic declaration in its unit AST through lazy-call
     expansion, throw processing, all ordinary and mode-file body sweeps, and
     unused checks. Teach the normal FuncDef body walk and initial lambda-lift
     walk to skip these unresolved template bodies, just as they already skip
     template macros. Task 11 extends static-throw sources while permanently
     excluding type-dependent throw sources from unresolved extension.
   - Record generic source identity separately from a normal concrete FuncDef
     binding, including the declaring path, so local/private and imported
     generics cannot be confused by name alone.
   - Remove the generic source declarations only after ordinary body typing,
     unused-private checks, and ~type_file(mode_file, ...)~ have completed.
     Before removal, verify that no call to a generic source remains. Erase
     their ~TypeScope.func_defs~ and ~TypeScope.bindings~ entries, remove their
     AST declarations, and refresh all surviving AST-backed definition
     pointers.

   Keeping the source alive is important: an inferred monomorphization then
   clones the live lazy-prepared body (and, for static throws after Task 11,
   its extended signature), not the stale seed-time copy currently stored in
   ~ctx.generic_funcs~. Type-dependent throw sources are deliberately not
   extended while unresolved.

**** Resolve a generic call in the typer

   Restructure ~infer_fcall_expr~ so Ident callees resolve before the blanket
   rejection of leftover ~ref~ argument bits, then run the generic-call check
   before normal FuncDef argument desugaring. Preserve the current early error
   for field/non-Ident calls. The generic path handles two shapes:

   - A late explicit call that survived in a prepared generic source body.
     Also run the existing recursive explicit expansion on a newly cloned
     concrete body before queueing it, so explicit dependent-throw calls are
     concrete before throw call-site lowering.
   - An omitted-type call such as ~assert_eq(got, 42)~ or ~gid(7)~.

   For an omitted-type candidate, clone the generic FunctionDef metadata and
   remove its ~Type~-typed parameters, adjusting ~variadic_index~ and
   ~kwargs_index~. Use that value-only signature with the existing
   ~desugar_fcall_args_for_fdef~ so positional/named/default handling stays in
   one implementation. In particular, ~loc = __LOC__~ is materialized here
   from ~ctx.path~ plus the original call's line/column.

   Infer every value argument through ordinary ~infer_expr~, then collect
   constraints from formal parameter types. The first implementation should
   infer a type parameter from direct occurrences (~a: T~, ~own a: T~,
   ~xs: ..T~). A parameter seen only inside a generated name such as
   ~Vec__T~ / ~Map__K_V~ does not guess: report that it cannot yet infer the
   nested type argument and ask for the existing explicit spelling. Structural
   decomposition of template instance names can be added later without
   blocking ~assert_eq~ or ~gid~.

**** Unification rules

   Keep inference deterministic and no more permissive than existing calls:

   - ~Dynamic~, ~Unknown~, and ~null~ do not establish a type argument. After
     another operand establishes it, leave their final treatment to ordinary
     call validation; do not claim a stronger check than current Dynamic
     semantics provide.
   - A typed non-literal operand is hard evidence. Multiple hard evidence
     sites for one type parameter must denote the same concrete type. Use exact
     primitive equality, aggregate-name equality, and exact named FuncSig
     identity. Do not copy permissive call compatibility such as interface
     conformance, ~USize~ coercion, or wildcard ~funcptr_eq~, and do not add
     integer widening (issue #224 already forbids it).
   - Numeric literals are soft evidence. If another operand fixes ~T~, validate
     and narrow the literal against that type with ~validate_fcall_arg~. With
     literals only, infer ~F32~ if any literal is fractional/exponent form,
     otherwise the normal ~I64~ default.
   - ~Str~ and ~Bool~ literals are fixed evidence.
   - If no evidence fixes a parameter, emit
     ~cannot infer type argument 'T' for 'name'; pass it explicitly~. A type
     parameter used only by the return type (~gdefault(T) returns T~) therefore
     remains explicit; expected-result-type inference is a separate feature.
   - Inference does not invent a ~ref~-qualified type argument. Calls that need
     the #320 ownership-changing form continue to say ~ref Type~ explicitly.
     Ordinary ~own~/~mut~/~ref~ value-parameter behavior is preserved by
     validating the rewritten call against the concrete FunctionDef.

   Build both a concrete ~Type~ (for equality and validation) and its
   name-forming spelling (for substitution and the ~name__T~ key). Add one
   helper that obtains the best declared type name from an expression:

   - Named aggregate/enum/FuncSig types come from the Expr's Type payload.
   - Function calls and fields can recover the declared return/field type from
     their resolved FunctionDef/Declaration.
   - Ident bindings need declared-type provenance for width aliases. Add a
     name field to ~TypeBinding~ and populate it when parameters and
     typed/inferred declarations are bound.
   - Calls need the source-declared return spelling because
     ~infer_func_def_expr~ and ~infer_func_sig_expr~ normalize return aliases.
     Add a source return-type spelling to ~FunctionDef~ and substitute it with
     the rest of the signature. This new public AST field is an approval gate:
     do not implement that task until the user explicitly accepts the field.
   - Fall back to ~type_to_name~ for literals and expressions with no retained
     alias spelling, then pass the result through
     ~resolve_type_alias_for_name~. This preserves the existing rule that user
     aliases canonicalize while ~USize~/~UPtr~ remain target-independent names.

   Type equality, not spelling, decides whether evidence conflicts. If two
   equal-width aliases provide different valid spellings, choose the first
   non-literal declared spelling deterministically; a literal never overrides
   it.

**** Reuse monomorphization, do not reimplement it

   Introduce a shared ~GenericFuncSource~ record in ~src/self/context.til~
   containing the borrowed FuncDef cell, declaring path, source name, and
   privacy. Also expose ~init_func_is_generic~ through that shared layer so
   initer, desugarer, and typer use one source-classification rule. Local
   sources get their path from ~ctx.path~; imported sources get it from the
   resolved ~TypeBinding.path~ rather than from ~Context.generic_funcs~.
   Extract the substitution/name/clone portion of
   ~init_generic_expand_call~ into a shared
   constructor that accepts this source record, an ordered map of
   type-parameter names to concrete type-token Exprs, the existing
   ~ref_params~ set, and the destination Body (init's ~synthesized~ holder or
   the typer's pending holder).

   The constructor receives a resolved source and never reads
   ~Context.generic_funcs~ itself. Give recursive expansion two thin source
   resolvers: init resolves through its local/import seed map; late typing
   resolves only live retained definitions through ~TypeScope.lookup_func~ and
   the corresponding binding path.

   Keep call rewriting separate: return the concrete name plus an old-to-new
   argument-position map from the constructor, then let a call-site helper
   rewrite ~FCallData~ and its children. Both init-time explicit expansion and
   typer-time inferred expansion must use these helpers for:

   - alias-normalized monomorphization names;
   - dropping ~Type~ parameters from the concrete FunctionDef;
   - adjusting ~variadic_index~ and ~kwargs_index~ after removals;
   - remapping call ~own_args~ and consumed ~ref~ bits through the returned
     argument-position map;
   - ~init_substitute_type_params~ over signatures, defaults, throws, and body;
   - ownership/ref substitutions;
   - source-path-aware ~ctx.generic_func_synths~ cross-unit deduplication;
   - source privacy/path handling for concrete declarations;
   - recursive explicit-call expansion exactly once in each concrete body,
     with nested concrete declarations written to the same destination Body.

   During init, a private concrete declaration keeps ~is_priv~ and its raw
   source name so the existing private-renaming pass mangles it once. During
   late inference, start from the already-resolved/mangled source name and do
   not run private mangling a second time.

   This guarantees that ~assert_eq(I32, a, b)~ and ~assert_eq(a, b)~ select the
   same concrete declaration whenever they infer the same name-forming type.

**** Queue and type concrete declarations safely

   Give ~Context~ a per-unit pending holder of synthesized generic Decl Exprs.
   A Decl wrapper owns its FuncDef child, so expose and call the existing
   ~register_function_def_for_stmt~ while that child is in stable pending AST
   storage; this creates both the full binding metadata and ~func_defs~ entry.
   After rewriting the call's callee to ~name__T~, let the existing concrete
   call path perform argument/default validation, ownership checks, return-type
   resolution, proc restrictions, import-use tracking, and backend-visible type
   stamping from the registered concrete FunctionDef.

   Flush pending declarations only after ~infer_body_stmt~ returns to the
   top-level unit loop, where no refs into the current statement remain:

   1. Run lambda lifting on the concrete pending bodies, using a unit/context
      counter rather than restarting at ~_lambda_0~.
   2. Extend/register static throw metadata for each concrete declaration.
   3. Run ~constfolder_classify_stmt~ for every pending declaration.
   4. Record the destination unit's starting child index, then call
      ~destination.take_children(pending)~ once; it appends every child and
      empties pending. The old pending registrations become invalid at that
      move.
   5. Re-run ~register_function_def_for_stmt~ on each appended AST node by
      destination index, then
      call ~init_refresh_seeded_scope_defs~ after the batch.
   6. Let ~infer_body_unit~'s existing dynamic-length loop type the appended
      functions. Any inferred generic calls in those bodies queue another
      batch, giving a natural fixpoint for generic composition.

   The live source has already passed lazy expansion. A static throw type can
   be registered under both source and monomorphized names so the original
   caller is lowered before inference and the concrete body is lowered later.
   A throw type that names ~T~ cannot: unresolved error-output names and caller
   slots are created before inference. Detect that source in
   ~validate_one_fcall_consolidated~, defer that call without adding error
   outputs or generic throw diagnostics, and let ~infer_fcall_expr~ emit the
   single focused error requiring explicit type application.

   No builder/interpreter special case is needed. Both backends continue to
   receive only ordinary concrete calls and concrete FuncDefs.

*** Alternatives considered

   - *Make ~T~ an ordinary default*: not expressive. Defaults are concrete
     Exprs filled after init monomorphization; there is no value equivalent to
     "the static type of a later argument".
   - *Macro wrapper plus ~type_of(expr)~*: ordinary macros require comptime
     arguments, while ~assert_eq~ operands are runtime values. Supporting this
     would require a new hygienic expression-macro/static-reflection system
     and would still need typer integration. It is a useful future language
     feature, not the smallest root fix here.
   - *Special-case ~assert_eq~ in the typer*: small initially, but it duplicates
     generic substitution and leaves ~gid(7)~, generic helpers, and future
     assertion APIs unchanged. Reject unless the general path proves
     impossible.
   - *Runtime Dynamic assertion*: ~Dynamic~ carries an address, not a runtime
     type tag. Recovering ~neq~/~to_str~ would require passing exactly the type
     metadata this issue is trying not to spell, and would weaken static
     checking.
   - *Move every explicit generic expansion from init to the typer*: conceptually
     uniform, but unnecessarily moves the already-working path past lazy/throw
     preparation and makes every generic call pay the late-synthesis machinery.
     Keep explicit init expansion and share only the concrete-instantiation
     helper.

*** Handoff protocol

   The tasks below are ordered checkpoints, not independent alternatives. A
   later task may assume every earlier task is complete. Keep all work in the
   same issue worktree. Intermediate checkpoint commits are acceptable for
   handoff, but squash them into one feature commit before integration unless
   an actual bootstrap failure proves that a staged master migration is needed.
   Tasks 1-5 are preparation with no intended new call syntax; Task 6 is the
   first user-visible inference slice; Tasks 7-12 close semantic edge cases;
   Task 13 verifies, squashes, and closes the issue.

   For every task:

   1. Read the named functions before editing. Do not add a parallel helper
      until the existing helper's contract is understood.
   2. Make only that task's changes and tests. Do not migrate unrelated generic
      call sites while changing compiler phases.
   3. Run the focused test named by the task. Once ~bin/til~ exists,
      ~bin/test_runner both test/first_class.til~ runs that file in interpret
      and compile modes. Negative typer tests run through
      ~bin/til interpret test/typer_errors.til~ and require updating the exact
      error count in ~src/tests.til~.
   4. Before any commit containing til source, use the build workflow and run
      ~systemd-run --user --scope -p MemoryMax=64G make clean && make test~.
      Never edit ~boot/~ manually.
   5. Record completed checkpoints by changing their ~[ ]~ to ~[X]~. When
      implementation begins, change this issue's title from OPEN to WIP.
   6. Stop on an invariant failure. Do not add null guards, fallback types, or
      silent skips to make the next phase run.
