** FIXED #55 Lambda functions and first-class bodies

*** Post-mortem

    Root cause: til had first-class function values, but no distinct AST or
    type-system representation for statement bodies as values. Bare blocks were
    only statement bodies, so they could not be stored, passed, called, or kept
    in dynamic containers without pretending they were ~proc()~ values.

    Fix: added a distinct ~Type.Body~ and ~NodeType.BodyValue~, parsed typed
    ~Body~ literals and capture-list body literals, typed Body calls as
    zero-argument proc-like calls, and reused the existing closure carrier for
    interpreter/codegen storage, cleanup, struct fields, and ~DynVec(Body)~.
    Lambda functions were already fixed separately by #61; this commit lands
    the remaining first-class Body half of #55.

    Regression test: ~test/first_class.til~ covers direct Body calls, captured
    Body mutation, Body parameters, struct fields, ~dyn_type_to_str(Body)~, and
    ~DynVec(Body)~ cast-call execution.

*** Lambda functions (anonymous inline functions)

   Lambda functions are anonymous FuncDef literals passed directly as
   arguments. Same syntax as named definitions, just without a name:

   #+begin_src til
   Predicate := func(I64) returns Bool
   Reducer := func(I64, I64) returns I64

   // filter with inline lambda
   evens := numbers.filter(func(a: I64) returns Bool { return a.mod(2).eq(0) })
   // [2, 4]

   // reduce with inline lambda
   sum := numbers.reduce(0, func(acc: I64, x: I64) returns I64 { return acc.add(x) })
   // 15

   // FuncSig form lambda (type separated from param names)
   doubled := numbers.map(func(I64) returns I64 = (a) { return a.mul(2) })
   #+end_src

*** First-class bodies (blocks as values)

   A Body is a sequence of statements — the simplest unit of executable
   code. Simpler than a function: no signature, no parameters, no return
   type. A Body is essentially a zero-argument, void closure.

   #+begin_src til
   // Store in a variable
   cleanup : Body = [file] { file.close(); println("done") }

   // Pass as argument
   run_twice := proc(b: Body) {
       b()
       b()
   }
   run_twice({ println("hello") })

   // Store in a struct field
   Task := struct {
       on_complete : Body = { }
   }
   t := Task(on_complete = { println("finished") })
   t.on_complete()

   // Store in a collection
   steps := DynVec.new(Body)
   steps.push(own { println("step 1") })
   steps.push(own { println("step 2") })
   for step : Body in steps {
       step()
   }
   #+end_src

*** Relationship to functions and closures

   | Construct         | Has params | Has return type | Has captures | Has body |
   |-------------------+------------+-----------------+--------------+----------|
   | Body              | No         | No              | Optional     | Yes      |
   | func (no closure) | Yes        | Yes             | No           | Yes      |
   | func (closure)    | Yes        | Yes             | Yes ([[./54.org][#54]])    | Yes      |

   A Body is always a zero-argument closure. Without captures
   ([[./54.org][#54]]) it can access only globals; a capture list gives its
   isolated environment explicit access to enclosing locals:

   #+begin_src til
   mut total := 0
   data := vec("I64", 1, 2, 3)

   // Body with capture list
   summer : Body = [mut total, data] { for item : I64 in data { total = total.add(item) } }
   summer()
   // total is now 6
   #+end_src

   A Body is to ~proc()~ what a literal is to a named constant: an anonymous
   zero-argument callable. A first-class Body has ordinary closure-call
   overhead (an isolated call scope in the interpreter and a generated C
   closure function) and can access enclosing locals only through its explicit
   capture list. A bare statement block remains inline in its surrounding
   scope; turning that block into a Body value changes it into an isolated
   callable.

*** Use cases

   #+begin_src til
   // Deferred execution (like Go's defer)
   cleanup : Body = [file] { file.close() }
   // ... do work ...
   cleanup()

   // Callbacks and hooks
   Widget := struct {
       on_click : Body = { }
       on_hover : Body = { }
   }

   // Builder patterns
   with_transaction := proc(db: Database, action: Body) {
       db.begin()
       action()
       db.commit()
   }
   with_transaction(db, [db, record1, record2] {
       db.insert(record1)
       db.insert(record2)
   })

   // Test setup/teardown
   run_test := proc(name: Str, setup: Body, test_body: Body, teardown: Body) {
       println("Running:", name)
       setup()
       test_body()
       teardown()
   }
   #+end_src

*** Scope semantics: inline blocks, isolated Body values

   The implemented rule is the former Option C. A bare ~{ }~ statement block
   executes inline in its surrounding scope. A ~Body~ value executes in its
   own call scope rooted at its captured environment, whether called directly,
   passed as an argument, stored in a field, or stored in a dynamic container.
   Explicit captures are therefore the only route from a Body value to
   enclosing locals; ordinary globals remain visible as usual.

*** Comparison

   | Language   | Block-as-value          | Notes                              |
   |------------+-------------------------+------------------------------------|
   | Ruby       | ~{ ... }~ / ~do...end~  | Blocks and Procs are first-class   |
   | Smalltalk  | ~[ ... ]~               | Blocks are objects                 |
   | Swift      | ~{ () -> Void in ... }~ | Closures (always have captures)    |
   | Kotlin     | ~{ ... }~ (lambda)      | Trailing lambda syntax             |
   | Rust       | closure only            | No bare blocks as values           |
   | Go         | ~func() { ... }()~      | Must wrap in function              |
   | TIL        | ~Body = { ... }~        | Simpler than closure               |

   Ruby is the closest precedent. Ruby blocks can be passed to methods
   implicitly (~yield~) or explicitly (~&block~), and ~Proc.new~ wraps a
   block into a first-class value.
