** FIXED #467 C copies a non-mut struct parameter, losing destructor writes through ref fields built from it

*** Post-mortem

  Root cause: #223 auto-shallow passes a borrowed (non-~mut~) parameter of
  a primitive or small value-struct type BY VALUE in C. That is only sound
  while nothing can observe the copy, so it was already withheld when a
  borrow of the parameter escapes through the return value
  (~fdef_return_carries_borrow~, #344/#357) or is deposited into another
  parameter (~fdef_deposits_param~, #393). A third escape was missed: a
  value built INSIDE the body pointing into the parameter's storage -- a
  struct's ref field (~Tracked(drops=drops)~), a callee returning into its
  argument (~make_tracked(drops)~), a store into a ref field. Ref fields
  are writable, so writes through them (here a destructor's) hit the
  callee's copy compiled and the caller's storage interpreted.

  Semantics chosen: the interpreter's. A borrowed parameter is the
  caller's storage; the by-value copy is an ABI optimization that must
  stay unobservable, as for the earlier escapes.

  Fix (~src/self/typer.til~): the borrow summary walk now records in
  ~DepositAcc.retained~ every candidate parameter some call's value points
  INTO (~summary_expr_bits(...).into~, for every call in the body,
  temporaries included) and every source stored into a resolvable ref
  field. ~update_retained_params~ runs that walk ONCE per function with an
  auto-shallow candidate parameter (~summary_retain_candidates~), after the
  return/deposit fixed point in ~compute_ref_return_summaries~ has settled
  the callee summaries it reads, and records a retained candidate on the
  DIAGONAL of ~deposit_borrow_matrix~ ("the parameter deposits its address
  into the function's own storage"). No other path sets the diagonal and
  every deposit-mapping reader ignores it (they are gated on
  ~deposit_matrix~), so it feeds no other summary. ~fdef_deposits_param~
  already keeps any parameter with a bit in its column by-reference, so no
  FunctionDef field was added (FunctionDef's size sets sizeof(Expr)).
  Self-translate time is unchanged within noise.

  Regression test: ~test/bug467.til~ (constructor, callee-returned
  carrier, UFCS method form, ref-field store, temporary, generic
  instance), run interpreted and compiled by ~make test~.

Found while writing the [[../fixed/466.org][#466]] regression test. A
non-~mut~ struct parameter is passed BY VALUE in C (~static void
drop_one(Drops drops)~), while a callee taking the same kind of parameter
may be passed a pointer (~static Tracked make_tracked(Drops * drops)~).
A ~ref~ field built from that parameter then points into the callee's
copy, so writes through it (here from a custom ~delete~) never reach the
caller's value. The interpreter shares the caller's storage, so the two
backends disagree.

*** Reproduction

  Save this as ~tmp/bug467.til~:

  #+begin_src til
  mode cli
  Drops := struct { count: I64 = 0 }
  Tracked := struct {
      ref drops: Drops
      active := false
  namespace:
      delete := func(own self: Tracked, call_free: Bool = true) {
          if self.active { self.drops.count++ }
          if call_free { free(own self) }
      }
  }
  make_tracked := func(drops: Drops) returns Tracked {
      return Tracked(drops=drops, active=true)
  }
  drop_one := func(drops: Drops) {
      mut tracked := make_tracked(drops)
      tracked = Tracked(drops=drops)
      assert(tracked.active.not())
      assert(drops.count == 1)
  }
  main := proc() {
      drops := Drops()
      drop_one(drops)
      assert(drops.count == 1)
      println("caller observed destructor write")
  }
  #+end_src

  #+begin_src sh
  bin/til interpret --usize=32 tmp/bug467.til
  bin/til interpret --usize=64 tmp/bug467.til
  bin/til run --backend=c --usize=32 tmp/bug467.til
  bin/til run --backend=c --usize=64 tmp/bug467.til
  #+end_src

  Observed on master ~7426776~ + the #466 fix: the interpreter prints
  ~caller observed destructor write~ at both widths; C panics with
  ~tmp/bug467.til:24:5: panic: assert failed~ (the caller's assert) at
  both widths. The callee's own assert passes in C, so the write landed
  in the copy.

*** Notes

  - Writing ~counter.count++~ through a ~ref~ field of a local holder
    built from a non-~mut~ parameter is rejected by the typer ("'counter'
    is an immutable binding"); the destructor path is not, so either the
    typer has a hole (a non-~mut~ parameter's storage is mutated through a
    stored ~ref~) or C's by-value lowering is wrong for a parameter whose
    address escapes into a ~ref~ field. Decide which semantics is
    intended before fixing.
  - Making the parameter ~mut~ is rejected as "redundant 'mut' ... never
    written through", so the user cannot opt into the shared semantics
    either. ~test/aggregate_control.til~'s ~check_enums~ only checks
    deltas inside the callee, which is why it does not catch this.
  - FASM was not checked (vendor/fasm not bootstrapped in the session that
    found it).
