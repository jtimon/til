** FIXED #441 Target-aware size comparisons in function-generator macro conditions

*** Post-mortem

Definition-generating macros selected branches during initialization, where
the condition evaluator only recognized Type.is tests. Calling the ordinary
interpreter's size methods instead would have confused host storage widths
with the target widths needed for specialization.

The preparation added target primitive size comparisons and short-circuit
Boolean composition, resolving aliases through the target type scope while
preserving host interpreter layouts. Unsupported conditions now diagnose
rather than choosing a branch. After that support landed, core's factory
was migrated to ~make_usize_to_uptr()~ with
~USize.size() <= UPtr.size()~. It no longer enumerates U32/U64 combinations
or duplicates the unchecked body. A narrowing target keeps the value check;
other targets generate only the conversion.

Regression tests: ~test_size_condition_generators~ in test/first_class.til
and ~check_dynamic_widths~ in test/dynamic_widths.til. The byte-count probe
now calls core before its imported fixture so overflow proves the migrated
core function rejects the value. Final verification on master ~be9cae300~:
~make clean && make test~ passed 456/456, including the emitted-C checks
across all five 32-bit targets. Linux x86 QEMU container and byte-count
boundary probes passed with both ~--usize=32~ and ~--usize=64~.

*** Preparation history

The evaluator now supports target primitive size comparisons, non-negative
U64-range integer literals, aliases and substituted Type parameters. It also
handles ~or~ / ~and~ (method and plain-call forms, including ~||~ / ~&&~
sugar) with left-to-right short-circuiting. Unknown conditions diagnose at
the generator application instead of selecting the false branch. Aggregate
and user-defined size queries remain explicitly unsupported at this stage.

~test_size_condition_generators~ in test/first_class.til covers all six
comparisons, numeric bases, aliases, else-if selection, StructDef returns,
Boolean spellings and skipped unsupported operands. test/dynamic_widths.til
uses a size-based conversion factory from an imported fixture at both
USize widths and all five 32-bit targets, reusing the existing batched
compilations. It also checks the unsupported-user-size diagnostic.
~make clean && make test~ passed 524/524; Linux x86 QEMU boundary and
container probes passed at both widths.

The core factory migration required this preparation to land first. With
the size-based core factory, HEAD's til_boot failed while building make.til:

#+begin_example
./src/core/numbers.til:888:18: error: undefined function 'make_usize_to_uptr'
#+end_example

Combining the existing two Type.is branches with ~.or(...)~ also fails with
old til_boot ("macro argument must be known at compile time" and the same
undefined-function diagnostic). This is doc/self.org's staged source-level
migration: pass 1 rejects the new generator condition before the new compiler
can be built, so a two-pass invocation cannot bootstrap the combined change.
Core kept its old spelling in the preparation; the tested fixture already
used the desired size condition. The final migration followed the merge of
that preparation, using the zero-argument size-based factory below.

Verification also required correcting make.til's dispatcher to take
~mut b: Build~: master e61ceecf3 now enforces the stored handler's
~proc(mut Build)~ contract, which the old dispatcher signature violated.

*** Original goal

Allow a til macro returning ~FuncDef~ to select a function body using a
condition such as ~USize.size() <= UPtr.size()~. The decision belongs at
compile time; runtime calls should execute only the selected function.

The motivating case is #400's ~usize_to_uptr~ specialization. Its factory
currently enumerates U32/U64 type combinations with ~Type.is~ tests. The
desired spelling expresses the actual rule without enumerating widths:

#+begin_src til
make_usize_to_uptr := macro() returns FuncDef {
    if USize.size() <= UPtr.size() {
        return func(val: USize) returns UPtr {
            return val.to_uptr()
        }
    } else {
        return func(val: USize) returns UPtr {
            converted := val.to_uptr()
            if converted.cast(U64) != val.cast(U64) {
                panic("usize_to_uptr: byte count exceeds pointer width")
            }
            return converted
        }
    }
}

usize_to_uptr := make_usize_to_uptr()
#+end_src

*** Original behavior and constraints

- ~init_macro_cond_eval~ in src/self/initer.til recognizes type-test
  conditions, not size comparisons. ~init_macro_pick_return~ chooses the
  returned definition before the generated body is typed. This is earlier
  than ordinary constfolding, although both are compile-time work.
- Width aliases must resolve through the target type scope, as the type
  tests now do. Existing interpreter size queries can describe HOST storage:
  during #400 follow-up testing, ~UPtr.size()~ reported 8 while a conversion
  under ~--target=linux-x86 --usize=64~ actually narrowed to U32. Wrapping
  that same host-size query in a macro would still choose the wrong branch.
- The interpreter's real pointer allocations and aggregate layout tables
  must remain host-sized. This feature must not globally change those
  queries to target sizes or introduce a second layout cache.
- #440 tracks private generators being falsely reported unused. That is
  independent; this feature can use the existing non-private factory.

*** Implementation plan

- [X] Trace the parsed comparison shape and generator expansion order,
  including parameter substitution, imported factories and target alias
  registration. Establish which target facts are available before branch
  selection; do not assume ordinary constfolding has already run.
- [X] Extend generator-condition evaluation to compare known target sizes.
  Start with concrete primitive types, USize/UPtr and aliases to them,
  including substituted Type parameters and integer byte-count literals.
  Support the ordinary comparison operators (~<~, ~<=~, ~==~, ~!=~, ~>=~,
  ~>~), using existing primitive-size and target-alias authorities rather
  than a new width table or hard-coded U32/U64 combinations.
- [X] Keep this target-size evaluation distinct from interpreter storage
  sizing. Establish semantics and initialization availability before accepting
  aggregate sizes or user-defined size methods; never substitute a host
  layout for a target size that cannot yet be evaluated. Preserve the
  distinction between a false condition and an unsupported/unknown one,
  with a useful diagnostic if expansion cannot complete.
- [X] Retain compile-time branch selection: only the chosen returned
  definition becomes the generated function. Preserve existing Type.is
  conditions and if/else-if behavior. Reuse the evaluator if other existing
  definition-generating macros share this path; do not add new public
  intrinsics, flags or persistent artifacts for this feature.
- [X] Rewrite ~make_usize_to_uptr~ to the size-based form above once target
  comparisons work. Follow doc/self.org's bootstrap workflow: verify whether
  old til_boot can build the combined change; if not, land condition support
  as preparation before making core depend on it. Record the actual build
  failure rather than assuming two passes can resolve a pass-1 rejection.
- [X] Add regressions and run the required bootstrap/full-suite checks.
  Update the generator documentation with the supported condition forms
  and their target-versus-host sizing contract.
