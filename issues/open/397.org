** OPEN #397 A Type carries its Sym: Struct/Enum/Custom payloads become symbols

*** Why

The #292/#337 interning migration converted the scope registries to
Map(Sym, ...) keys, but the names that FEED the hot lookups still come
from the AST's type spellings: Type.Struct(Str) / Type.Enum(Str) /
Type.Custom(Str), read via expr_type_name_ref and friends. So
get_struct(name) and get_binding_name(name) hash a spelling to recover
a symbol that was known when the Type value was built.

Measured on `translate test/first_class.til` (2026-08-19, master
d125e36e): SymbolPool.lookup runs 540,767 times; get_struct is 41.6%
of the calls and get_binding_name 29.3% -- 71% combined. Each lookup
is fnv1a over the whole name (~15 instructions/byte at -O0) plus a
Str_eq bucket confirmation; fnv1a + Str_eq together are ~8% of the
run. This is the main remaining chunk of the interning migration's
half-way cost (the migration's maps got cheaper, but paying
hash+confirm at the door made hot paths NET slower than the
pre-interning Str-keyed binary searches).

Micro-alternatives measured and rejected before this design, so they
stay rejected:
  - first-byte fast path in Str.cmp: +4.5%;
  - value-form tag reads: +0.001% (noise);
  - wiring the never-read bindings_filt as a probe filter: the filter
    skipped 18.5% of probes and still cost +2.5% net (per-call
    fingerprint arithmetic on 826K calls outweighed the skipped
    searches). At -O0 the win comes from removing WORK, not from
    adding cleverness in front of it.

*** The design: replace, not duplicate

Type's name payloads become symbols:

    Struct: Sym,  Enum: Sym,  Custom: Sym   (FuncPtrSig: Sym too)

ONE representation. The alternative -- carrying {name: Str, sym: Sym}
side by side -- is a second representation of the same fact that must
never disagree, exactly what CLAUDE.md's duplication rule exists to
prevent, and is rejected here by design, not deferred.

Spellings come back through SymbolPool.resolve(sym) at the edges that
genuinely need text: diagnostics, name mangling, C emission, to_str.
A site that forgets resolve() prints a number instead of a name --
ugly and loud, not silently wrong.

*** Why this is NOT a single commit

doc/self.org "Staged migration across master merges" applies twice
over:

  - Type's own comment records the constraint: til_boot has Type's
    layout and tag values BAKED into its compiled C. Changing a
    payload from Str (16 bytes) to Sym (4) changes the variant's
    layout; a single commit would have master's til_boot mis-decoding
    Type values while bootstrapping the very compiler that defines
    the new layout. Pass 1 dies, so two_pass cannot rescue it (the
    CAP_INLINE lesson, which burned exactly this way).
  - The interpreter reads Type through its raw-bytes layout model
    (struct_layouts / enum payload slots), so both backends must
    switch understanding in the same step a value's bytes change.

*** Staged plan (each step merges to master before the next)

1. Preparation: teach the compiler to CONSTRUCT and MATCH both forms.
   Add Sym-carrying twins appended at the enum's END (tag stability,
   same rule Primitive followed): StructSym: Sym, EnumSym: Sym,
   CustomSym: Sym, FuncPtrSigSym: Sym. Nothing produces them yet.
   Shared accessors in context.til so consumers ask one question:
   type_sym(t, symbols) (interning the Str forms on demand) and
   type_name_ref(t, symbols) (resolving the Sym forms). Suite green,
   emitted C byte-identical. [plain commit]

2. Consumers that ALREADY hold a symbol stop round-tripping through a
   spelling. Correction to this step's original rationale, which was
   wrong: it claimed routing get_struct/get_binding_name callers
   through get_struct_by_sym(type_sym(...)) wins "because type_sym
   interns ONCE per call instead of per scope level". get_struct
   already hashes once per call, not once per level -- it does a
   single symbols.lookup and then walks the levels by Sym. Routing a
   Str-holding caller through type_sym therefore buys nothing: the
   hash simply moves. The only free win available before step 3 is
   the caller that never needed a spelling in the first place --
   IdentData.name has been a Sym since #292, so any site doing
   ident_name(names) purely to hand the result to a name-keyed lookup
   is resolving a symbol so the lookup can hash it back.

   Harvested here (measured, `translate --force-rebuild
   test/first_class.til`): fa_is_ns's Ident branch via
   fa_is_ns_named_sym, the interpreter's static_ns_func_def_sym /
   ns_func_def_sym, and the constfolder's two ns_func_def sites.
   get_struct 279,919 -> 146,155 calls, SymbolPool.lookup 592,240 ->
   546,825, fnv1a 860,686 -> 815,271: 6,374,349,409 -> 6,353,302,722
   instructions, -0.330%. Modest, and that is the honest size of it.

   What is left is NOT free and belongs to step 3: get_binding_name's
   top caller resolve_type_alias (97,283), get_struct's top caller
   name_is_interface (42,369), and fa_is_ns's other branch (88,349)
   all take their name off a Type payload. find_callee_fdef's 59,660
   are worse than free -- those names are SYNTHESIZED at emit time
   (type_name.format("_delete") and friends), so interning them would
   add a hash plus an insert where today there is one lookup.
   [plain commits]

3. Producers flip: infer/parse/init sites that build Type.Struct(name)
   build Type.StructSym(symbols.intern(name)) instead. One family per
   slice, each suite-green on master before the next.

   DONE, slice 1 -- the FuncPtrSig family (all 12 producers, in typer/
   parser/initer/loader/context). Chosen first because it is the one
   family fully closed inside src/self: core's own producers
   (declaration_type_from_name, the TYPE_* singletons) serve runtime
   reflection and never build a FuncPtrSig. What the slice established,
   which the remaining families inherit:

   - The RUNTIME Type surface stays Str-shaped. User programs match
     .FuncPtrSig(name) and have no pool, so the twins live only inside
     the compiler process; write_runtime_type resolves a twin back to
     the Str form at the marshalling edge. Consequence: emitted C for
     user programs did not change ("Two-pass:" was not needed --
     the plain three-pass build and the corpus eqcheck passed), and
     emit_dyn_type_to_str_body's "?" fallthrough stays dead.
   - The three runtime spelling accessors (Declaration.type_name,
     til_type_name, expr_type_name_ref) now PANIC on a twin, and every
     compiler call site moved to a both-forms reader: type_name_res
     (Declaration method taking the pool's names Vec, ident_name-style),
     til_type_name_res / type_name_of / type_to_name(+pool) in the
     compiler. ~350 call sites swept; the sweep is done ONCE, so the
     remaining families only flip producers against already-migrated
     readers.
   - Tag-check sites moved to type_is_funcsig / is_funcptr (twins
     included). The class to grep for when flipping the next family:
     `case .FuncPtr, .FuncPtrSig, .Body`-style TAG LISTS. Two silent
     traps of that class were only caught by the C compiler and ASAN
     respectively: til_type_to_c's default arm emitted I64 for a twin
     (a FuncSig-typed GLOBAL emitted as I64 -- caught by -Werror), and
     the interpreter's heap_drop/clone/move arms missed the twin, so
     closure envs bound to FuncPtrSigSym-typed locals leaked (caught
     only by the ASAN pass; the plain suite was green).
   - Diagnostic scaffolding warning: a `loc: Str = __LOC__` default
     parameter on the panicking accessors located every caller during
     the sweep, but it CANNOT ship -- the constfolder rebuilds macro
     calls without filling defaults, so the extra parameter broke
     arity at interpretation time (OutOfBounds in eval args).
   - REBASE HAZARD, and the reason a green pre-rebase suite proves
     nothing here: master keeps adding callers of the very readers this
     migration retires, and they auto-merge CLEANLY. Two classes, and
     only one is caught by the compiler. A new `type_to_name(t)` fails
     the build (the signature grew a pool). A new `.type_name()`,
     `til_type_name(t)` or `expr_type_name_ref(e)` compiles FINE and
     panics at runtime only if a twin reaches it -- so the guard is to
     re-grep for all four after every rebase, not to trust the build.
     Six such callers arrived in one 10-commit rebase (2 + 4).
   - The #170 cache does not key on the compiler mid-migration state:
     manual debug builds poisoned it and three tests "failed" on stale
     cached successes. `make clean && make test` is the arbiter; it
     passed 470/470.

   Still owed by the remaining families (Struct/Enum/Custom):
   - is_type_metatype answers the "is this the Type metatype" question
     with `case: false` for the twins -- correct for FuncPtrSigSym,
     WRONG for a future StructSym/EnumSym/CustomSym naming "Type".
     Must gain twin arms (or route through type_sym) in the slice that
     flips those families.
   - constfolder_type_is_aggregate's final `case .Struct, .Enum` tag
     arms; write_runtime_type's remaining panic arms; make_til_type_expr
     (needs the payload spelling once Struct/Enum/Custom flip);
     til_type_name_c's payload-carrying Custom arm.
   - The interpreter's layout tables pick up those variants' sizes in
     the same slices.

4. Retirement: when nothing constructs the Str forms, reject them in
   a transitional commit (panic in the accessors' Str arms naming this
   issue), then delete the variants... which SHIFTS TAGS -- so the
   deletion is its own staged dance: master's til_boot must already
   understand the post-delete tag numbering before the commit that
   renumbers. Follow Primitive's precedent in reverse and expect this
   step to be the slowest; it can also simply WAIT -- dead variants
   cost nothing at runtime -- until a natural Type-layout change
   batches with it.

5. Measure at every step against the standing baseline (4,596M
   instructions at 9263b9c8, before the interning regression). Note
   for anyone re-running the numbers: since #170 landed, `translate`
   CACHES its output, and a warm cache turns the benchmark into a
   lex-and-exit that measures 177M instead of ~6,350M while printing
   the same "Generated:" lines. Always pass --force-rebuild.
   Step 2 removed 45K of get_struct's hashes (the ones whose caller
   held an Ident); step 3 is where the rest of get_struct and most
   of get_binding_name go. The success
   criterion is not "faster than yesterday" but BELOW THE PRE-INTERNING
   BASELINE, since that is what finishing the migration is for.

*** Risks

  - Forgotten resolve() at a text edge: symbol number in a diagnostic
    or, worse, in MANGLED C names. The corpus eqcheck catches the
    C-name case byte-for-byte; goldens and typer_errors.til catch
    diagnostics.
  - The Sym is Context-local: a Type value must never cross Contexts
    (REPL cached base vs deltas is the place to look; SymbolPool
    clone semantics already note "a cloned Context starts with a
    FRESH interner").
  - Map(Sym,...) iteration order is intern order, not alphabetical:
    anywhere a walk over a Type-keyed or name-keyed structure feeds
    OUTPUT, determinism must be re-checked (the #292 conversions are
    the precedent that this is manageable).
