** WIP #367 The NUL guarantee in the type: #343's route 2

#343 shipped its route 1: the ext-call boundary panics when a Str whose
~c_str~ feeds a C string parameter is not NUL-terminated (the compiled
~TIL_CSTR~ macro, mirrored in the interpreter's FFI marshalling). That
is a runtime backstop, and it sees only the direct ~expr.c_str~ form: a
pointer laundered through an ~I8~ local first escapes it, and so does a
binding's own C side. The rules in doc/ffi.org remain the rules; the
check just turns getting them wrong into a panic naming the cause.

Route 2 is the honest fix #343 recorded and deferred: make the
guarantee VISIBLE IN THE TYPE, so ~s : Str~ stops meaning two different
things ("length-counted bytes" and "C-ready string") depending on which
caller you ask. A distinct type or qualifier for "NUL-terminated Str"
that ~clone~ / ~format~ / ~with_capacity~ / string literals produce and
~substr~ / ~trim~ views do not, checked at TYPECHECK time:

- an ext binding's C-string parameter demands the terminated type, so
  passing a view is a type error at the call site instead of a runtime
  panic at the boundary;
- ~clone()~ is the blessed conversion, exactly the idiom doc/ffi.org
  already teaches -- the type makes the existing rule mechanical instead
  of remembered;
- core/str.til's own view-consuming functions (~eq~'s memcmp, ~substr~
  chaining, ~hash~) keep taking plain ~Str~, so views stay first-class
  everywhere the count is authoritative -- which is everywhere except
  the C boundary.

Why it is large, recorded so the estimate survives: it touches every
signature that currently says ~Str~ and means "C-ready" -- the ext
bindings in vendor/bindings/*.til with ~I8~ string params, their
wrappers (src/modes/gui.til, std/sys's ~get_env~), and the binder's
generation so regenerated bindings come out with the right type. The
design question to settle first is the SHAPE: a wrapper type
(~CStr~-like, with an explicit accessor), a qualifier on Str, or a
refinement the typer tracks. The wrapper is the smallest honest
version: no inference machinery, conversions are spelled, and the
runtime representation stays a Str whose invariant is established at
construction.

Keep route 1's runtime check even after route 2 lands: the type governs
til call sites, while the macro also catches invariant breakage coming
from the C side (an ext function returning a Str it forgot to
terminate), which no til-side type can see. #343's NUL audit -- every
allocating Str path reserves count+1 -- is the invariant both routes
stand on; ~test_file_readfile_is_nul_terminated~ and the boundary tests
(~cstr_view_interp~ / ~cstr_view_run~) pin it.

*** Stage 1 landed: the type, both boundaries, the typecheck

    Shape DECIDED per this issue's own lean: the wrapper. `CStr` in
    core/str.til, whose one field is `ref s : Str` -- a BORROW,
    deliberately, because a by-value Str field would hand CStr's
    generated delete the inner buffer (Str's destructor frees c_str
    regardless of call_free) and the wrapper would free a string it
    never owned. `Str.to_cstr` is the spelled conversion; it verifies
    the terminator at CONSTRUCTION (the #343 discriminator, one layer
    earlier), so a CStr in hand is proof.

    The typecheck: `to_cstr` on a receiver the typer KNOWS is a view is
    a type error naming the fix (clone first). Two shapes are knowable
    -- an Ident binding carrying #372's provenance, and a view-returning
    method call as the receiver directly (matched in its RAW pre-UFCS
    shape; str_view_source_name expects the post-rewrite one). A
    provenance-less view (arriving through a call result) falls through
    to the construction check and dies with #343's exact message.

    Both boundaries marshal `name : CStr` ext params:
    - compiled: the prototype writer maps a CStr param on an EXT decl to
      `const I8 *` (the binding declares the real C signature); the arg
      lowering emits `TIL_CSTR((<value>).s)` -- route 1's boundary check
      deliberately stays; and the #326 TIL_CSTR site collector counts
      the new shape, or the macro definition is dead-pruned out from
      under the call.
    - interpreter: a CStr param's cif slot was already ffi_type_pointer
      (non-shallow default); the marshal loop unwraps value -> s ->
      c_str with the terminator re-check between.

    Tests: test/cstr_type.til (safe shapes end to end through real libc,
    both backends), test/cstr_construct.til (the provenance-less view
    panics at construction, both backends), and two typer_errors
    negatives for the typecheck shapes. 473/473.

    THE BOOTSTRAP TRAP, why the std/vendor flip is NOT in this commit:
    pass 1 compiles src/std/sys.til and src/modes/gui.til with the
    PREVIOUS boot compiler, which has no CStr lowering -- flipping
    `getenv` / `til_setenv` to CStr in the same commit as the emitter
    support cannot build. Classic preparation + use (doc/self.org):
    this commit is the preparation; the flip follows once it is in the
    merged boot.

*** Recorded hazard, pre-existing and adjacent

    Declaring the SAME ext symbol twice with different signatures (a
    test file rebinding sys.til's `getenv` with a CStr param while the
    import's I8 binding is live) segfaults the interpreter: the FFI
    entry is keyed by name and registered once, while call-site
    marshalling consults the SCOPE's def -- two different declarations,
    one cif. Reproducible without CStr (my marshal arm just makes the
    mismatch fatal faster). A duplicate ext binding with a conflicting
    signature should probably be a load-time error; not this issue's
    scope, recorded here so it is not rediscovered the hard way.
