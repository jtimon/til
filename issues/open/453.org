** WIP #453 Add a FASM native assembly backend

Implement a native assembly backend that emits flat assembler (FASM) source
from til's prepared program, then assembles it into native code. Backend
selection and the target OS/architecture are separate concerns, as with the
existing C and MLIR backends.

*** Reference

  - Official FASM 1 source repository: https://github.com/tgrysztar/fasm
  - Website and binary releases: https://flatassembler.net/
  - Vendored source: ~vendor/fasm/~; license also in ~LICENSE/fasm.txt~.
  - Initial reference revision: ~225ce90e81e69877ab42505f7713e3d3fd531d42~.

   FASM is now a vendored optional build dependency; the duplicate inspiration
   clone has been removed. This issue targets FASM 1, not fasmg.

*** Progress

  The first slice selects ~--backend=fasm~, emits ~gen/fasm/<source>.fasm~
  and builds standalone Linux ELF64 executables in the existing ~bin/~ paths.
  Internal calls use SysV integer registers and 16-byte stack alignment.
  FASM's first bootstrap is manual; subsequent rebuilds and installation are
  integrated as described below. See ~doc/self.org~ for the implemented subset and
  ~test/fasm_options.til~ / ~test/fasm_native.til~ for initial checks.

  The first subset supports I64/Bool parameters and value locals, local
  assignments, direct calls, returns, if/else, wrapping add/subtract/multiply,
   signed comparisons and Bool negation. That initial commit supported only
   core ~exit~ as a runtime service.

  Verification: ~make clean && make test~ passed 477/477. The separate
  ~test/fasm_native.til~ also passed with the ASAN compiler and test driver.
  Native tests compare the same programs with interpretation and C, including
  six-argument calls, nested calls, branches and signed overflow. Mutated
  input locals prevent compile-time folding from hiding the emitted operations.

**** Native runtime follow-up

  ~src/fasm/ext.fasm~ is now the separate native boundary, following ext.c
  and the core Str/io/exit contracts. Generated assembly includes it directly.
  Str and variadic Array(Str) layouts match C at USize32 and USize64; value
  slots retain their outer storage while runtime-returned wrappers are moved
  and released. SysV register and stack conventions remain unchanged.

  The implemented boundary includes counted stdout/stderr, print/format and
  panic/assert/expect, allocation and raw memory, owned/borrowed strings,
  integer formatting, and the cfile open/read/write/close/update/append/seek
  primitives. Allocation failures return NULL, realloc preserves the old
  block on failure, and file I/O failures terminate instead of reporting
  successful truncated data. Native diagnostics are documented in self.org.

  The emitter now also accepts script bodies, integer widths needed by the
  runtime ABI, typed scalar pointer locals and borrowed Str parameters.
  At that stage general aggregates, user arrays, aggregate returns/reassignment,
  indirect calls and general exception propagation were still outstanding.

  ~test/fasm_runtime.til~ compares identical source programs through the
  interpreter, C and FASM at both USize widths, reusing the existing hello
  script unchanged. Temporary frontier cases cover byte-exact output, panic,
  string ownership, memory, file growth/update/append, counted path views,
  /proc reads, missing files and /dev/full. A native ABI check verifies failed
  realloc preservation without bypassing til's ownership-transfer checks.

  Verification on master base ~73cfa28ba~: ~make clean && make test~ passed
  481/481; ~test/fasm_runtime.til~ and ~test/fasm_native.til~ both passed with
  the ASAN compiler and test driver. ASAN instruments the compiler/driver,
  not the generated native assembly runtime.

**** Build/install and scalar-control follow-up

  The normal vendor phase and FASM build/run commands now refresh a
  bootstrapped assembler from changed assembly/includes. Builds use a
  process-specific checkout tmp file and rename only after successful assembly,
  preserving the working tool on failure. The bootstrap seed remains optional
  for C builds and survives clean/clean_vendor.

  Linux x86-64 installation copies the available assembler/license at
  ~lib/til/vendor/fasm/~ and the runtime at ~lib/til/src/fasm/~. The installed
  compiler uses those read-only payloads, with no assembler build sources or
  temporary writes under the installation. Without a bootstrap, installation
  reports that only runtime sources are being installed.

  The emitter now handles while/range loops, nested break/continue, lexical
  blocks, mut/ref scalar arguments, short-circuit Bool operations, division,
  remainder, shifts, bitwise operations and all scalar comparisons. Primitive
  signedness is taken from Primitive tags, not type_name_ref (which has no
  primitive name payload). Narrow cells are normalized after reference writes,
  and arithmetic uses the method's width before caller-argument widening.

  Shared-source execution now includes FizzBuzz, the existing TempleOS scalar
  checks and continue fixture, plus ~test/scalar_control.til~ in the normal
  interpreter/C suite. The latter exposed missing interpreter dispatch for
  U32_cmp: ext.h keeps it always-inline, so there is no exported FFI symbol.
  A handler calls that existing inline comparison, preserving the C hot path.
  Both USize widths are checked. Native integration also covers assembler
  rebuilds and failure preservation; the install test runs a real installed
  FASM program outside the checkout.

  Verification on master base ~2d9d1c893~: ~make clean && make test~ passed
  486/486, including the installed-compiler probe and the shared scalar test.
  ~test/fasm_native.til~ and ~test/fasm_runtime.til~ also passed with the ASAN
  compiler/test driver; native comparisons exercised both USize widths.

**** Aggregate and ownership follow-up

  The emitter now lowers ordinary structs and nested inline/own/ref fields,
  aggregate parameters/returns, heap and stack outer storage, assignments and
  custom cleanup. It indexes the canonical imported definitions and emits
  reachable core/std methods, including Array/Vec clone/delete/indexing and
  the ordinary File wrappers. Imported initializer statements are emitted too;
  persistent runtime globals still fail explicitly.

  Layout uses the shared target_value_size_align query. ctx.struct_layouts is
  host-interpreter layout (e.g. a USize32 compiler's Str is 16 bytes even when
  the target's Str is 24), so using that cache in native code corrupts nested
  fields. FASM now derives target offsets without a second persistent cache.

  Aggregate values have an internal address/boxed-return ABI; shallow, ref,
  own and GcStorage decisions follow the shared lowering. save_old_delete and
  swap_replace preserve evaluation/cleanup order, and discarded results release
  their owned wrappers. Precomputed sequences are immutable assembly templates
  cloned through the actual til methods, not a second implementation of array
  ownership semantics. Lowered bounds catches and bang panics now run normally.

  test/aggregate_control.til is shared by the ordinary interpreter/C suite and
  the FASM native driver at both USize widths. It checks layout, owned nested
  fields, clone independence, custom destructor counts, mut-parameter
  replacement, discarded values, returned borrows, arrays and File wrappers.
  Existing imported-call and bang-panic sources are reused unchanged. Removal
  now follows ext.c's current unlink/ENOENT contract, including directory errors.

  The tests exposed a pre-existing interpreter/C discrepancy for ref-to-ref
  rebinding: the interpreter copies through the left reference, while C rebinds
  it. FASM follows C, and the native driver records that comparison separately;
  the shared corpus covers mutation through returned borrows. Enums, interfaces,
  indirect calls and broader runtime/test-mode coverage remain unfinished.

  Verification on master base ~1ec7e4ba0~: ~make clean && make test~ passed
  495/495. Both FASM native drivers passed with the ASAN compiler/test driver,
  exercising the shared sources at USize32 and USize64, including bounds
  failures and custom destructor counts. Native emitted code is not ASAN
  instrumented; the compiler, driver and ordinary C suite are.

  Differential testing against C and interpretation is a primary motivation.
  Selective future JIT execution could amortize compilation for expensive or
  repeated work. In-process code allocation, relocation, lifetime management
  and interpreter/native value boundaries are separate future work; JIT is
  not required to complete this initial backend, nor a wholesale interpreter
  replacement.
