** WIP #453 Add a FASM native assembly backend

Implement a native assembly backend that emits flat assembler (FASM) source
from til's prepared program, then assembles it into native code. Backend
selection and the target OS/architecture are separate concerns, as with the
existing C and MLIR backends.

*** Related host direction

[[./151.org][#151]] records the TempleOS-host plan: native til self-building for
TempleOS first, then Linux x64 as its first foreign target through a ported
FASM. This issue supplies the corresponding FASM backend/host integration;
the detailed bootstrap and low-address/OS-adapter requirements live in #151.
Porting the assembler to TempleOS is distinct from adding TempleOS output
to this backend. The latter is not required to produce Linux ELF in the guest.
Current Linux-only host invocation and target restrictions remain the actual
implementation. [[./472.org][#472]] owns determinism; [[./473.org][#473]] owns the producer/consumer
CI cells, whose functional checks need not wait for reproducible bytes.

*** Progress

  The first slice selects ~--backend=fasm~, emits ~gen/fasm/<source>.fasm~
  and builds standalone Linux ELF64 executables in the existing ~bin/~ paths.
  Internal calls use SysV integer registers and 16-byte stack alignment.
  FASM's first bootstrap is manual; subsequent rebuilds and installation are
  integrated as described below. See ~doc/self.org~ for the implemented subset and
  ~test/fasm_options.til~ / ~test/fasm_native.til~ for initial checks.

  The first subset supports I64/Bool parameters and value locals, local
  assignments, direct calls, returns, if/else, wrapping add/subtract/multiply,
   signed comparisons and Bool negation. That initial commit supported only
   core ~exit~ as a runtime service.

  Verification: ~make clean && make test~ passed 477/477. The separate
  ~test/fasm_native.til~ also passed with the ASAN compiler and test driver.
  Native tests compare the same programs with interpretation and C, including
  six-argument calls, nested calls, branches and signed overflow. Mutated
  input locals prevent compile-time folding from hiding the emitted operations.

**** Native runtime follow-up

  ~src/self/codegen/ext.fasm~ is now the separate native boundary, following ext.c
  and the core Str/io/exit contracts. Generated assembly includes it directly.
  Str and variadic Array(Str) layouts match C at USize32 and USize64; value
  slots retain their outer storage while runtime-returned wrappers are moved
  and released. SysV register and stack conventions remain unchanged.

  The implemented boundary includes counted stdout/stderr, print/format and
  panic/assert/expect, allocation and raw memory, owned/borrowed strings,
  integer formatting, and the cfile open/read/write/close/update/append/seek
  primitives. Allocation failures return NULL, realloc preserves the old
  block on failure, and file I/O failures terminate instead of reporting
  successful truncated data. Native diagnostics are documented in self.org.

  The emitter now also accepts script bodies, integer widths needed by the
  runtime ABI, typed scalar pointer locals and borrowed Str parameters.
  At that stage general aggregates, user arrays, aggregate returns/reassignment,
  indirect calls and general exception propagation were still outstanding.

  ~test/fasm_runtime.til~ compares identical source programs through the
  interpreter, C and FASM at both USize widths, reusing the existing hello
  script unchanged. Temporary frontier cases cover byte-exact output, panic,
  string ownership, memory, file growth/update/append, counted path views,
  /proc reads, missing files and /dev/full. A native ABI check verifies failed
  realloc preservation without bypassing til's ownership-transfer checks.

  Verification on master base ~73cfa28ba~: ~make clean && make test~ passed
  481/481; ~test/fasm_runtime.til~ and ~test/fasm_native.til~ both passed with
  the ASAN compiler and test driver. ASAN instruments the compiler/driver,
  not the generated native assembly runtime.

**** Build/install and scalar-control follow-up

  The normal vendor phase and FASM build/run commands now refresh a
  bootstrapped assembler from changed assembly/includes. Builds use a
  process-specific checkout tmp file and rename only after successful assembly,
  preserving the working tool on failure. The bootstrap seed remains optional
  for C builds and survives clean/clean_vendor.

  Linux x86-64 installation copies the available assembler/license at
  ~lib/til/vendor/fasm/~ and the runtime at ~lib/til/src/self/codegen/~. The installed
  compiler uses those read-only payloads, with no assembler build sources or
  temporary writes under the installation. Without a bootstrap, installation
  reports that only runtime sources are being installed.

  The emitter now handles while/range loops, nested break/continue, lexical
  blocks, mut/ref scalar arguments, short-circuit Bool operations, division,
  remainder, shifts, bitwise operations and all scalar comparisons. Primitive
  signedness is taken from Primitive tags, not type_name_ref (which has no
  primitive name payload). Narrow cells are normalized after reference writes,
  and arithmetic uses the method's width before caller-argument widening.

  Shared-source execution now includes FizzBuzz, the existing TempleOS scalar
  checks and continue fixture, plus ~test/scalar_control.til~ in the normal
  interpreter/C suite. The latter exposed missing interpreter dispatch for
  U32_cmp: ext.h keeps it always-inline, so there is no exported FFI symbol.
  A handler calls that existing inline comparison, preserving the C hot path.
  Both USize widths are checked. Native integration also covers assembler
  rebuilds and failure preservation; the install test runs a real installed
  FASM program outside the checkout.

  Verification on master base ~2d9d1c893~: ~make clean && make test~ passed
  486/486, including the installed-compiler probe and the shared scalar test.
  ~test/fasm_native.til~ and ~test/fasm_runtime.til~ also passed with the ASAN
  compiler/test driver; native comparisons exercised both USize widths.

**** Aggregate and ownership follow-up

  The emitter now lowers ordinary structs and nested inline/own/ref fields,
  aggregate parameters/returns, heap and stack outer storage, assignments and
  custom cleanup. It indexes the canonical imported definitions and emits
  reachable core/std methods, including Array/Vec clone/delete/indexing and
  the ordinary File wrappers. Imported initializer statements are emitted too;
  persistent runtime globals still fail explicitly.

  Layout uses the shared target_value_size_align query. ctx.struct_layouts is
  host-interpreter layout (e.g. a USize32 compiler's Str is 16 bytes even when
  the target's Str is 24), so using that cache in native code corrupts nested
  fields. FASM now derives target offsets without a second persistent cache.

  Aggregate values have an internal address/boxed-return ABI; shallow, ref,
  own and GcStorage decisions follow the shared lowering. save_old_delete and
  swap_replace preserve evaluation/cleanup order, and discarded results release
  their owned wrappers. Precomputed sequences are immutable assembly templates
  cloned through the actual til methods, not a second implementation of array
  ownership semantics. Lowered bounds catches and bang panics now run normally.

  test/aggregate_control.til is shared by the ordinary interpreter/C suite and
  the FASM native driver at both USize widths. It checks layout, owned nested
  fields, clone independence, custom destructor counts, mut-parameter
  replacement, discarded values, returned borrows, arrays and File wrappers.
  Existing imported-call and bang-panic sources are reused unchanged. Removal
  now follows ext.c's current unlink/ENOENT contract, including directory errors.

  The tests exposed a pre-existing interpreter/C discrepancy for ref-to-ref
  rebinding. That was initially tested separately against C; the follow-up below
  fixes it and moves the case into shared coverage. Enums, interfaces, indirect
  calls and broader runtime/test-mode coverage remain unfinished.

  Verification on master base ~1ec7e4ba0~: ~make clean && make test~ passed
  495/495. Both FASM native drivers passed with the ASAN compiler/test driver,
  exercising the shared sources at USize32 and USize64, including bounds
  failures and custom destructor counts. Native emitted code is not ASAN
  instrumented; the compiler, driver and ordinary C suite are.

**** Reference-rebinding conformance fix

  The interpreter treated every borrowed assignment as a write through the
  existing pointer, cloning an aggregate RHS into the old pointee. It now
  distinguishes a source ref declaration from borrowed parameters/captures,
  retargets the reference for reference/field/ref-returning-call sources, and
  preserves foreign-borrow bookkeeping and the actual field storage width.

  The shared ownership pass had two related defects: it inserted a destructor
  for the old pointee before a ref rebind, and it omitted owners acquired by
  later rebindings from the borrow graph. Reference assignments now stand down
  value-replacement deletion. Scoped storage-identity loan edges retain the
  new owner (including chains through nested blocks), without incorrectly
  retaining already-consumed constructor inputs. Typer provenance is updated
  for subsequent mutability checks and rejects shorter-lived local sources.

  test/reference_rebinding.til replaces the C/FASM-only workaround and runs in
  the ordinary interpreter/C suite and the FASM driver at both USize widths.
  It covers owned pointees, snapshots, repeated and loop rebinding, shadowing,
  field places, a getter evaluated once, scalar write-through and owner lifetime.
  The escape and read-only fixtures check unsafe cases before code generation.

  Verification on master base ~9bc23073e~: ~make clean && make test~ passed
  500/500. Both FASM native drivers also passed with the ASAN compiler and
  driver; emitted native assembly is not ASAN-instrumented.

**** Persistent module and namespace globals

  On base ~8fafc8219~, supported globals now have writable executable storage,
  with stable scalar/aggregate addresses and pointer slots for references/raw
  allocations. Initializer temporaries stay on their frames. The emitter indexes
  all globals before emitting functions/initializers, so calls can read and
  mutate persistent state. Parameter/local binding replaces all global storage
  flags when shadowing; the aggregate differential driver caught a stale-address
  flag on a scalar parameter and now passes with this corrected binding.

  Literal initialization precedes namespace runtime initialization; namespace
  members use ~ns_const_eval_order~, and ordinary module initializers retain
  canonical dependency order. Shared units in diamond imports execute once.
  CLI roots and script roots both participate. Reassignment preserves shared
  old-value cleanup and custom deletes; globals are not destroyed on returning
  from an initializer and no process-exit cleanup policy is introduced.

  ~test/fasm_runtime.til::check_globals~ compares identical CLI/script, imported,
  reference/raw-pointer and namespace-dependency sources through interpreter,
  C and FASM at USize32/USize64. It exercises persistent heap strings, aggregate
  fields/returns/replacement, destructor counts, recursion, scalar/aggregate-name
  shadowing and narrow writes. ~test/fasm_options.til~ covers assembler-free
  emission and unsupported global-type diagnostics.

  The frontend's eager namespace evaluation still limits defaults involving
  runtime allocation or not-yet-bound module state. An initial allocating
  namespace-default probe failed in the interpreter's native registration
  (and during C preparation), before FASM emission. A separate probe where a
  shadowing parameter calls a global-reading function returned 200 rather than
  C's 111 under interpretation: the interpreter found the caller's shadow.
  The shared fixture checks shadowing without that dynamic-lookup shape; a
  separate C/FASM-only fixture pins the correct 111 result. Neither
  frontend/interpreter limitation is claimed fixed by this backend change.

  The runtime allocation-failure check also now asserts the current C/USize32
  cage diagnostic explicitly; FASM's syscall allocator and C/USize64 retain
  their null-return checks. Native assembly is not ASAN-instrumented.

  Verification: ~make clean && make test~ passed 515/515 on this base, including
  the assembler-free options and installed-compiler tests. Both optional native
  drivers passed against the freshly built ~bin/til~, exercising both USize
  widths. These runs used master's current non-ASAN test configuration (#464).

**** Enum lowering

  On base ~c721fbbf2~, FASM now supports tag-only enums, tagged payloads and
  borrowed/owned niche representations. Tag widths, explicit values, variant
  identity and payload layout come from shared definitions/target queries.
  Niche discrimination maps null/non-null to the actual declared variants,
  including a Some-first enum with explicit nonzero tags.

  Enum constructors move inline payload contents or retain the niche pointer
  according to shared ownership. get_payload/deref distinguish inline union
  storage, tagged borrowed-pointer slots and niche payload pointers. Switches
  emit native dispatch over the prepared arms; nested patterns/guards retain
  their common lowered control flow. Payload aliases are write-through places,
  and namespace constants are not field places that retarget a reference.

  Namespace methods are indexed for EnumDef as well as StructDef. Generated
  clone/delete/eq/cmp/to_str bodies run normally, rather than duplicating their
  resource semantics in a second runtime. Precomputed enum values (including
  clone-wrapped values and owned-niche array elements) are immutable templates
  cloned through those methods. The internal aggregate address/boxed-return
  convention applies to enum calls; no external enum ABI is introduced.

  ~test/aggregate_control.til::check_enums~ is shared by interpretation/C and
  the native FASM driver at both USize widths. It covers explicit/wide tags,
  narrow and Bool/USize payloads, returned enums, payload mutation, nested and
  multi-pattern matches, scalar ranges and loop exits, enum-valued fields,
  ref payloads, Option unwrap/take, independent tagged/owned-niche templates,
  and custom payload destructor counts across clone, replacement and transfer.
  The existing options test translates this expanded corpus without FASM.

  Investigation also exposed common lowering limitations, not fixed here:
  switching directly on a side-effecting enum-returning call with a payload
  binder called it twice under both interpretation and C. The fixture binds
  the result before switching and verifies one call. Assigning a namespace
  variant through a normal enum reference also exposed C's retargeting branch
  after old-payload deletion; an owning array element can then retain a freed
  payload pointer. The shared template test uses the Array.set value-replacement
  path instead. FASM's field-place classifier now excludes namespace constants;
  this does not claim to repair the C emitter or shared call reevaluation.
  These defects are now tracked separately as [[./465.org][#465 (scrutinee reevaluation)]]
  and [[./466.org][#466 (stale payload after C reference assignment)]].

  Verification: ~make clean && make test~ passed 517/517, including the expanded
  shared corpus and assembler-free translation. Both optional FASM native/runtime
  drivers passed against the fresh ~bin/til~ at both USize widths. These runs
  used master's current non-ASAN test configuration (#464); native assembly is
  not ASAN-instrumented.

**** Indirect calls and closures

  On rebased base ~b114fe56c~, FASM now materializes callable values and executes
  indirect calls through parameters, locals, fields and globals. Descriptors
  use four native words (code/env/drop/clone). Static functions have shared
  read-only descriptors/cells; capturing functions and Body values have owned
  descriptors and environments. Prepared bodies are addressed by canonical AST
  routes, with local/capture signature metadata retained for ABI selection.

  The hidden environment travels in R10 and is saved before any nested call;
  explicit runtime arguments retain the existing six-register budget. Mutable
  callable parameters and ref-callable results use descriptor cells. Ordinary
  scalar/aggregate/ref results preserve their existing native convention.
  Ref captures alias their source; shallow/own captures use private boxes.
  Generated drop/clone functions invoke actual capture lifecycle methods, and
  the native runtime implements closure/cell clone, take, pop and deletion.
  Replacement evaluates/copies the new callable before old-value cleanup.

  Two shared root causes surfaced in the resource tests during development:

  - Callable-returning factories could auto-shallow an input such as Counts,
    then return an environment whose owned Tracked capture still referenced
    that dead stack copy. Factories and their signature contracts retain the
    ordinary borrowed-input ABI. Return summaries now include captured into-
    storage and carried relationships, including moved aggregate carriers.
    This complements the retained-parameter protection from #467 already on
    the rebased master, including consistent bodyless factory signatures.
  - An immediately invoked owned factory result had no owner for cleanup.
    The hoister now names that callee before processing argument expressions,
    allowing the existing garbager to destroy its environment after the call.
    Immediate Dynamic casts retain their borrowed invocation context.

  ~test/aggregate_control.til::check_callables~ compares interpreter/C/FASM at
  both USize widths: inferred/named/static values, field/parameter calls,
  returned factories, six arguments, aggregate/ref results, mutable callable
  parameters/cells, ref/shallow/own captures, nested Body captures, static array
  templates, cloned private state and custom payload destructor counts. It
  checks evaluation order and immediate-call destruction. ~fasm_runtime~ also
  covers global replacement and copying through a borrowed parameter, plus
  native C/FASM raw callable slot operations/casts. Raw cells do not use the
  interpreter's typed-container ownership bookkeeping and are native-only tests.

  ~fasm_options~ checks a supported native runtime function as a callable;
  an explicit native probe prints through that descriptor. C currently fails
  the corresponding direct print_single value probe because its static closure
  descriptor is not emitted, so the three-way corpus uses an ordinary til print
  wrapper. This change does not add arbitrary foreign-function callbacks,
  dynamic method/reflection lookup, a public closure ABI or JIT execution.

  The shared factory ABI/hoisting changes are verified through a two-pass
  self-build; the final commit uses the Two-pass prefix for integration.
  After rebase, ~make clean && make test_two_pass~ passed 536/536 with master's
  current non-ASAN suite configuration (#464). Both optional FASM drivers passed with
  the self-applied compiler at USize32/USize64. The expanded shared corpus also
  passed a focused C ~--asan --usize=64~ run with no sanitizer diagnostics.

**** Unboxed aggregate call ABI

  On base ~01dc23183~, FASM non-ref aggregate results use caller-provided
  storage in RAX, saved before parameter/environment setup. Constructors and
  enum values use frame storage; direct/indirect calls, static templates,
  clone methods and bodyless runtime thunks follow the same result convention.
  Str capacity/clone/view/substr/from-C, format, integer formatting and file-read
  producers fill caller descriptors and allocate only their payload buffers.

  Ordinary own aggregate parameters borrow the outer slot while consuming its
  contents. A real heap argument outer is released by the caller after the
  call. Lifecycle functions save R11 outer ownership, allowing computed
  call_free values and indirect/forwarded destructors to keep their behavior
  without freeing frame addresses or requiring temporary call boxes. The R10
  closure environment and six explicit argument registers remain intact.
  Returning an owning lifecycle parameter copies into the result buffer and
  releases its original heap outer when present; a counted probe pins one
  explicit allocation and one free at either width.

  Actual persistent ownership (own fields, owned-niche payloads, private
  captures, raw/opaque escaping storage) retains allocated storage. Its clone
  helpers allocate the final owned destination directly. This change does not
  combine closure allocations or implement interfaces; it removes the
  transient aggregate allocate/copy/free convention.

  ~fasm_runtime::check_unboxed~ compares semantics at both widths, then counts
  native malloc/free calls using a temporary instrumented copy of ext.fasm.
  The pair/inline-enum/six-argument indirect-call probe goes from 9 allocations
  with the baseline boot emitter (USize32) to 0 at either width. View/empty-Str
  paths allocate 0; numeric formatting allocates/frees only 1 character buffer.
  ~aggregate_control~ additionally checks a capturing six-argument function
  returning a heap-buffer-owning record, preserving both hidden inputs.
  Details and measurement limits are in ~doc/optimizations.org~; the ABI is
  documented in ~doc/self.org~.

  FASM integration drivers passed at USize32/USize64, including the allocation
  counters and lifecycle forwarding. The expanded shared corpus and the new

**** Consolidated closure storage

  On base ~4a621551f~, capturing functions and Body values allocate a single
  descriptor/environment/private-value block. The existing four-word callable
  handle and R10 invocation contract remain intact. Private scalar, aggregate
  and callable cells live inside the block; borrowed captures retain their
  addresses, and moved heap owners/owned opaque pointers retain independent
  storage. Clone callbacks return a complete block, writing aggregate clones
  and nested callable cells directly into their final destinations.

  Drop distinguishes inline private storage from independently owned captures,
  preserves custom delete call_free branches via the existing R11 ownership
  bit, and frees the closure block once. Pointer-table entries allow heap-owner
  identity to survive without additional capture boxes or per-instance layout
  metadata. Private area can be unused for a moved heap owner; the clone uses
  that reserved area instead of allocating another outer box.

  ~fasm_runtime::check_closure_allocations~ verifies exact malloc/free counts
  at both widths: private captures 8 -> 2, borrowed captures 4 -> 2, custom
  resource captures 6 -> 2, nested closures 12 -> 4, a heap-owned capture 3 -> 2,
  and independently mutable owned strings 8 -> 4. Details and paired baseline
  runtime methodology are recorded in ~doc/optimizations.org~. The string probe
  also pins destination preservation across USize32 runtime size macros.

  The custom clone/delete probe compares native C/FASM: before these changes,
  the interpreter copied captured records without calling their custom clone
  hook. The remaining allocation probes compare all three execution paths.
  Verification: ~make clean && make test~ passed 558/558, both FASM drivers
  passed at USize32/USize64, and ~aggregate_control~ plus all six new probes
  passed focused C ~--asan --usize=64~ checks without sanitizer diagnostics.
  Native emitted assembly is not ASAN-instrumented.

  Differential testing against C and interpretation is a primary motivation.
  Selective future JIT execution could amortize compilation for expensive or
  repeated work. In-process code allocation, relocation, lifetime management
  and interpreter/native value boundaries are separate future work; JIT is
  not required to complete this initial backend, nor a wholesale interpreter
  replacement.

   Subsequent direction is tracked separately in [[./474.org][#474]]: FASM is a base
   for native JIT work, with eventual replacement of AST interpretation rather
   than only selective acceleration. TempleOS uses its HolyC compiler for the
   native JIT. Our own reduced MLIR-style JIT and eventual retirement of the
   required GCC/Clang toolchain are later milestones; the standalone FASM
   backend need not wait for that full migration.
