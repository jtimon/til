** WIP #151 TempleOS target

:DEPENDENCIES: [[../fixed/12.org][#12]]

  Add a TempleOS target. This is not part of the hosted 32-bit target
  work anymore: TempleOS is a separate toolchain, runtime, filesystem,
  graphics, and testing environment.

  The old broad 32-bit scope was split:

  - Hosted 32-bit Linux/Windows targets are tracked in [[./232.org][#232]].
  - Browser WASM is tracked in [[./228.org][#228]].

*** Scope

  - Emit or translate til programs to HolyC or another TempleOS-native
    representation.
  - Replace POSIX/Windows runtime assumptions with TempleOS primitives.
  - Implement ~mode gui~ on TempleOS using native graphics rather than
    raylib.
  - Define a QEMU-based test loop using a TempleOS VM image.

*** Notes

  TempleOS has no normal C compiler path comparable to the Linux,
  Windows, or browser targets. Treat it as deferred platform work, not
  as one more clang cross target.

*** Direction

  Translation stays on the Linux host: Linux til loads, types, lowers,
  and emits a HolyC source file. TempleOS receives only that generated
  source plus its TempleOS-native runtime support, then its own compiler
  compiles and executes the program. A host-side HolyC implementation is
  not the acceptance environment.

  Share the frontend and semantic analyses, not the textual emitter. HolyC
  receives the same typed, lowered, ownership-annotated, constant-folded, and
  scavenged AST as C. It should also reuse target-width resolution, callable
  and type queries, definition dependency ordering, and core-operation
  classification where those describe til semantics rather than C spelling.

  Keep textual emission in a dedicated ~holyc_codegen.til~ backend, following
  the builder boundary already used by the JVM backend. The regular C emitter
  assumes libc headers and ~ext.h~, typedefs/unions, the C pointer ABI, GNU
  statement expressions, compound literals, ternaries, attributes, libc
  allocation/memory/output, C entrypoints, libffi, and C-specific helper
  reachability. Passing a dialect flag through those paths would spread
  backend conditionals across the most ownership- and evaluation-order-
  sensitive parts of ~c_codegen.til~. A ~HolyCEmitState~ should instead own
  HolyC feature requirements and runtime-helper reachability; do not put a
  dialect flag in the frontend ~Context~.

  Extract target-neutral pieces from the C backend only when HolyC needs them.
  In particular, separate scope-pointer refresh and symbol registration from
  the C-only emit inventory, and separate aggregate dependency ordering from
  C struct/union syntax. Preserve the same logical til object and ownership
  model where TempleOS can implement it, but use TempleOS-native runtime
  functions and ABI decisions at the external boundary.

  TempleOS is x86-64-only with 64-bit pointers. The current
  ~TempleosX86~ target is excluded from ~target_is_32bit~, so UPtr is U64.
  USize follows the source alias (currently U64) or the existing
  ~--usize=32/64~ override, independently of UPtr.

*** HolyC ABI and runtime contract

  ~src/holyc/ext.HC~ is the TempleOS-native external boundary. Generated
  programs include it from the fixed guest path ~/Home/Ext.HC~; host and CI
  packaging must inject that file beside the generated program. The ABI is:

  - I8/U8, I16/U16, I32/U32, I64/U64 and Bool have their HolyC widths and are
    passed and returned by value. UPtr and all raw addresses are 64-bit. The
    source-level USize width is resolved by the frontend.
  - F64 uses native eight-byte float storage. HolyC has no F32 storage type,
    so F32 uses four-byte IEEE binary32 bits with x87 widening/rounding
    helpers. Literals preserve their resolved float bits, and numeric
    conversions use conversion primitives rather than HolyC storage casts.
  - Raw pointers cross the boundary as ~U8 *~ values. Ownership changes do not
    add pointer indirection: ~TilFree~ consumes a pointer value. A slot load is
    the explicit exception and uses ~U8 **~ through ~TilDeref~.
  - Raw byte counts use U64/UPtr semantics. TempleOS primitives accept signed
    I64 counts, so the boundary rejects values above ~I64_MAX~ and allocation
    multiplication overflow rather than wrapping them.
  - ~TilMAlloc~, ~TilCAlloc~, and ~TilFree~ wrap TempleOS ~MAlloc~, ~CAlloc~,
    and ~Free~. ~TilFree(NULL)~ and zero-length memory operations are valid.
  - ~TilMemCpy~, ~TilMemMove~, ~TilMemSet~, and ~TilMemCmp~ preserve counted
    memory semantics. ~TilMemMove~ handles overlap in both directions because
    TempleOS ~MemCpy~ only copies forward; memset stores the low byte; memcmp
    preserves negative/zero/positive results.
  - ~TilRawWrite~ emits counted bytes without treating them as a format or
    requiring NUL termination. ~TilPanic~ emits counted bytes and throws the
    catchable TempleOS exception ~'TILPANIC'~. Null dereferences emit exactly
    ~panic: null deref\n~ and throw that same exception.
  - Dynamic and typed raw pointers use one native pointer word. Typed scalar
    pointer reads check for null before loading. Borrowed/owned aggregate
    fields and ref-returning functions use the aggregate pointer ABI.
  - Callable values are pointers to a four-word TilClosure descriptor:
    call address, environment, drop callback, clone callback. Static functions
    share ownerless descriptors; captures own an environment when present.
    Generated typed trampolines prepend the environment to the lowered ABI,
    retaining native out parameters for aggregate returns and pointers for
    borrowed returns. Mutable/borrowed callable slots hold a descriptor pointer.
  - ~TilStr~ matches til's three-field value (~c_str~, ~count~, ~cap~), with
    counts/capacities and literal/view sentinels matching the resolved USize.
    Generated HolyC defines that width before including ~Ext.HC~. TempleOS rejects
    class-valued function returns, so Str constructors, clones, views, and
    integer formatting initialize caller-owned stack values through explicit
    out parameters rather than heap-boxing the struct.

  ~examples/hello_script.til~ as ~gen/til/hello_script.HC~. TempleOS 5.03
  compiled and ran it with ~ExeFile2~ under QEMU TCG, reported
  ~TILTEST:PASS~ over ~isa-debugcon~, and exited through ~isa-debug-exit~.
  ~build~ and ~run~ still fail explicitly until that guest path is
  integrated.

  The second slice emits ~examples/fizzbuzz.til~, including scalar locals,
  I64 arithmetic/comparisons, mutation, conditionals, loops, literal output,
  and ~I64.to_str()~ output. TempleOS 5.03 compiled and ran that generated
  file under QEMU TCG and reported ~TILTEST:PASS~. User-defined direct calls
  were the remaining part of this incremental-plan item.

  The third slice emits ~examples/templeos_calls.til~ with scalar parameters,
  return values, forward declarations, function definitions, and direct calls.
  TempleOS 5.03 compiled and ran it under QEMU TCG and reported
  ~TILTEST:PASS~.

  The fourth slice moves all HolyC textual emission into
  ~src/self/holyc_codegen.til~. The builder dispatches directly to that
  backend, and ~HolyCEmitState~ records user functions and I64 div/mod helper
  requirements instead of searching generated text. All HolyC goldens remain
  byte-identical. The current subset consumes no C-only preparation analysis,
  so none was extracted prematurely; shared analyses will move only when a
  HolyC feature needs them.

  The fifth slice makes the scalar subset match TempleOS register semantics.
  Narrow arithmetic explicitly wraps and sign-extends instead of relying on
  HolyC local declarations to truncate; C-style prototypes become HolyC
  ~extern~ declarations; unsupported ~continue~ and F64 fail explicitly.
  ~examples/templeos_scalars.til~ covers every integer width, signed and
  unsigned overflow, shifts, Bool, div/mod by zero and nonzero divisors,
  comparisons, bitwise operations, and nested calls. TempleOS 5.03 compiled
  and ran the generated file under QEMU TCG and reported ~TILTEST:PASS~.

  The sixth slice adds ~src/holyc/ext.HC~, installs it with compiler support,
  and makes every generated program include its fixed guest path. The runtime
  wraps allocation, counted and overlap-safe raw memory, counted output,
  pointer checks, and catchable panic/null-deref behavior under the contract
  above. Til-level pointer calls remain unsupported until Dynamic lowering is
  implemented. TempleOS 5.03 passed a direct boundary probe covering widths,
  allocation, zeroing, copy/compare, both overlap directions, low-byte memset,
  null-free, counted output, slot dereference, panic, and null dereference;
  the generated scalar corpus also reported ~TILTEST:PASS~ with the runtime
  prelude and include in place.

  The seventh slice emits all surviving functions and top-level initialization
  from every user unit in deterministic dependency-first order. Namespace
  imports are already lowered to direct identifiers by the frontend, so one
  prototype pass across all units supports forward and cross-unit calls without
  a backend-specific reachability graph. Retained import directives are skipped
  as compile-time statements. C's three ~ext.c~-only scavenger roots are now
  gated to C outputs; HolyC continues to own only its ~Ext.HC~ runtime boundary.
  ~examples/templeos_calls.til~ now calls a function from
  ~templeos_calls_helper.til~ after running that imported unit's top-level
  initializer. TempleOS 5.03 compiled and ran the generated two-unit output
  under QEMU TCG and reported ~TILTEST:PASS~.

  The eighth slice adds per-body pointer binding state so a typed allocator
  local stores an address but reads through ~TilCheckPtr~, while Dynamic and
  ~ref Dynamic~ bindings carry one pointer word. ~malloc~, ~calloc~,
  ~realloc~, ~free~, ~memcpy~, ~memmove~, ~memset~, ~memcmp~, ~ptr_add~,
  ~ptr_eq~, ~is_null~, ~deref~, ~write_ptr~, and ~to_ptr~ lower explicitly to
  HolyC expressions or ~Ext.HC~ entrypoints. Scalar arguments used as raw
  memory sources pass their address instead of being mistaken for pointers.
  ~TilReAlloc~ preserves bytes with TempleOS ~MSize~ and ~TilWritePtr~ owns
  pointer-slot mutation. The existing ~test/script_raw_alloc.til~ and
  ~test/script_dynamic_free.til~ sources now serve as HolyC translation
  fixtures without backend-specific source copies. Both ran under TempleOS
  5.03 and reported ~TILTEST:PASS~; a self-checking guest probe also covered
  calloc, overlap-safe memmove, memcmp, realloc, null tests, pointer equality,
  and ~to_ptr~. Pointer-bearing aggregates and pointer function interfaces
  remain explicit unsupported shapes for later slices.

  The ninth slice introduces the native three-field ~TilStr~ value and
  out-parameter runtime operations for literals, owned clones, capacity-backed
  mutation, substr/borrowed/trim views, deletion, comparison, signed integer
  parsing/formatting, and counted output. The existing lowered one-element
  ~println~ scaffold now builds and writes a real Str instead of treating its
  contents as a TempleOS format string, so embedded NUL bytes and percent signs
  remain data. ~test/script_str_runtime.til~ is shared unchanged by the
  interpreter, C backend, and HolyC translation; TempleOS 5.03 compiled and ran
  it with ~TILTEST:PASS~. A guest self-check additionally covered clone buffer
  independence, view pointer identity, prefixed integer parsing, and I64_MIN
  formatting. Real ~Array(Str)~ execution follows in the eleventh slice.

  The tenth slice makes Str replacement alias-safe by initializing the new
  value before deleting the old payload, matching the C backend's ordering for
  assignments such as ~s = s.substr(...).clone()~. User functions pass shallow,
  mutable, and owned Str parameters as ~TilStr *~ and return Str through a
  caller-owned out parameter because TempleOS cannot return class values.
  Returning a literal converts its cap sentinel to a non-owning view, and
  deleting an owned parameter frees its payload but never its caller-owned
  stack wrapper. The expanded shared ~test/script_str_runtime.til~ covers all
  of these paths; TempleOS 5.03 and a self-checking guest probe both reported
  ~TILTEST:PASS~.

  The eleventh slice replaces the one-element ~println~ shape matcher with a
  real ~TilStrArray~ value: zeroed fixed-capacity element storage, bounds-
  checked ownership-transferring set, element/payload teardown, and consuming
  ~print~/~println~ operations. The shared Str runtime script now includes a
  four-part println assembled through ordinary lowered ~Array(Str)~ operations.
  TempleOS 5.03 compiled and ran that generated program with ~TILTEST:PASS~;
  the self-checking guest probe also verified that print consumes the array,
  moved element temporaries are empty, and cloned source strings remain owned.

  The twelfth slice starts general aggregates with POD/value structs. HolyC
  ~class~ definitions are emitted in stable inline-field dependency order,
  independent of source declaration order. Constructor calls recursively
  initialize caller-owned destinations, including nested constructors, without
  class returns or compound literals; scalar fields support nested reads and
  direct assignment. ~test/script_struct_runtime.til~ is shared by the
  interpreter, C backend, and HolyC translation, and deliberately declares its
  outer struct before its inline dependency. TempleOS 5.03 compiled and ran it
  with ~TILTEST:PASS~; a self-checking guest probe verified every nested field.
  Ref/pointer-bearing aggregates remain in the unchecked aggregate milestone.

  The thirteenth slice adds managed Str fields and value-struct function ABI.
  Generated recursive clone/delete helpers preserve nested aggregate ownership,
  and field replacement initializes the new Str before deleting the old value.
  Struct parameters use pointers and struct returns use caller-owned out
  parameters, avoiding HolyC class-valued returns. The expanded shared
  ~test/script_struct_runtime.til~ exercises dynamic managed-field construction,
  function parameters, a non-folded struct return, clone independence, field
  replacement, and recursive deletion. The interpreter, C backend, and HolyC
  translation passed the shared test; TempleOS 5.03 compiled and ran the
  generated output with ~TILTEST:PASS~.

  The fourteenth slice adds recursive value-struct equality for the frontend's
  generated field-wise comparison methods. HolyC ~Type_Eq~ helpers short-circuit
  over scalar fields, use ~TilStrEq~ for managed strings, and recurse through
  nested structs; ~eq~ and ~neq~ calls pass caller-owned values by pointer.
  Custom ~eq~ or ~cmp~ methods remain explicit unsupported shapes rather than
  being silently replaced with structural semantics. The expanded shared
  ~test/script_struct_runtime.til~ covers equal and unequal nested POD and
  managed structs on the interpreter and C backend. TempleOS 5.03 compiled and
  ran the same generated program with ~TILTEST:PASS~.

  The fifteenth slice adds payload-free enums as values of their resolved
  U8/U16/U32/U64 tag type, including explicit discriminants, variant values,
  parameters/returns, ~is~, ~eq~/~neq~, and generated clone/delete operations.
  Enum switches evaluate the subject once and compare full-width tags inside
  a one-iteration block, preserving multi-pattern cases, defaults, and nesting.
  Native HolyC switches reject sparse tag ranges (the guest reported
  ~switch range error~ for tags 7 and 4294967303), so this lowering does not
  depend on HolyC's dense jump-table range. Payload enums and custom methods
  are rejected explicitly.

  The shared ~test/script_struct_runtime.til~ covers all four tag widths,
  inferred width, U32_MAX, U64 tags with identical low 32 bits, mutation,
  non-folded function returns, and single-evaluation/nested switches. Its
  U32_MAX case also exposed and fixes a shared interpreter tag-reader bug:
  four-byte unsigned discriminants were sign-extended through I32 instead of
  read as U32. Interpreter and C outputs match. TempleOS 5.03 under QEMU TCG
  compiled the same generated program with ~ExeFile2~, produced the complete
  expected output over debugcon, and reported ~TILTEST:PASS~.

  The sixteenth slice adds payload-bearing enums as tagged HolyC classes with
  inline union storage. Scalar, Str, struct, and nested-enum payloads have
  constructors, borrowed/mutable case bindings, caller-owned returns, active-
  payload clone/delete/equality, and replacement following the shared ownership
  pass. Empty variants also have addressable values for calls and comparisons.
  Struct-payload comparison eligibility reuses the shared recursive field check
  when its generated methods have not yet been materialized.

  HolyC's function-wide local names require unique payload bindings and emitter
  temporaries, including nested shadowing. Numeric widening first forces an
  rvalue: HolyC's postfix I64 cast otherwise widens the memory read of a narrow
  payload. Payload-enum sizes remain backend-resolved rather than folding the
  shared/C layout; lowered whole-value swaps use typed copies and validate their
  size against HolyC sizeof. At this stage pointer/ref payloads and custom
  lifecycle methods remained explicit unsupported shapes.

  The expanded ~test/script_struct_runtime.til~ checks independent managed
  clones after mutation/deletion, U8 and I64 payloads, empty values, nested
  payloads and shadowing, multiple return paths, and mutable-parameter/payload
  replacement. Interpreter and generated C output match. TempleOS 5.03 under
  QEMU TCG produced the same 47 lines and ~TILTEST:PASS~. The native Str/raw-
  allocation goldens also record the corrected temporary naming and widening.

  The seventeenth slice adds pointer-bearing aggregate storage: required ref
  fields borrow their pointees, own fields allocate and recursively clone/free
  boxed values, and field replacement initializes its new value before tearing
  down the old box. Ref-returning functions, borrowed aggregate/scalar
  parameters, mutable scalar parameters, and typed malloc-backed struct values
  use pointer ABI throughout. Stack-owned function parameters never free the
  caller's wrapper on delete, even if the C ABI passes a free flag. Generated
  struct helpers accept a call-free flag for owned heap boxes. Class definitions
  order cross-type pointer fields after their targets; self-references need no
  forward class declaration (which HolyC rejects).

  ~Option(ref T)~ niche values carry one borrowed pointer, including nullable
  recursive fields, Some/None construction, is_some/is_none and checked unwrap.
  Multi-variant enum ref payloads store and clone the pointer without owning
  the pointee; generated equality compares pointee values, including distinct
  pointers with equal contents. Borrowed struct fields and nullable refs also
  compare pointee values when the frontend generated equality. Ref payload
  bindings read through the lowered pointer slot, and their HolyC local names
  are unique across switch arms. Other niche shapes (owned boxes) and
  non-niche function-pointer payloads remain unsupported. The interpreter now
  demotes a moved literal Str in an own field from CAP_LIT to CAP_VIEW: the
  characters remain static, while deleting the owned heap wrapper no longer
  leaks it.
  The shared ~test/script_struct_runtime.til~ exercises these paths, including
  forwarding and self-referential classes, in the interpreter and C backend;
  TempleOS 5.03 under QEMU TCG produced the same 65 output lines and
  ~TILTEST:PASS~.

  The eighteenth slice adds typed ~Array(T)~ and ~Vec(T)~ lowering alongside
  the existing ~TilStrArray~ print runtime. Specializations come from the
  frontend's typed AST and existing type-generation sources, including nested
  collections; no new persisted type registry is needed. HolyC emits typed
  contiguous element storage and native helpers for constructors, checked and
  unchecked get/set, deep clone/delete, Vec push/pop/clear, grow, append,
  remove, truncate, take/take_prefix, move and marked compaction, and Array
  concat/to_vec. Ownership-transferring writes clear moved-from aggregate
  slots, while zeroed own-field slots are valid during Array clone/delete.
  ~Array(Str)~ keeps its existing representation and gains clone, checked get,
  concat and to_vec; aggregate parameters and caller-owned returns work for
  both collection representations. Checked accesses set the shared error slot,
  and a tested out-of-bounds guest call throws with the expected message.

  The expanded shared ~test/script_struct_runtime.til~ covers scalar, Str,
  struct, payload-enum and nested-Vec elements with host interpreter/compiled
  C parity. TempleOS 5.03 under QEMU TCG produced the same 80 output lines and
  ~TILTEST:PASS~. Dynamic/F64 elements and custom aggregate lifecycle remain
  unsupported by this HolyC subset. A zeroed Array of a struct with an own
  POD field also still hits the host C backend's own-field clone value/pointer
  mismatch; it needs a shared compiler fix before it can join the guest corpus.

  The nineteenth slice adds ordered ~Map(K, V)~ and ~Set(T)~ lowering for
  scalar and Str keys/elements. Map uses the frontend's two aligned typed
  Vec fields; Set uses sorted contiguous storage. Generated helpers implement
  binary-search lookup, sorted insertion and removal, duplicate Set handling,
  Map overwrite, pre-sizing, clear, deep clone, and ownership-aware delete.
  Map values include scalar, Str, struct, and nested Vec types; specializations
  use the already-lowered storage field types, including nested type names.
  The shared ~test/script_struct_runtime.til~ checks literals, mutations,
  misses, overwrites, deep clone independence, pre-sizing, and nested values
  in the interpreter and compiled C. TempleOS 5.03 under QEMU TCG produced
  the same 102 output lines and ~TILTEST:PASS~. Aggregate keys and custom
  comparison methods remain outside this slice.

  The twentieth slice extends Map keys and Set elements to comparable value
  structs and enums. Their generated comparison methods run from the shared
  lowered AST, including nested struct fields; user-defined ~cmp~ methods and
  the namespace methods they call use the same function emitter. Method
  declarations precede collection helpers, while definitions follow the
  ordinary function prototypes so custom comparators can call user functions.
  Generated payload-free enum comparison uses variant declaration order, even
  when explicit tag values are out of order; payload enums compare active
  scalar and Str payloads. Custom enum comparators can override tag order.
  Aggregate insertion and duplicate Set disposal retain the shared ownership
  behavior, and borrowed enum keys use their concrete tag width. The expanded
  shared ~test/script_struct_runtime.til~ exercises
  generated, nested, and custom comparisons on both Map and Set, including
  deep cloning, replacement, removal, and enum order. TempleOS 5.03 under
  QEMU TCG produced the same 118 output lines and ~TILTEST:PASS~.

  The twenty-first slice begins native filesystem support with
  ~File.exists~ / ~cfile_exists~. HolyC calls a TempleOS ~FileFind~ wrapper
  that copies the counted Str path to a NUL-terminated temporary, so a
  substring view cannot expose trailing bytes as part of the filename.
  Imported external declarations are not emitted as HolyC functions;
  unsupported external calls still fail explicitly. The shared
  ~test/script_str_runtime.til~ now checks existing files and directories,
  absent files, and non-NUL-terminated views. It uses the existing
  ~src/holyc/ext.HC~ on the host and the injected ~/Home/Ext.HC~ in the
  guest. Interpreter and compiled C output match; TempleOS 5.03 under
  QEMU TCG produced the same 13 lines and ~TILTEST:PASS~.

  The twenty-second slice adds ~File.readfile~ using TempleOS's native
  whole-file ~FileRead~: there is no persistent handle to close, and its
  allocated, NUL-terminated bytes become an owned, counted Str freed by
  ordinary Str teardown. The path is copied from counted Str storage so
  substring views work, and unrepresentably large files and failed reads
  throw rather than returning partial or empty content. The shared
  ~test/script_str_runtime.til~ reads the same ~ext.HC~ bytes on host and
  guest, checking the prefix and byte count. Interpreter and compiled C
  output match; TempleOS 5.03 produced the same 15 lines and
  ~TILTEST:PASS~. A missing-file guest probe emitted
  ~cfile_open: could not open 'missing.HC'~ and ~TILTEST:FAIL~.

  The twenty-third slice adds ~File.writefile~ through TempleOS's native
  whole-file ~FileWrite~. Its counted Str path is NUL-terminated before the
  call, while content is passed with its byte count, including embedded NULs.
  A zero result reports a failed write and throws with the path; the native
  whole-file operation needs no persistent handle. The shared
  ~test/script_str_runtime.til~ writes a longer file, replaces it with
  three binary bytes, then writes an empty file and reads both results back.
  A parent-directory preflight preserves the host API's failure behavior:
  TempleOS ~FileWrite~ would otherwise create missing parent directories.
  Interpreter and compiled C output match; TempleOS 5.03 under QEMU TCG
  produced the same 18 lines and ~TILTEST:PASS~. An invalid-name guest
  probe emitted ~File.writefile: could not write 'bad?.HC'~ and
  ~TILTEST:FAIL~. A missing-parent probe likewise failed without creating
  ~BADDIR~ on the guest disk.

  The twenty-fourth slice adds ~File.is_file~ and ~File.is_dir~, with their
  existing ~cpath_is_file~ / ~cpath_is_dir~ primitives. The TempleOS
  ~FileFind~ wrapper now shares counted-path conversion among all three
  lookup operations and applies ~FUF_JUST_FILES~ or ~FUF_JUST_DIRS~ for
  kind-specific queries. The shared ~test/script_str_runtime.til~ checks
  file, directory, wrong-kind, missing, and substring-view paths through
  both public and primitive calls. Interpreter and compiled C output match;
  TempleOS 5.03 under QEMU TCG produced the same 24 lines and
  ~TILTEST:PASS~.

  QEMU TCG, mtools, fdisk, curl, and Expect via ~test/templeos.Dockerfile~;

*** Milestone 2: basic filesystem workflows

  File/Dir namespace methods now use the shared lowered method bodies,
  including custom teardown and ref-returning chains. The HolyC backend
  records their parameter/return ABI, emits class definitions before method
  prototypes, and preserves source scopes with unique function-wide local
  names. Generated nested lifecycle helpers remain available even when the
  frontend scavenged their unused namespace definitions.

  The native runtime implements read/write, append, and update handles with
  byte cursors over TempleOS CFile block I/O. It supports partial and whole
  reads, tell, absolute/current/end-relative seek, append-after-seek, sparse
  zero filling, immediate creation/truncation, and close. FAT32 grows its
  cluster chain; RedSea grows contiguous storage while preserving existing
  bytes. Sector staging keeps counted writes within their source buffers.

  Directory handles own native entry snapshots, return owned names, skip
  dot entries, and release the snapshot on close. The standard Dir.list
  body uses this iterator. Native mkdir_p, file removal, recursive tree
  removal, and replacement rename cover complete workflows. Rename stays
  on one drive and follows TempleOS copy-and-delete semantics, not POSIX
  atomic replacement; it preserves raw .Z bytes and supports directory
  moves onto absent or empty destinations.

*** Milestone 3 follow-up: raw scalar assignment and float text I/O

  A typed raw-allocation assignment crashed the interpreter while compiled C
  executed it correctly. The primitive assignment arm excluded raw allocation
  bindings and installed the scalar's bits as their pointer. It now writes
  through the existing allocation, matching C, while Dynamic assignments keep
  pointer-transfer semantics. Raw write-through requires its live allocation;
  it does not silently manufacture storage after consumption. The shared
  ~test/script_raw_alloc.til~ regression covers F32/F64/I64 values, borrowed
  RHSs, call results, local bindings, and explicit deallocation under ASAN.

  F32/F64 ~to_str~ and ~to_repr~ initialize owned Str values with the same
  general-format output as C's %g: six significant digits for ordinary text,
  nine for binary32 repr, seventeen for binary64 repr, round-to-nearest/even,
  and matching fixed/scientific notation and trailing-zero removal. Special
  values preserve the signs of zero, infinity, and NaN.

  ~Str.to_f32~ and ~Str.to_f64~ preserve the current core parser contract:
  separator removal, counted/NUL-bounded input, decimal/scientific and hex
  input, whitespace/signs, infinities/NaNs, numeric prefixes, and overflow/
  underflow. Finite decimal conversion compares exact base-10^9 expansions
  against positive IEEE bit patterns and their adjacent-value midpoint;
  hexadecimal conversion rounds the significand with guard/sticky bits.

*** Milestone 4: callable values, closures, and metadata

  HolyC emits typed adapters for function values and indirect calls from the
  shared FuncSig contracts. Capturing FuncDefs and Body values initialize
  environment records with borrowed addresses or owned/private storage;
  generated clone/drop callbacks preserve those modes. Callable values travel
  through parameters, returns, struct fields, enum payloads, and the existing
  dynamic containers' callable-slot operations. Temporary capturing arguments
  are released after borrowed calls, and reassignment clones borrowed callable
  sources before their hoisted temporaries are destroyed.

  The initial dyn_fn implementation resolves counted type names and statically
  identified method names to generated descriptors with the existing
  erased-method ABI. Clone/delete/cmp
  adapters bridge ordinary element
  storage to dynamic callers. dyn_has_method, dynamic size/storage-kind queries,
  Type rendering, and struct/enum/FuncSig metadata primitives are emitted from
  loaded definitions into the existing HolyC output; no separate metadata file
  or persistent registry is introduced.

  Shared acceptance exposed and fixed existing host-path bugs: C captured
  aggregates were emitted as values but selected with ->; script-global capture
  values were mistaken for function definitions; callable assignment could
  retain a hoisted temporary's descriptor after its deletion. Interpretation
  now invokes language destructors for owned capture payloads, preserves static
  function-pointer slots when converting from Dynamic, and refreshes payload /

  aggregate payload destructors without freeing the outer slot; environment
  cleanup then releases that slot once. FuncSig reflection excludes lowered

*** Callable follow-up: mutable slots, borrowed returns, and runtime lookup

  dyn_fn accepts runtime method names. The shared scavenger and C emit inventory
  expand those lookups over otherwise reachable types, constrained by the
  destination FuncSig. HolyC uses the same signature matcher and generates typed
  adapters through its ordinary function/method emission. Erased collection
  signatures retain their element-data ABI. Literal names and counted string
  views enter the same lookup; missing methods fail at the lookup site.

  Mutable callable parameters pass the caller's descriptor slot in C and HolyC.
  Borrowed callable returns keep that slot rather than cloning its current
  descriptor. Shared declaration inference uses a returned callable's signature,
  not the signature of the callback that returned it. The garbager owns the
  old-descriptor cleanup decision when a mutable parameter replaces a callable.

  Interpreter callable slots retain stable storage through delete/reassignment.
  Borrowed aliases can update that storage, so callable ownership metadata is
  refreshed from the slot and raw teardown inspects the current descriptor.
  This avoids both stale static-callable flags leaking replacements and borrowed
  returns accidentally owning private clones.

  The shared aggregate corpus now produces 164 lines. Added checks cover direct
  and indirect mutable callable parameters, replacement through a borrowed
  callable return (including immediate invocation), nested owned callable
  captures cloned in DynVec, user
  destructor counts on replacement/deletion, runtime method changes, counted
  method-name views, and literal typed lookup. The native runner adds a missing
  runtime method failure at each USize width. The clean hosted ASAN suite passes
  458/458 (including clang validation); TempleOS passes all 55 cases at USize
  32/64. The aggregate and collection checklist entries above now reflect the
  completed guest coverage.

*** CLI translation and future compiler/application milestones

  Mode cli emits a loadable HolyC module. Its global declarations and
  dependency-ordered initialization are outside the source main function, and
  functions receive the same global binding/type information. TilMain exposes
  the source main's lowered typed signature; it is not automatically called.
  This avoids inventing an empty argv or a host command-line convention.

  For example, translating examples/cli_typed.til produces an entrypoint
  ~U0 TilMain(TilStr *name, I64 count)~. After loading the generated module in
  TempleOS, a native caller can construct a TilStr and call
  ~TilMain(&name, 42)~. A ~main(args: ..Str)~ takes a TilStrArray; an integer
  result from main is returned to that caller. Source-level shell argument
  parsing, exit/task lifecycle and a general TempleOS command launcher remain
  future work, not implied by successfully translating a CLI module.

  Supported ext_func/ext_proc signatures retain extern declarations, with no
  empty substitute body. Target-selected host C source/link/include inputs are
  recorded as comments in the existing .HC output; they are not linked by HolyC.
  This is useful for emission work on programs whose platform boundaries are not
  yet ported. The installed compiler has no new Docker or QEMU dependency. The
  previously considered Docker-backed build/run integration was set aside;
  Docker/QEMU remains the repository's explicit guest acceptance machinery.

**** Keyboard follow-up: held keys across focus changes

  differ from the task that received the press. Message-only held state left
  IsKeyDown stuck after switching tasks and releasing the key elsewhere.

  between polls. Physical state only removes stale holds; a background-held key
  does not turn into a new GUI press on refocus. IsKeyReleased observes the

  examples/gui_mouse.til selects either pane with a left click, drags a cell
  selection, resets it with a right click, and exits with Enter/Escape. It uses
  the existing GetMouseX/Y/Position and IsMouseButtonDown/Up/Pressed/Released
  facade. Position is sampled per frame in client coordinates; Vector2 retains
  its two-F32 layout. Out-of-client coordinates remain signed rather than being
  clamped to the viewport.

  The native message pump now handles mouse messages without treating their
  coordinates as keyboard input. Left/right held state is cleared on blur and
  reconciled with physical state on refocus, including a release elsewhere
  between frames. InitWindow temporarily inhibits DolDoc mouse actions, delayed
  double-click handling and Ctrl-drag window panning; CloseWindow restores the
  previous policy. This gives the application immediate button events instead
  of moving the console cursor or generating a double-click Escape.

  This sprint supports left/right buttons. Middle/auxiliary button queries fail
  explicitly on the native target; pointer warp/scale/cursor
  APIs remain later work. Invalid button indices retain the facade's false
  result. Key/text queues remain separate from mouse frame state.

  Mouse cell arithmetic exposed missing native I32 div/mod lowering. It now
  uses the signed division helpers and narrows the result, preserving signed
  truncation and the zero-divisor rule. Bool.to_str is also lowered with the
  ordinary returned-string ownership convention. test/holyc_i32_divmod.til
  checks runtime signed div/mod, zero divisors and both Boolean spellings.

  Hosted test/gui_mouse.til drives raylib's GLFW callbacks. Native acceptance
  checks client coordinates, Vector2 ABI, holds/edges/chords, focus changes,
  same-frame taps, window-policy restoration and reopen. Real PS/2 injection
  clicks/drags both panes, checks selection pixels and calls the loaded module
  twice in one VM. Existing keyboard focus cases also run in focused verification.
  Pixel checks use visible color regions, so manually placing the native pointer
  over a probe point does not cause a false failure; injection also covers that
  hover position.

  and formatting, mouse interaction/reuse, mouse boundaries, unsupported-button

**** Wheel scrolling with the existing raylib semantics

  GetMouseWheelMove/GetMouseWheelMoveV now have native implementations. The
  current raylib behavior is preserved: the last delivered event replaces
  earlier events in the same frame, queries do not consume it, and the next
  frame with no event reports zero. For example, events +1 then +2 report +2,
  not +3. There is no sensitivity multiplier or change to the vendored raylib.
  The scalar getter keeps raylib's largest-magnitude-axis rule; native PS/2
  input is vertical, so its vector has x=0 and y equal to the scalar value.

  TempleOS delivers wheel changes through native controls rather than mouse
  messages. A temporary invisible control is installed first in the task's
  control list, so wheel input reaches the GUI instead of panning the underlying
  console. The original control list and window policy are restored on close.
  The window-manager callback records the latest event; EndDrawing transfers
  and clears it atomically for the application frame. Up is positive and down
  negative, matching the facade. TempleOS may coalesce physical ticks into one
  delivered event; the port preserves that event's amount without rescaling it.

  Pending input is discarded across observed focus loss/refocus. Task-routed
  callbacks also prevent replay of scrolling delivered to another task between
  application polls. Opening/reopening a window starts with zero wheel delta.

  examples/gui_mouse.til now scrolls three visible row labels over either pane,
  keeps each pane's row offset, and clamps to the 100-row example's bounds.
  Its fractional-row carry is application state across frames, not accumulation
  of multiple callbacks in one frame. Enter uses queued key presses so slower
  native bitmap frames do not miss a short tap. The existing manual repeat
  prompt works with the extended example.

  Hosted callback checks cover event replacement, fractional values, both axes,
  the scalar axis-selection rule, repeated queries and frame expiry. Native
  checks cover the same snapshot/ABI rules, direction, focus changes, control
  cleanup/reopen, fractional row movement and viewport bounds. Real QEMU wheel
  injection scrolls the left pane down/up and the right pane independently.

  Verification on master ee8785cb2: clean hosted ASAN suite 492/492, including
  the existing raylib callback behavior and clang validation. All 14 focused
  native cases pass at USize 32/64: four wheel cases plus the existing mouse,
  arithmetic/formatting and keyboard-focus checks. The full guest matrix was
  not rerun for this sprint.

**** Manual GUI testing in one VM

  The task worktree already has the existing ~til-templeos-test~ Docker image,
  ~tmp/templeos/TempleOS.ISO~ and FAT32 ~tmp/templeos/guest.raw~ used by the
  native tests. Use that prepared worktree for these commands. A fresh checkout
  needs the setup at the start of ~test/templeos.til~ first.

  Stop the VM before staging files. The test runner recreates ~guest.raw~ for
  each case, so it is test storage, not a place to keep personal files. Re-stage
  after native tests if they replaced the program. Hosted manual testing is just
  ~bin/til run examples/gui_mouse.til~.

  Compile the mouse example and add a guest-side repeat prompt to the existing
  generated module. This keeps the same compiled module and VM alive across
  interactions, without reloading its symbols into the task:

  #+begin_src sh

  cp src/holyc/ext.HC tmp/templeos/Ext.HC

  Bool manual_old_ac=AutoComplete(OFF);
  I64 manual_again;
  MsSet(0,0);
  do {
    TilMain;
    Print("Run again? y/n\n");
    manual_again=GetChar(,FALSE);
  } while (manual_again=='y');
  AutoComplete(manual_old_ac);
HC
  docker run --rm --user "$(id -u):$(id -g)" \
    -v "$PWD/tmp/templeos:/work" -w /work til-templeos-test \
    mcopy -o -i guest.raw@@1048576 Ext.HC TILTEST.HC ::/Home/

  Launch QEMU in the foreground, with VNC published only on localhost. The
  image's VNC backend works without installing a host QEMU or GTK backend:

*** QEMU validation

  The repository driver formats an isolated FAT32 data disk per case and
  boots the checksum-pinned live ISO. It injects the Linux-generated HolyC
  file and ~test/templeos.HC~ as ~C:/Home/Once.HC~.
  The runner mounts the data disk in the first user task and executes
  ~Once.HC~, which compiles and executes the generated file with ~ExeFile2~,
  catches exceptions, reports
  framed output and the result token over ~isa-debugcon~, and exit QEMU
  through ~isa-debug-exit~. The host requires the guest exit status, result
  token, and expected output to agree and applies a hard timeout.

  This runs the generated program directly on TempleOS in both local and
  CI testing. QEMU uses TCG in CI, legacy PC/IDE hardware, one CPU, and at
  least 512 MiB RAM; KVM is an optional local acceleration only.
