** OPEN #433 Qualifiers in template/macro type arguments: Vec(ref T) / Vec(own T)

   Let a template (macro) type argument carry an ownership qualifier, so a
   container can say how it holds its elements: `Vec(own T)` owns each
   element, `Vec(ref T)` borrows each element. Ref-qualified arguments already
   work for typed template fields and enum payloads, including Option(ref T).
   The remaining gap is making raw-buffer containers honor the qualifier in
   their element layout, insertion, cloning, destruction and borrow tracking.

*** DECIDED: interface element types require own or ref (2026-10-27)

   - Reject unqualified interface element instantiations such as Vec(Iface).
   - Reject shallow interface elements, including Vec(shallow Iface).
   - Vec(own Iface) holds owning interface handles; Vec(ref Iface) holds
     borrowing interface handles. Payload ownership remains static.
   - Iface() remains forbidden. Bare interface parameters and returns remain
     valid: parameters borrow by default and returns own by default.
   - These rules do not redefine own/ref for ordinary types. Their existing
     meaning and the existing ref-qualified template machinery are reused.
   - The old unqualified Vec(Iface) behavior must not be used as justification
     for silently substituting Vec(Concrete) inside a copied default.

*** Motivation

   1. Borrowed containers of ordinary types. `Vec(ref Str)`,
      `Map(Str, ref Expr)`, `Set(ref Node)`: today these are either owned
      copies or Vec(Dynamic) islands the garbager cannot see
      (doc/concepts/ownership.org, "Known manual-memory islands"). A `ref`
      element follows the same owner-outlives-the-view rule as #329's
      Slice(T), extended through the garbager over push/insert/set.

   2. A static, per-container statement of interface ownership. Since
      d11c2acf (#251 follow-up) a heterogeneous `Vec(Drawable)` already
      works using a fixed-size dispatch handle. #432 has already removed
      iface_owned: ownership is static, not a per-element runtime flag.
      The decision above now requires the element qualifier to be explicit:

          shapes := Vec(own Drawable).new()
          shapes.push(Circle(r = 1))       // owned clone; the Vec frees it
          shapes.push(Polygon.Tri)
          for s in shapes { println(s.draw()) }   // runtime dispatch per element

          views := Vec(ref Drawable).new()
          views.push(c)                    // borrow; c must outlive views

      The handle carries method-selection information as well as the payload
      reference. The wrapper's fixed size does not make a bare interface a
      concrete, directly instantiable element type.

*** Semantics to settle

   - Element clone/delete follow the qualifier: own -> the element type's
     clone/delete (for an interface element, the tag-dispatching pair);
     ref -> copy the borrowing handle without destroying its referent.
     Unqualified concrete element types keep today's behavior; unqualified
     interface element types are rejected as decided above.
   - Lifetime: a `Vec(ref T)` borrows every source. The deposit escape
     checks d11c2acf added for interface elements are the model for the
     general case: an inner-scope or caller-owned destination may not
     outlive the owner, and ref aliases of the destination are followed.
   - Syntax: the qualifier sits on the type argument -- `Vec(ref Drawable)`
     -- and a macro parameter declared `T: Type` receives it. Whether the
     qualifier is part of the Type value or a separate macro-parameter kind
     is open.
   - Interaction with #243: the erased Vec and a monomorphized Vec(T) both
     need the element qualifier; decide whether it threads into
     elem_clone/elem_delete selection (erased), into the expanded StructDef
     (monomorphized), or both.

*** Relations

   #432 (the interface box this stores), #243 (erased vs monomorphized
   containers; templates == macros), #329 (borrowed views; lifetime rule),
   #212 (cast), #57 (macro machinery).

*** Acceptance

   - `Vec(ref T)` / `Map(K, ref V)` never free elements; escaping a dead
     owner is diagnosed (or, where liveness cannot yet be proven, rejected
     loudly rather than copied silently).
   - `Vec(own Drawable)` and `Vec(ref Drawable)` hold mixed conforming
     concretes with the stated ownership and dispatch per element in
     interpret and compile modes, ASAN clean.
   - Existing Vec/Array/Set/Map behaviour unchanged for unqualified concrete
     arguments; unqualified and shallow interface element arguments rejected.
