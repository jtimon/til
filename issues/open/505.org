** OPEN #505 Run Android APK reproducibility checks in til

Make Android APK reproducibility a til-driven regression, extending the
existing ~test/reproducible_build.til~ and #472/#473 comparison work.

The local Android investigation used an ad-hoc Python script to orchestrate
builds, copy fixtures, wait between builds and compare APK bytes. None of
that requires Python: til already has Cmd, File, directory copying,
environment handling and sleep_ms. This is missing maintained test
coverage, not a missing language or standard-library primitive.

Related: [[./462.org][#462]] implements Android builds; [[./472.org][#472]] owns
reproducible output and [[./473.org][#473]] owns cross-producer CI comparisons.

*** Acceptance

  - [ ] The maintained APK regression is written in til and needs no Python.
  - [ ] Exercise android-x64 and android-arm64 at USize32 and USize64.
  - [ ] Rebuild the same GUI program in separate checkout roots and at
    different times, comparing exact APK bytes with identical signing inputs.
  - [ ] Cover different producer compilers at the same source revision and
    logical compiler path; distinguish local architecture emulation from
    actual cross-host results.
  - [ ] State the SDK/JDK and signing inputs. Where keys differ, explicitly
    compare the agreed pre-signing payload instead of claiming signed APK
    equality or silently rewriting outputs.
  - [ ] Integrate the applicable checks with the existing reproducibility
    driver/collector and report failures and missing coverage clearly.
