** WIP #491 Enforce writable reference return contracts

*** Existing preparation

This is enforcement and source/API migration work, not a request for a new
owned-return qualifier. The parser/AST preparation in ~ceca22348~ already
accepts ~returns ref mut T~ on named functions/signatures and inline ~Fn~
signatures, records ~FuncSig.return_ref_mut~, and distinguishes read-only
and writable reference results in inline signature identities. The following
type-argument preparation carries that bit through generic substitution.
Existing accepted programs retain their old permission behavior until the
enforcement migration. Parsed metadata is not proof of an enforced contract.

*** Contract

The working default follows #490: ordinary ~returns ref T~ is read-only and
the less permissive contract needs no extra keyword; writable results require
~returns ref mut T~. This is a reasonable starting expectation for reads and
queries, not a measured claim about every workload. Revisit the default if
observed use shows the opposite is more common; C's mutable-pointer default
and Rust's explicit mutable-borrow spelling illustrate different precedents.

The function grants access to the referent; the caller chooses whether its
own reference slot can be rebound. The caller may restrict granted access
but cannot increase it.

#+begin_src til
read := func(value: Item) returns ref Item {
    return value
}
write := func(mut value: Item) returns ref mut Item {
    return value
}
#+end_src

- ~returns ref T~ grants read-only referent access.
- ~returns ref mut T~ grants writable referent access, which must be justified
  by the returned source/access path. It must not launder a read-only borrow.
- A caller's ~ref mut result = read(...)~ cannot manufacture write permission,
  even when another alias reaches a mutable owner.
- The returned reference does not fix the caller's reference SLOT. Fixed and
  replaceable slots remain independent of referent permission (see #490).
- ~returns T~ transfers/produces an owned value under the existing ownership
  rules. No separate ~returns mut T~ is needed: the caller chooses its owned
  binding's mutability.
- Neither write permission nor pointer-slot mutability transfers ownership or
  extends a referent/VM lifetime.

The C comparison motivating the discussion is ~const T *~ versus ~T *~ for
referent access. Top-level const on a pointer returned by value (~T *const~)
does not fix the caller's pointer slot; it receives a copy. Native declarations
must describe the actual foreign contract, including read-only pointer results.

*** Accessor decisions still open

The existing Vec/Array ~get~ and ~unsafe_get~, and Map ~get~, return plain
~ref~. Once that means read-only, writable element access needs an explicit
contract. No new public accessor/query API has been approved yet.

- Decide between separate writable getters (~get_mut~, ~unsafe_get_mut~ where
  applicable) and a permission-dependent getter signature. Separate getters
  make contracts explicit but add methods/migration; permission-dependent
  getters reduce duplication but require a further signature rule/notation.
  Read-only getters plus setters alone cannot provide writable element aliases.
- Separately decide whether indexing/iteration stays read-only with explicit
  mutable accessor calls, or selects a writable accessor in explicitly mutable
  contexts. The latter is convenient but adds context-sensitive lowering.
- Separately decide whether generators get a public ~type_arg_is_ref_mut(T)~
  query or permission inspection remains internal. A mutable container must
  never upgrade an element stored as read-only ~ref T~.

*** C-to-Til draft binding generator impact

Update the draft C-header translator (~til bindings~, ~src/self/binder.til~),
not only Til-library bindings emitted by ~src/self/codegen/c_codegen.til~.
Its return-type scan currently discards ~const~ and ~volatile~ tokens, and
emits plain ~returns ref T~ for every single-level typed pointer result.
Once plain ~ref~ is read-only, that would incorrectly restrict writable C
results while still failing to record their actual const contract.

- Map ~const T *~ results to ~returns ref T~ and ~T *~ results to
  ~returns ref mut T~, following pointee constness through typedefs.
- Top-level const on a by-value pointer result (~T *const~) does not fix the
  caller's slot. Do not confuse it with a const pointee; the caller owns its
  pointer copy and chooses whether that slot can be replaced.
- Apply the same result permission rules to function-pointer/callback
  signatures where represented. Audit ~void *~, multi-level pointers and
  typedefs currently erased to ~Dynamic~; document/diagnose qualifier loss
  instead of silently granting writable access.
- Do not infer ownership, freeing responsibility, lifetime or til effects
  from C mutability qualifiers. Retain the generator's separate audit needs.
- Add C-header fixtures for const/non-const pointees and top-level pointer
  const, then type-check and exercise the generated declarations at the native
  boundary. Regenerate existing approved bindings with the new contracts.

[[490.org][#490]] covers the corresponding stored-pointer slot/pointee distinction,
including ~const ref mut~ fields. Both issues affect this generator.

**** Reflection bootstrap sequence

Restoring ~FuncSig.return_ref_mut~ in ~func_sig_of~ requires a private scalar
query in core/dyn. On base ~ae1daf9eb~, introducing its use alongside its
emitter fails pass 1 while building ~bin/til~:

#+begin_example

#+end_example

Apply ~doc/self.org~ "When a preparation commit is needed" / "Staged migration
across master merges": prepare C/MLIR-bridge and HolyC emission, reflection
inventory and interpreter dispatch first; then introduce the private core
declaration and make ~func_sig_of~ restore the bit. The query resolves core's
private identity from the owning module, including installed SDK paths. It
adds no public reflection API. The use step must verify both matching writable
contracts and rejection of read-only/writable mismatches at TilVm/native
callable boundaries. At the preparation checkpoint reflection still loses
the permission bit; the use step below restores it.

Preparation verification: ~make clean && make test_two_pass~ passed 575/575,
including native self-translation. The query use and boundary regressions
belong to the following commit, once its bootstrap has this emit logic.

The preparation is ~c4233b419~. The use step adds the private core query and
restores ~FuncSig.return_ref_mut~ in ~func_sig_of~. Previously host reflection
silently initialized this field to false: a matching writable guest signature
was rejected, while a read-only guest result could pass a host contract that
was supposed to require writable access. ~FuncSig.eq~ and the existing native
schema checks already compare this field; restoring the lost metadata fixes
those checks without adding layout-based exceptions or changing the ABI.

Coverage includes named and inline FuncSig reflection (with runtime calls to
avoid testing only constant folding), copied signatures, a user function with
the raw query's unmangled name, checked installed-SDK lookup/calls, and matching
writable native callable-enum results. A read-only callable result with the
same pointer layout must fail schema validation before attachment, even when
the enum's current value has no callable payload. HolyC's scalar query emitter
is prepared, but exercising the full AST-valued ~func_sig_of~ there exposed
~HolyC codegen: cyclic inline struct dependency~: Declaration's optional Expr

is not yet supported by that backend. This is distinct from the new scalar

**** Initial signature implementation

Initial implementation work addresses callable contract compatibility and
metadata loss: reject read-only results where a writable-return signature is
required, permit writable results to satisfy read-only result contracts with
the same borrow ABI, preserve the result bit in inferred/typed functions and
generic-generator twins, and emit it in Til-library bindings. This does not
yet enforce all returned source paths or direct writable-alias creation from
plain-ref call results, or migrate collection accessors. Return-permission
reflection and boundary coverage are implemented in the use step above;
other reference-permission metadata and the C-header translator changes remain
required. Do not close the issue on signature/reflection work alone.

Initial verification: ~make clean && make test_two_pass~ passed 575/575,
including native self-translation. ~return_signature_checks~ in
~test/type_arg_qualifiers.til~ covers rejection at local/field/argument and
typed/capturing-function boundaries, borrowed versus owned return ABI, typed
~dyn_fn~ rejection in interpreted and compiled execution, accepted permission
restriction, inferred signatures and generic-generator result metadata. Its
~generics~ family also passed with compiled ASAN programs.
~test/library_namespace.til~ checks writable results in generated ext
declarations, wrappers and named FuncSig declarations, with the existing
native library/consumer suite passing.

- Check writable return sources and writable alias creation at call sites;
  preserve read-only paths through getters, forwarding and cloning.
- Carry result permission through direct/indirect calls, closures, named and
  inline signatures, generic instantiations, and borrowed container elements.
- Preserve/check it in reflection, generated bindings and native/TilVm schema
  and signature validation; matching pointer layouts are insufficient.
- Migrate compiler/core/std and fixtures to explicit writable contracts where
  needed, with actionable diagnostics for old mutable uses of plain-ref results.
- Cover both accepted and rejected programs in interpretation and compiled
  execution, plus REPL/embedding and backend paths where applicable. Retain
  actual-owner write credit and prevent stale folding across permitted writes.
