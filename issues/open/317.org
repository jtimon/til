** OPEN #317 MLIR backend alongside the C backend

Add MLIR (Multi-Level Intermediate Representation, part of the LLVM
project, https://mlir.llvm.org/) as a codegen backend next to the C
backend. Filed as a low priority feature to capture the design space;
the C backend stays the default and the bootstrap path.

*** Related SIMD and heterogeneous-execution work

- [[../fixed/318.org][#318]] delivered interpreter/C SIMD; ordinary execution
  remains CPU-side unless a future device API is explicitly used.
- [[./409.org][#409]] covers CPU feature selection and performance validation.
- [[./410.org][#410]] defines additional portable vector operations.
- [[./411.org][#411]] designs explicit kernels, devices, memory and synchronization.
- [[./412.org][#412]] proves a small end-to-end GPU path, then matrix multiplication
  and second-vendor portability. It need not wait for this entire backend;
  MLIR infrastructure alone does not implement the device execution model.

*** Why MLIR

- MLIR is organized around "dialects" (func, arith, scf/cf, memref,
  vector, gpu, llvm, ...) and progressive lowering: high-level ops stay
  target-independent until late, then lower dialect-by-dialect to LLVM
  IR and finally per-target machine code. CPU lowering can reuse LLVM's
  instruction selection. GPU support additionally needs a device execution
  model, address spaces, kernel launch/runtime integration and target-specific
  lowering; CPU IR does not become a GPU program just by selecting a target.
- Mojo demonstrates the approach, but is not a thin frontend receiving all
  its performance infrastructure for free. The now-public compiler contains
  custom LIT/KGEN/POP/HLCF dialects and substantial elaboration, lifetime,
  target and LLVM-lowering code. Its source is a concrete reference, not a
  ready-made til backend.
- For til the reason to add MLIR is access to explicit IR transformations,
  structured/vector operations and a possible future accelerator pipeline.
  Fixed-width SIMD and ISA legalization alone do NOT require it: #318 can
  use GCC/Clang vector extensions, and LLVM IR supports vectors directly.

*** Mojo source review (2026-09-29)

Reviewed modular/modular ~ce67c4bba4~, whose compiler and stdlib are available
under Apache-2.0 with LLVM exceptions. ~Mojo/stdlib/std/simd.mojo~ stores
~!kgen.simd~ and emits ~pop.add~, ~pop.simd.select~, ~pop.simd.splat~, etc.
~Mojo/lib/KGENToLLVM/LowerPOPToLLVM.cpp~ converts those operations to LLVM
dialect operations, with additional stdlib LLVM-intrinsic/target-specific
paths. The earlier description of Mojo SIMD as necessarily passing through
the upstream ~vector~ dialect was incorrect. See [[../fixed/318.org][#318]] for the
syntax/semantics review and proposed til contract.
That issue also contains paired Mojo/til arithmetic, comparison, mask,
selection and matrix-multiplication examples. The human has chosen
elementwise comparisons: ~a == b~ and ~a.eq(b)~ return masks, while
~(a == b).all()~ / ~a.eq(b).all()~ return whole-vector value equality.
Possible ~reduce_eq~ shorthand and ~reduce_and/reduce_or~ mask-reduction
aliases remain naming proposals. This backend must preserve the chosen
contract, including mask normalization and explicit all/any reductions;
fusing compare-and-reduce must not change its semantics. The matrix example uses ordinary SIMD
row combinations and does not require a tensor dialect or matrix type.

Recommendation: use upstream dialects for til's first implementation and
external tools, keeping Mojo's custom dialects out of the dependency graph.
The C SIMD backend remains supported after MLIR lands. This issue is neither
a dependency of #318 nor a promise that a vector op will be one instruction.

*** Fit with existing til structure

- Issue #288 already drew the portability boundary with MLIR explicitly
  in mind: ~core_func~ is the mandatory primitive ISA every backend
  must lower inline (C -> ~a*b~, MLIR -> ~arith.muli~), ~ext_func~ is
  the per-backend symbol layer. That contract is the backend interface.
- ~Lang~ in src/self/targets.til enumerates C, HolyC, TIL and Java at
  master ~24b032796~. MLIR would be another emitter selected by
  src/self/builder.til. Target/Lang validation currently associates a
  platform with its default language: supporting C AND MLIR for one CPU
  requires an explicit backend-selection design, not merely an enum case.
- Reuse the prepared AST and inserted ownership/throw cleanup. Existing
  synthetic error-kind/payload reference parameters are the language-level
  calling contract; their machine ABI, especially aggregate passing, must
  be matched explicitly. Do not move destruction decisions into this emitter.

*** Implementation plan (staged; C backend stays green at every stage)

  Strategy in one line: emit the textual .mlir format into gen/ the
  way the C backend emits textual C, drive external tools
  (~mlir-opt~, ~mlir-translate~, ~clang~/~llc~) to get objects, retain the
  C runtime implementation of the native ~ext_func~ layer, and
  never link MLIR's C++ libraries into til itself. Only ~core_func~
  ops, control flow, and data layout are emitted as MLIR.

   1. Toolchain/ABI probe, zero compiler changes: on an approved pinned LLVM
      toolchain, hand-write a hello world .mlir (func + arith + llvm,
      calling a C symbol). Run ~mlir-opt~ conversions to LLVM-translatable
      dialects BEFORE ~mlir-translate --mlir-to-llvmir~, then compile/link
      with ~clang~. Translation alone does not lower func/arith/cf/vector.
      Pin the conversion pipeline, data layout and target triple; record
      exact versions/commands and use a matching toolchain for each stage.
      Add mixed C/MLIR calls with narrow scalars, aggregates, pointers and
      error out-parameters. A matching-looking ~func.func~ signature does
      not itself implement Clang's platform ABI (sret/byval/coercions and
      extension attributes may matter). Test C calling MLIR and vice versa.
  2. Backend plumbing: new ~Lang.MLIR~ variant in src/self/targets.til
      with explicit target/lang selection and output paths. Proposed surface,
      to be approved at implementation time: til writes textual .mlir under
      gen/, read by humans and mlir-opt; converted IR is passed to
      mlir-translate and LLVM/Clang. Existing build entry points regenerate
      everything from til source. C output cannot carry these MLIR operations;
      the tradeoff is a separate optional toolchain and generated IR path.
      Approve exact paths, any persisted intermediate artifacts, backend
      selection syntax and tool installation before implementing them. No
      second source of truth or persistent compilation cache is proposed.
  3. Emitter skeleton alongside src/self/codegen/c_codegen.til:
      module header and signatures implementing the C ABI established by
      the probe, including return values and existing synthetic error
      out-parameters, plus declarations for reachable ~ext_func~ symbols.
      ABI-compatibility with the C runtime is the
     load-bearing decision: the runtime is not re-implemented, MLIR
     code just calls it (#288's ~ext_func~ layer).
  4. Minimal end-to-end subset: main, scalar locals, ~core_func~ ops
      lowered inline to ~arith/llvm~ with til's scalar semantics (zero
      division, signedness and shifts are not blindly mapped to bare ops),
      direct calls, string literals as globals,
     print via ~ext_func~. A til hello world runs through the MLIR
     pipeline.
  5. Control flow: if/while/for/switch, and the throw/catch tag checks
     after calls, lowered with cf blocks (cf matches the shape the C
     emitter produces more directly than scf; revisit if scf's
     structured ops make the emitter simpler).
   6. Aggregates and memory: structs as ~llvm.struct~ with GEP field
      access, own/ref pointers as ~llvm.ptr~, matching size/alignment and
      calling conventions. Constructors/clone/delete and collection methods
      written in til must also be emitted; they are not all C runtime
      symbols. Verify Str/Vec/Map/Set, layout, aliasing and cleanup before
      claiming collections work. SIMD memory layout must match #318 even
      when register vectors/masks have a different representation.
  7. Suite burn-down: run the test corpus under the MLIR backend and
     close the gap (dyn/FuncPtr, closures, FFI, gui mode last). Every
     landed stage keeps ~make test~ (C backend) green; the MLIR
     backend is allowed to stay partial between stages.

*** Acceptance

  - A smoke program compiles through gen/ .mlir and runs with output
    identical to its C-backend build.
   - ~Lang.C~ remains the default native backend and bootstrap path.
     Compiler changes may regenerate boot/ through the normal C build;
     building til itself does not require or select MLIR.
  - ~core_func~ ops appear inline as arith/llvm dialect ops in the
    emitted .mlir (no calls); ~ext_func~ calls link against the
    unchanged C runtime objects.
  - ~make test~ does not require MLIR tools; the MLIR path has its own
    opt-in target/mode gated on the tools being installed.
   - Mixed C/MLIR ABI probes pass on each claimed native target, and the
     supported semantic corpus matches the interpreter/C backend. Smoke
     hello-world success is the first milestone, not suite completion.
   - When #318 exists, its same value/mask/memory contract passes here.
     Use arith/vector/llvm operations as appropriate; fixed-order FP
     reductions and uncontracted arithmetic cannot silently become
     reassociating reductions or fused multiply-adds. Inactive lanes of
     masked memory ops must not access memory. Do not gate source-language
     SIMD semantics on this emitter merely because C lacks one intrinsic.

*** Non-owning pointer/reference fields (base a06e63e54)

Structs now support native ref fields, including the established ref Dynamic
raw C-pointer/null boundary. Typed refs can borrow supported scalar, SIMD, POD,
Str and array-descriptor storage. Construction, field retargeting and holder
clone preserve addresses; value use reads the pointee and raw Dynamic remains
opaque. Recursive ref records stop layout at the pointer slot. Own fields and
owning user-aggregate cleanup remain separate work.

Reference fields are INTEGER eightbytes even when the pointee is floating-point
or SIMD. Classification now computes field offsets with target_value_size_align
instead of the host interpreter cache, aligning target USize64 fields correctly
under the compact compiler. Existing whole-aggregate spills, rollback and sret
cover nested pointer/SIMD layouts without adding a second layout cache.

Mutable typed-reference locals use an entry-block pointer variable, so a rebind
inside an if/loop changes later reads/writes through that alias. The emitter
mirrors reference RHS rebinding versus value RHS write-through and keeps mutable
parameters write-through. Borrowed array-reference locals select descriptor
addresses, not the descriptor's first data-pointer member.

The C/interpreter references exposed shared bugs: C ref-field steps
advanced the stored pointer instead of the numeric pointee; C ref-field rebinds
boxed scalar values rather than borrowing them; interpreted ref-field writes
treated already-erased Dynamic addresses as pointer-word slots. C now binds and
steps the actual target once, borrows on ref rebinds, and the interpreter uses
the existing raw-result argument metadata for data-reference stores and null.
A nullable Dynamic binding is also accepted as a borrow source: its presence
and moved_out state, not nonzero pointer bits, distinguish a live binding.
Reference pointee reads also retain their declared scalar type: a pointer
slot's eight-byte width is not a reason to read an I8/F32 pointee as U64.

test/mlir.til check_pointer_fields exercises scalar/alias/SIMD/POD ref boxes,
full-width/raw/null pointers, nested/self-ref records, Str/array references,
typed null-read diagnostics, field/pointee mutation, conditional scalar/array
reference selection, pointer/FP register classes, rollback and hidden sret at
O0/O2/O3 with native C and ASAN til/C consumers. test/ref.til covers shared
stepping, getter evaluation count, clone identity and raw field rebind/null;
test/mlir_options.til checks storage, target widths and ABI classification.

*** Shared scalar integer arithmetic and MLIR lowering (base 0fafe1c4e)

The human approved unifying previously inconsistent/undefined edge cases before
adding MLIR scalar div/mod/shl/shr. All scalar integer widths now return zero
for zero divisors, signed MIN for MIN/-1 and zero for its remainder. Shifts test
the full count against the declared width: negative/oversized counts produce
zero, except signed right shifts produce sign-fill. I16/U16 now expose shl/shr
alongside the other widths. Operands run once, left to right.

C explicitly checks division overflow and counts and shifts unsigned bit
patterns. Interpretation checks the source width rather than always shifting

emitting div/rem/shift, then selects the defined result. This prevents LLVM
poison even for constant or discarded exceptional operations. Declared-width
results are converted only afterwards when an enclosing context widens them.
Clang discarded-value handling also covers scalar statement expressions so
operand side effects survive without unused-result compilation failures.

*** Scalar/nested POD structs and LLVM 18 ABI export (base 959dff083)

POD structs with Bool, I32/U32, I64/U64, F32 and nested scalar POD fields now

*** SysV aggregate stack arguments (base e9c9d59e7)

The old eight-SSE/six-INTEGER SIMD argument limits are removed. A shared
definition/call allocation pass walks parameters in source order, accounts
for hidden sret and error-out pointers, and spills whole two-eightbyte vectors
when their bank cannot hold both chunks. Spilling rolls the bank back so later
scalars or masks can use its remaining register. The banks stay independent.

Stack arguments use LLVM byval pointers to scalar-layout structs, alignment 8,
with source snapshots stored in fixed entry-block slots. Register and return
ABIs stay as before. The original LLVM 18 instruction-selection probe consulted
the callee's attributes, but that is insufficient under optimization; the POD
follow-up above corrects the exported call-site contract. No toolchain change
or additional C wrapper is needed. Indirect calls remain outside the subset.

Integration covers 0..10 leading SSE scalars and 0..8 leading INTEGER scalars,
two numeric vectors and trailing scalars, both direct and forwarded calls.
Additional cases cover mixed-bank spills, masks, sret, trailing error pointers,
raw signaling-NaN/zero copies, operand snapshots across mutation and a million-
iteration bounded-stack loop. Interpreter/C references and ASAN C/til consumers
run at O0/O2/O3 with the supported native USize64 layout. Translation checks
assert byval/alignment without requiring installed LLVM tools.

*** Numeric casts (base 742677606)

The shared language cast now includes integer/float numeric conversion, not
just integer reinterpretation/widening and F32/F64 lane conversion. MLIR lowers
I32x4/U32x4/F32x4 conversions and supported scalar conversions with signedness-
correct LLVM operations. Integer sign reinterpretation preserves bits. Float
results follow the normal rounding mode; float-to-integer truncates toward zero
and panics for NaN, infinity or an out-of-range truncated result.

MLIR checks every lane before executing fptosi/fptoui, so invalid inputs never
reach a poison-producing conversion. Failures call the ordinary C-core panic
ABI, not a new runtime implementation. The interpreter and C backend implement
the same contract for all integer widths and F32/F64. Casts retain their source
unit for diagnostics; DCE preserves potentially panicking discarded results.

Tests cover all six vector directions, signed/unsigned boundaries, nearest-even
rounding examples, fractions, scalar 64-bit limits, single evaluation and error
propagation. Invalid scalar casts at every integer width and mandatory macro
aborts run without LLVM tools. Native C/til consumers and failure subprocesses
compare exact interpreter/C diagnostics at O0/O2/O3. MLIR verification uses
USize64: the current master rejects compact-layout MLIR pending cage support.

*** Min/max reductions (base bac208501)

F32x4, I32x4 and U32x4 reduce_min/reduce_max now lower through the same
halving tree as core: (0,2), (1,3), then the two results. The operand is
evaluated once. Integer comparisons preserve signedness. Float pairs propagate
NaNs (RHS wins if both are NaNs), preserve the chosen bits/payload, and select
-0 for min / +0 for max when both zero signs are present. Explicit comparisons
and selects avoid changing those semantics through generic LLVM reductions.

Regression coverage compares all 14^4 combinations of boundary bit patterns
through native C callers, plus interpreter/C and ASAN til/C reference cases
for zero signs, quiet/signaling NaNs, multiple payloads and the tree's ordering.
Side-effecting/throwing operands check single evaluation and propagation. The
clean suite passed 491/491 and ASAN MLIR integration passed at O0/O2/O3 with
both USize widths.

*** I32x4/U32x4 SIMD (base f2ad7b5ca)

Integer four-lane vectors now support new/splat/zero, wrapping arithmetic and
reduce_add, division, bitwise operations, all comparisons, mask selection,
checked lane reads/updates, and checked load/store on borrowed I32/U32 arrays.
Signed/unsigned predicates retain lane semantics. Division replaces exceptional
divisors before evaluating LLVM div: zero yields zero and signed MIN/-1 yields
MIN, matching the existing SIMD div_lane contract without creating poison.

The SysV public ABI uses two i64 INTEGER chunks, not an SSE vector. Calls,
returns and mixed scalar/pointer/mask/SSE arguments use that representation.
More than six INTEGER slots with integer-vector parameters is rejected pending
whole-aggregate stack passing; hidden error/sret pointers count toward the limit.

Differential tests cover boundary bit patterns, wraparound and division, all
comparison predicates and selection masks, the six-register ABI boundary,
same-file calls, lane failures, scalar-aligned memory, failed-write preservation,
empty/maximal-index accesses and signed/unsigned reference widening. Interpreter/C
references and ASAN C/til callers run at O0/O2/O3 with both USize widths. The
translation/ABI-limit checks remain independent of installed LLVM tools.

*** Temporary C-core bridge for strings/runtime (base 3515db554)

The human approved using the C-compiled core as an interim bridge. MLIR emits
ordinary Str/Array(Str) values and ABI calls for printing, formatting, string
methods and panic, preserving the prepared AST's ownership decisions. The
special generated-bang panic recognizer/emitter is removed. Str value returns
match SysV at both USize widths (16-byte register return / 24-byte sret), and
owned transfers distinguish stack records from already-owned heap wrappers.

Translation writes the normal gen/til source/forward-header pair alongside
gen/mlir. Builds compile only the C core/runtime portions, using existing
versioned gen/lib object paths, and include those objects in the MLIR artifact.
This adds generated C and compilation work, not a cache or new source of truth.
Native static-archive callers link libm. The bridge does not emit public bindings.

IMPORTANT: the intended end state is til core bodies emitted directly as MLIR,
with libc/platform dependencies at the same low-level boundary ext.c provides.
Depending on C-generated til core code is temporary, not the final architecture.
Remove this support-generation/link bridge as native MLIR coverage replaces it;
do not duplicate string/ownership algorithms in a permanent second runtime.

Tests compare stdout/stderr and explicit/bang panic diagnostics, exercise
embedded NULs and escaping, and check C/til consumers of both return ABIs.
Repeated transfers, replacement, mutation and owned-parameter returns are
checked with ASAN callers, across both widths and O0/O2/O3.

*** Floating division and explicit FMA (base 6eed1697a)

F32 and F32x4 division lower to arith.divf with the existing IEEE semantics;
integer division remains unsupported. Explicit fma lowers to llvm.intr.fma,
preserving single rounding without contracting ordinary multiply/add pairs.
Operands retain source evaluation order. Executable/shared-library linking
includes the existing system libm for baseline CPU fmaf lowering; static
archive consumers link libm themselves.

Tests cover zero divisors, signed zeros, infinities, NaNs, subnormal/overflow
inputs, cancellation distinguishing fused from separate rounding, and
once-only ordered operand evaluation with error propagation. Interpreter/C
references, native C callers and ASAN til/C callers run at O0/O2/O3 with both
USize widths. A baseline-CPU executable also exercises the libm link path.

*** Dynamic SIMD lane access (base 9bc23073e)

F32x4 and Boolx4 get/set now accept runtime indices. Unsigned USize bounds
checks precede LLVM extraction/insertion, preserving wide-index rejection and
avoiding poison from out-of-range accesses. Failed local updates preserve the
vector, including earlier successful writes. Shared lowered error guards
provide propagation, local catch/reset and bang panics. Proven in-range
constant accesses retain the existing no-error-write proof. Mutable vector
parameters and borrowed vector returns remain outside this ABI subset.

Integration coverage includes all four lanes, invalid/maximal indices, all
16 masks, raw NaN/negative-zero F32 bits, repeated catches, propagation, and
exact panic diagnostics/status for both reads and writes. Interpreter/C
references and C callers of MLIR run with both USize widths and O0/O2/O3.

*** SIMD comparisons, masks and selection (base 1ec7e4ba0)

F32x4 now supports all six elementwise comparisons, with ordered predicates
except unordered inequality. Simd(Bool,4) supports new/splat/zero, constant
lane reads, eq/neq, band/bor/bxor/bnot, all/any and selection. Selection also
accepts F32x4 values and preserves the chosen bits rather than performing
floating arithmetic. Internal four-i1 predicates cross the existing C ABI as
four normalized Bool bytes in one INTEGER chunk. Mutable locals and direct
calls support masks without exposing packed predicate storage to C callers.

The optional integration test covers all 16 masks and all 256 mask pairs,
six floating comparisons including NaNs/infinities/zeros/subnormals, and
bit-preserving selection including signaling NaNs. Interpreter/C references,
native C callers and ASAN til/C callers exercise both USize widths and
O0/O2/O3. Normal translation tests require no LLVM tools.

*** Local OutOfBounds handling (merged 1ec7e4ba0)

The backend handles the shared frontend's lowered local error slots,
catch/reset branches and rethrowing. Generated bang failures preserve the
source-location diagnostic on stdout and exit status 1. Until general strings
and runtime calls are supported, only the compiler-generated OutOfBounds
panic shape is recognized and emitted through libc fwrite/exit; this is not
a second throw/catch desugaring pass. Tests cover repeated recovery, partial
writes, nested ? inside ! and exact panic output/status. Verification was
494/494 clean-suite tests plus ASAN MLIR integration at both USize widths
and O0/O2/O3.

*** Borrowed F32 buffers and checked memory (base ee8785cb2)

The MLIR backend now accepts borrowed Array(F32) descriptors, including mut
outputs, len, checked scalar get/set, and four-lane SIMD load/store. It uses
the existing pointer-plus-USize-capacity layout and supports both USize
widths without changing pointer width. References to elements and descriptor
aliases borrow the caller's storage; allocation, cloning and ownership
transfer remain outside this subset.

Functions declaring throws OutOfBounds propagate through the existing I64
error-out argument. Checked spans use start <= count followed by
count-start >= 4; only the successful block forms a data address. Loads and
stores require scalar alignment, not vector alignment. Failed stores leave
their span untouched, while preceding successful writes remain visible.
There are no inbounds/noalias promises. Callers initialize the error word
to zero and handle catch/! in the ordinary C/til host.

Error-state knowledge is invalidated by potentially throwing calls, writes
and loop exits. A proven-clear branch allows a constant SIMD lane read after
a successful buffer load without folding away a live error check. MLIR-side
buffer/helper bangs are rejected explicitly, including helper calls followed
by constant lane reads; they cannot inherit a stale known-zero error slot.

The expanded opt-in test/mlir.til exercises array addition and four-lane dot
products with scalar tails, interpreter/C references, native C callers and
ASAN til/C callers, at O0/O2/O3 and both USize widths. Cases include empty
buffers, scalar-aligned vector starts, short inputs/outputs, maximum indices,
error forwarding, aliases, overlapping/in-place output, partial writes,
reference mutation, cancellation and raw NaN payload loads/stores.
test/mlir_options.til checks translation/ABI spelling and rejected operations
without requiring the optional LLVM tools.

Verification on the rebased tree: clean full ASAN suite 492/492, plus the
expanded opt-in integration test with the ASAN-built compiler and driver.

*** Mutable locals and control flow (base 201db1ef2)

The MLIR backend now lowers mutable value locals, if/else, while,
break/continue and early returns into explicit LLVM-dialect blocks. Mutable
storage is allocated once at function entry; declaration initializers still
run at their source position. Lexical binding snapshots preserve branch
shadowing while stores through outer-local slots remain visible.

I32/U32/I64/U64 and Bool values now complement F32/F32x4. Integer add/sub/mul
and increment/decrement wrap without LLVM overflow assumptions; comparisons
distinguish signed and unsigned operands. F32 comparisons retain unordered
NaN behavior for inequality. Boolean results use i1 internally and normalized
byte values across the C ABI. Lazy Boolean operands remain conditional.
USize follows the existing resolved target width, including explicit test
overrides; the default-policy/configuration migration remains separate (#455).

The normal translation tests cover control flow and both USize widths without
requiring MLIR tools. The opt-in LLVM 18 integration tests compare interpreter
and C reference results with native C and til/C consumers at O0/O2/O3 and
USize32/USize64. They exercise nested loop-local initialization, zero trips,
break/continue, condition re-evaluation, both-returning branches, snapshots,
shadowing, Boolean ABI calls, wraparound, wide counts, mutable scalar/SIMD
values, signed/unsigned integer widening and a million-iteration bounded-stack
check. Widened declarations emitted as clone calls retain the required
extension rather than being mistaken for identity copies. Existing SIMD numerical
and ABI checks also remain green.

Verification: clean full ASAN suite 476/476; the expanded opt-in integration
test passes using the ASAN-built compiler and test driver. Borrowed buffers,
mutable parameters and general exception handling remain future increments.

*** SIMD dot-product operations (2026-10-27)

The MLIR F32/F32x4 subset now includes multiplication, SIMD ~new~, ~splat~,
~zero~, statically in-range lane access and ~reduce_add~. A til dot product
~(a*b).reduce_add()~ lowers with separate multiply/add rounding and exactly
~(lane0+lane2)+(lane1+lane3)~; no reassociating vector reduction or initial
positive-zero addition is introduced. Constructors and lane reordering are
bit-preserving, including signaling-NaN payloads.

Checked lane reads retain their contract: compile-time index/error-tag
bookkeeping proves the bounds-error branch unreachable for indices 0..3.
Unknown or out-of-range indices are explicitly unsupported, not converted
to unchecked/poison extracts. This is not general runtime control flow or
exception support. The tool-independent tests cover both USize widths.

Verification: clean full ASAN suite 465/465; expanded opt-in tests pass
using the ASAN compiler/test driver at O0/O2/O3. The same dot checks run
through the interpreter, C and a til/C caller of the MLIR library. The C
oracle adds exceptional FP pairs, cancellation, negative-zero reduction,
raw-bit construction/reordering and separate-rounding versus FMA cases.
The native oracle also passes with MLIR libraries built at O3 for
x86-64-v3 and x86-64-v4 on the local host. No timing claims are made.

*** Initial CPU value backend (2026-10-27)

The approved ~--backend=mlir~ selector is independent of the CPU ~--target~.
~src/self/codegen/mlir_codegen.til~ emits the prepared AST's straight-line F32 and
~Simd(F32,4)~ addition, locals, calls and returns. Linux x86-64 aggregate
arguments/results use the existing C ABI rather than assuming a native
LLVM vector has the same calling convention as a four-float C struct.

The builder pipes LLVM 18 vector/arith lowering and LLVM IR translation into
Clang, with failure propagation and no persistent intermediates or cache.
MLIR source lives under ~gen/mlir/~; ordinary C builds remain the default.
Unsupported operations, runtime features and platforms fail explicitly.
This does not complete the general backend or implement GPU execution.

[[../../doc/self.org::*Experimental MLIR backend][Build documentation]] records the exact subset, output paths, optional tools
and interoperability test commands. ~test/mlir_options.til~ exercises
tool-independent translation/diagnostics in the normal suite;
~test/mlir.til~ is the opt-in LLVM 18 C/til interoperability test.

Verification: clean full ASAN suite 465/465; the opt-in integration test
passes with an ASAN-built compiler and test driver. Its C caller checks
scalar/F32x4 returns, nested/private calls and the eight-SSE-slot boundary
at O0/O2, including signed zeros, subnormals, infinities and NaNs. The
ordinary til/C consumer calls the shared MLIR library through explicit
shallow aggregate bindings. No GPU compilation or execution is claimed.
