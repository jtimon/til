** OPEN #341 Leading-dot enum variants in switch/match cases: `case .Body:`

Every ~switch~ over an enum repeats the enum's name on every arm:

#+begin_example
switch e.node_type {
case NodeType.Body:
case NodeType.Decl(dd):
case NodeType.FCall:
case:
}
#+end_example

The type is already fixed by the subject expression, so the repetition
carries no information. Jai has the leading-dot form and Odin picked it
up; Swift has it too. Proposal: allow the enum name to be elided when
it is implied.

#+begin_example
switch e.node_type {
case .Body:
case .Decl(dd):
case .FCall:
case:
}
#+end_example

Why it should be tractable: the switch subject is inferred before its
cases are checked, so a leading-dot case has exactly one enum to
resolve against -- the subject's. This is the same shape as the field
init shorthand ([[../fixed/340.org][#340]]): the parser cannot resolve
it (a bare ~.Body~ has no receiver), but the typer can, because by the
time it walks the arms it knows the subject's type. Rewriting the case
pattern into the fully qualified ~NodeType.Body~ there means every
later pass keeps seeing exactly what it sees today.

Open questions to settle before implementing:

- Scope: switch/match arms only, or also other positions where an enum
  type is implied (a typed declaration's RHS ~t : NodeType = .Body~, a
  call argument at an enum-typed parameter, a return in an
  enum-returning function, a struct literal's enum-typed field)? Rust's
  answer is "nowhere, use the path"; Swift's is "everywhere the type is
  known". Starting with switch/match alone is the smaller change and
  covers the case that actually hurts.
- Payload binding (~case .Decl(dd):~) has to keep working identically.
- Nested/qualified subjects (~switch self.kind~) resolve the same way,
  but a subject whose type is Unknown must produce a clear error rather
  than a confusing "no variant" one.
- The default arm stays bare ~case:~ -- unchanged.

Regression tests to add: a switch with every arm in the dot form
(including payload binding and a default), a mixed switch (some arms
qualified, some dotted) to confirm both spellings coexist, and a typer
error test for a dotted name that is not a variant of the subject's
enum.
