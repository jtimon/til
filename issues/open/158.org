** WIP #158 One pass per phase across the whole pipeline

   Progress / current state (read the source, the original list below
   is stale):

   - lexer (~tokenize~), parser (~parse~): single pass. Done.
   - initer (~init_declarations~ / ~init_declarations_unit~): now a
     single AST walk that buckets each Decl into index lists; the
     post-walk loops iterate those small filtered lists (not the AST)
     in dependency order (type names in scope -> aliases -> layouts ->
     size/derived methods). The 12 sub-procs the old list named are
     gone. Done.
   - typer (~infer_body~ -> ~body_pre_passes~): the 7 desugar/insert
     sub-passes are one prefilter + one move-out/rebuild/move-back.
     That is [[./146.org][#146]]'s scope. Done.
   - constfolder (~constfolder_imported~): the three setup sub-passes
     (scan_names, register_defs, register_globals) re-walked the AST
     even though every statement already carries all the data each one
     needed and none reads the scope the others build. Collapsed into a
     single walk (~constfolder_collect_and_register~). Done. (constfolder's
     state -- macro/func name sets and the fold-results map -- now also
     lives on ~Context~ as ~constfolder_macros~/~constfolder_funcs~/
     ~constfolder_known~, per the [[./178.org][#178]] direction.)

   Remaining phases keep multiple walks, but these are NOT redundant
   re-walks -- they are an irreducible dependency chain. Each later
   walk consumes the *complete* output of an earlier walk over the whole
   program, so it cannot start until the earlier one finishes (top-level
   forward references / graph reachability / C output ordering):

   - interpreter (~interpret~ / its imported variant): register_defs ->
     {register_aliases, init_ns} -> copy_alias_ns -> eval. register_defs
     must precede the rest (an alias ~Foo := Bar~ or a method body can
     reference a name defined later). Merging register_aliases with
     init_ns is NOT behaviour-preserving: ~interpreter_init_ns~ calls
     ~eval_expr~ on every namespace-member default, which reads the
     ~global~ scope that ~register_aliases~ writes -- a ns default that
     names a type by its *alias* would resolve under the current
     "all aliases first" ordering but not under an interleaved walk.
     copy_alias_ns reads the namespaces init_ns fills, so it stays last.

     The ORDER above is irreducible, but re-deriving the alias SET was
     not: ~interpret_register_aliases~ and ~interpret_copy_alias_ns~
     applied a character-for-character identical predicate (Decl, no
     til_type, Ident rhs resolving to a struct/enum) over every
     top-level statement of every unit, to act on the handful that
     qualify. Registration now records each alias it registers into a
     borrowed ~InterpAlias~ list that the copy phase iterates instead,
     so the whole-program walk between the two barriers is gone while
     the barriers themselves are untouched. The target is still
     re-resolved through ~global~ at copy time (init_ns is what filled
     the namespaces being copied), so the copy is byte-identical.
   - scavenger: build top maps -> seed worklist -> BFS -> filter. BFS
     follows edges, not source order; the sweep needs the full mark.
   - builder: header/forward decls -> globals -> function bodies. C
     requires a declaration before its use. [[./178.org][#178]] already moved the
     builder's redundant lookup *tables* onto Context.

   The one redundancy left is cross-phase, not within-phase: constfolder's
   name classification (and the interpreter's def/alias/ns registration)
   re-derive facts the typer already computed. The storage half of that
   is done -- [[./178.org][#178]] / [[./147.org][#147]] moved the per-phase symbol/cache state
   onto Context.

   The foldable-name half is now done too. ~constfolder_classify_stmt~ no
   longer runs as a dedicated pre-walk over each unit's top level in
   ~infer_body_unit~; it is called inline from the per-decl loops that
   already existed:
   - ~type_decls_file~ (the normal path) -- after the layout /
     size-methodgen / cmp / unity work for that decl, so classify sees
     the ns methods those helpers just added;
   - ~type_check_unit~ -- for the lifted ~_lambda_<N>~ tail only, which
     is appended after ~type_decls_file~ ran;
   - ~type_repl_delta_decls_from~ -- the REPL delta path, which never
     goes through ~type_decls_file~;
   - ~flush_generic_pending~ -- late concrete generics, as before.

   The [[./315.org][#315]] forward-reference guarantee still holds:
   ~type_decls_file~ completes for the whole transitive import graph
   before ~type_bodies_file~ types any body, so every top-level foldable
   is recorded before ~body_pre_passes~ asks ~is_macro_call~ whether to
   skip hoisting a macro call's args.

   What remains under this issue is the per-body garbager work: lifting
   the inline ~garbager_destroy_body~ calls (function / if / while /
   block / catch scopes) into the single ~garbager_destroy(ctx)~ walk.
   The blocker is per-body scope ownership -- those TypeScopes are locals
   of the typer functions and are gone once ~infer_body~ returns -- which
   needs either a per-body scope cache on Context or an on-the-fly scope
   rebuild in garbager. See [[../fixed/204.org][#204]] step 3b.

*** Measured: what an on-the-fly scope rebuild can and cannot recover

    The rebuild option was prototyped and measured against the live
    scopes, to settle it with data instead of argument. A throwaway
    ~garbager_rebuild_scope~ derived each body's TypeScope from the typed
    AST (params from ~fd.params~, locals from the body's top-level
    ~Decl~s, types via ~type_from_name_init~ /
    ~declaration_resolved_type~ -- deliberately NOT the typer's
    ~type_from_name_at~, which reports priv-access errors and marks
    cross-file imports used, so re-running it would duplicate diagnostics
    and mask unused-import warnings), and an equivalence check compared it
    against the live scope at every site the pass runs.

    First, the good news, and it is the load-bearing half. The pass reads
    exactly FOUR binding facts -- ~name~, ~type~, ~own_type~, ~is_param~.
    No other TypeBinding field is touched anywhere in garbager.til
    (~is_alias~ / ~is_raw_alloc~ / ~is_str_view~ / ~borrow_roots~ /
    ~used~ / ~written~ are typer- or diagnostics-only). Over a full
    self-host -- every body in the compiler -- the rebuild matched the
    live scope EXACTLY on which names are bound, on params vs locals, and
    on ownership. Zero dropped bindings, zero invented ones.

    Now the blocker, which is ~own_type~, and it is not a gap that more
    care in the rebuild closes. THREE registrars create body Decls and
    each writes a different ~own_type~ to the AST ~Declaration~ than to
    the ~TypeBinding~, with nothing in the AST marking which one ran:

    - the typer's Decl handler registers the binding ~Shallow~
      unconditionally, then upgrades to ~Ref~ when ~sdecl.own_type~ is
      ~Ref~. An ~Own~ on the Declaration never reaches the binding.
    - ~hoist_to_temp~ registers the hoisted expression's ~til_type~ RAW,
      so a temp holding a user-enum value keeps ~Custom(name)~ where a
      source-level local of the same type holds ~Enum(name)~. That is
      observable -- ~is_aggregate~ is ~Struct or Enum~, so ~Custom~ reads
      as non-aggregate -- and it accounts for 433 type divergences in a
      self-host (278 ~Literal~, 155 ~Primitive~), all on ~hoisted__~
      names.
    - ~desugar_array_vec_decl~ writes ~own_type = Own~ onto the
      Declaration while registering the binding ~Shallow~ -- and it does
      this for the USER'S variable name, not a prefixed temp. The
      equivalence check caught it on ~gui_files := array(Str, ...)~ in
      src/tests.til.

    That third case is what settles it: the Declaration's ~own_type~
    genuinely does not determine the binding's, and there is no
    syntactic marker to recover which registrar ran. Keying on a name
    prefix works for ~hoisted__~ and fails here by construction.

    Measured for completeness: resolving every Decl type through
    ~declaration_resolved_type~ diverges on 433 hoist temps; resolving
    none (raw ~dd.til_type~) diverges on 1866 source locals. Neither rule
    is right because the split is not a rule -- it is history.

    So the rebuild needs a PREREQUISITE commit that reconciles the
    registrars: make ~Declaration.own_type~ and ~TypeBinding.own_type~
    agree at every site that creates a body Decl (and, for the type,
    make ~hoist_to_temp~ resolve like the Decl handler). That is an
    emit-affecting normalization -- it changes what the garbager decides
    -- so it wants the full suite plus ASAN, and it is worth doing on its
    own merits: two records of the same fact that disagree is the shape
    [[./302.org][#302]] has been retiring elsewhere. With the registrars in
    agreement, the rebuild's remaining derivation is already proven exact
    by the measurement above.

    The alternative (a per-body scope cache on Context) sidesteps all of
    this but costs retained memory for every body until typing ends --
    against the direction [[../fixed/204.org][#204]] / [[./302.org][#302]] took -- and couples two
    walks by completion order, where a divergence hands a body the wrong
    scope and miscompiles its frees silently. The rebuild fails loudly;
    the cache fails quietly. That is why the rebuild is still the
    recommended route, behind the reconciliation commit.

** Original report (kept for reference)

Each phase listed in doc/pipeline.org (lex, parse,
   init_declarations, type_check, constfolder, scavenge, interpret /
   build) should walk the AST exactly once. At each statement, all
   the work that phase needs to do should happen before moving on.

   Today this is not true. Concrete evidence read directly from the
   source:

   - ~tokenize~ (src/self/lexer.til:259) -- single pass over the
     source string. OK.

   - ~parse~ (src/self/parser.til:1319) -- single pass over the
     token stream. OK. After the main loop it appends pre-collected
     ~fn_sig_decls~ and ~lambda_decls~ -- no extra AST walks.

   - ~init_declarations~ (src/self/initer.til:1870-1887) calls 12
     separate sub-procs, each taking ~program~ and walking it:
       register_struct_definitions, register_funcsig_aliases,
       generate_missing_struct_clones, generate_missing_struct_deletes,
       register_enums_and_generate_nonclone_methods,
       generate_missing_enum_clones, register_type_aliases,
       compute_all_struct_layouts, generate_size_methods,
       generate_derived_methods, register_function_definitions,
       register_top_level_values.

   - ~type_check~ -> ~infer_body~ runs 7 sub-passes per body
     (already covered in [[./146.org][#146]]): desugar_set_literals,
     desugar_map_literals, desugar_variadic_calls,
     desugar_kwargs_calls, hoist_fcall_args, insert_field_deletes,
     insert_free_calls.

   - ~constfolder~ (src/self/constfolder.til:506) has 3 numbered sub-passes
     (collect names, set up scope, fold calls).

   - ~scavenge~ (src/self/scavenger.til:212) has 5 numbered
     sub-passes (build top maps, seed worklist, BFS, filter
     top-level decls, filter ns methods).

   - ~interpret~ (src/self/interpreter.til:1622) walks core and user
     programs through 5 sub-procs each before evaluation:
     ~ffi_init_scan_program~, ~interpret_register_defs~,
     ~interpret_register_aliases~, ~interpreter_init_ns~,
     ~interpret_copy_alias_ns~, then ~eval_body~. So core/user are
     each walked ~6 times before execution.

   - ~build~ (src/self/builder.til:3617-3699) calls roughly a dozen
     emit_* helpers, each walking core and user programs:
     build_register_lookups, build_register_funcsig_names,
     emit_monolithic_header, emit_ext_func_declarations,
     emit_all_forward_declarations, emit_global_declarations,
     emit_function_bodies, emit_dyn_call_bodies,
     emit_dyn_fn_wrappers, emit_dyn_has_bodies,
     emit_collection_helpers, plus emit_test_main /
     emit_script_main / emit_lib_init at the end.

   What I want: one pass per phase. Not one pass for some sub-passes
   inside the typer ([[./146.org][#146]]'s scope). Every phase: lexer, parser,
   initer, typer, constfolder, scavenger, builder, interpreter -- one
   walk over the AST (or token stream / source for lexer/parser).

   Related:
   - [[./146.org][#146]] -- partial step inside the typer only: merge the
     desugar/insert sub-passes
   - [[./144.org][#144]] -- per-pass clone-and-assign that this would also
     eliminate
   - [[./109.org][#109]] -- the leaks dominated by these repeated rebuilds
   - [[../fixed/204.org][#204]] -- asap-destruction extracted into the
     garbager phase; the per-body (function/if/while/block/catch)
     garbager calls still run inline in the typer, and lifting them
     into the single ~garbager_destroy(ctx)~ walk is part of this
     issue's per-body scope-cache work
