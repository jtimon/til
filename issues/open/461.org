** WIP #461 Simplify borrow-aware last-use destruction and reduce analysis cost

Revisit how much lifetime protection til should provide around non-owning
references and automatic last-use destruction. The reference-rebinding work
in #453 (merged as ~7a7ce5a51~) prompted a reported performance regression and
this policy question: should using a ref keep its owner alive, or should the
programmer be responsible for keeping the owner live?

~ref~ does not own its pointee. ~mut~ permits mutation; it does not transfer
ownership. Extending an owner's lifetime because a reference is used later
is an additional analysis policy, not a consequence of reference ownership.

*** Motivating case

  Schematic source, with ~borrow~ returning a reference to its argument:

  #+begin_src til
  a := first.clone()
  b := second.clone()
  ref mut alias := borrow(a)
  ref source := borrow(b)
  alias = source
  println(alias.text)
  #+end_src

  After rebinding, ~alias~ points at ~b~. Neither reference owns ~b~.
  Borrow-aware analysis retains ~b~ through the print. A simpler last-use
  policy could destroy ~b~ after its last direct use, making the later
  reference use a programmer error. In this example, writing ~println(b.text)~
  directly makes the owner's use explicit. Accessors, containers and conditional
  reference selection make less obvious versions of the same question.

*** Separate the decisions

  Preserve the two reference-operation fixes from #453:

  - Rebinding retargets the reference rather than overwriting its old pointee.
  - Rebinding a non-owning reference does not destroy its old pointee.

  Evaluate lifetime extension separately. Removing it changes when owned
  values and their resources are destroyed and which programs are valid; it
  is a language-policy change, not merely a faster implementation. The current
  analysis is not a complete dangling-reference proof, especially across raw
  pointers, Dynamic, explicit frees and FFI.
