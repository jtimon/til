** OPEN #476 `throw x` types a shadowing local from the outer same-named declaration

Found while fixing [[../fixed/471.org][#471]]. The throw lowering types
the value of ~throw x~ by name with ~guess_local_type~, which returns the
FIRST declaration of ~x~ anywhere in the function, ignoring nested-body
scopes. When a nested-body ~x~ shadows an outer ~x~ of another type, the
throw is typed as the outer one.

*** Reproduction

  ~tmp/bug476.til~:

  #+begin_src til
  mode cli
  Oops := struct { code: I64 = 0 }
  fail := proc(flag: Bool) throws Oops {
      e := 10
      if flag {
          e := Oops(code=7)
          throw e
      }
      println(e.to_str())
  }
  main := proc() {
      fail(true)?
      catch (err: Oops) { println(format("caught ", err.code.to_str())) }
  }
  #+end_src

  Observed on master ~e523e73~, interpreter and C, USize32 and USize64:

  #+begin_src text
  tmp/bug476.til:4:5: error: function may throw 'I64' but it is not in the throws clause; declare 'throws I64' or catch it
  tmp/bug476.til:4:5: error: 'throws Oops' is declared but 'Oops' is never thrown -- remove it from the throws clause
  tmp/bug476.til:7:9: error: '_err_I64' assignment type mismatch
  3 type error(s) found
  #+end_src

  Expected: prints ~caught 7~. Renaming the outer ~e~ (no shadowing)
  prints ~caught 7~ on both backends.

*** Notes

  Every whole-function lookup of a thrown identifier's type in
  ~src/self/desugarer.til~ has this flaw:
  - ~throw_type_name_for_with_body~ (its ~.Ident~ arm calls
    ~guess_local_type(ctx.scope, body, ...)~), called from
    ~subtree_has_throw_type~, the throws validation/collection sites, and
    the Throw case of ~process_throw_catch_in_body~ -- where it runs
    BEFORE the lexical ~lowering_param_types~ map #471 introduced, so
    that map never gets a say for this shape;
  - ~annotate_throw_ident_expr_types~
    (~guess_local_type(scope, root_body, ...)~).

  The #471 lexical map (a declaration enters at the next statement,
  untypable ones shadow as "", dropped at body end) is the model; the
  passes that run outside ~process_throw_catch_in_body~ have no lexical
  state and need their own scoped walk.
