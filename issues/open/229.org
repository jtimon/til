** OPEN #229 Support user-defined enum/struct types as main() CLI args

  Today a program whose ~main()~ takes a CLI argument can only use the
  built-in parseable types: ~Str~, ~Bool~, ~F32~, ~F64~, and the integer family
  (~I8/U8/I16/U16/I32/U32/I64/U64/USize/UPtr~). Any other type is rejected
  up front by ~validate_cli_main~ (see ~src/self/loader.til~). This issue
  extends that set to user-defined ~enum~ and ~struct~ types.

  Reviewed against master ~4f976d78e~ on 2026-10-31. Both float widths
  already work in the validation, C parsing and interpreter paths. This
  issue remains about user-defined enums/structs, not float enablement.
  The review inspected code and registered tests; it did not rerun the
  runtime tests.

*** Current implementation map

   Parsing/validation and reachability must stay in sync. The old
   three-location list omitted scavenger roots and named a removed helper:

   1. [[file:../../src/self/loader.til][validate_cli_main(lp: LoadedProgram)]] checks parameter names directly
      against the supported set; there is no ~cli_arg_type_supported~
      function now. The validator already has ~LoadedProgram~ and its
      context. Enum/struct acceptance needs definition-aware validation
      instead of merely adding more string comparisons. Variadic parameters
      are checked by element type.

   2. [[file:../../src/self/c_codegen.til][cli_box_expr(ttype, arg, by_value)]] is in ~c_codegen.til~, not
      ~builder.til~. ~emit_cli_parse_value~ selects value, stack-backed or
      boxed bindings for fixed/variadic arguments. New aggregate parsers
      must preserve that storage/ownership contract, rather than returning
      a tag scalar where an enum value is required.

   3. [[file:../../src/self/interpreter.til][parse_cli_arg(s, type_name, ctx)]] allocates raw result storage
      through ~dispatch_result_alloc~ and writes the parsed value. It no
      longer constructs the historical ~Value~ enum. Enum construction
      must use the current interpreter layout and ownership rules.

   4. [[file:../../src/self/scavenger.til][seed_cli_arg_helpers / seed_cli_main_arg_roots]] root the exact
      conversions needed by main's signature, plus deletion for variadic
      elements. Any new parser/constructor/deletion dependency must survive
      scavenging even when referenced only by the generated entry wrapper.

   ~validate_cli_main~ is shared frontend validation. Extending it also
   changes what reaches alternative backends; check their CLI entry
   restrictions rather than assuming the C/interpreter implementation
   establishes support on every target.

*** Phase 1: enums (tractable)

   Scope: enums whose variants are all payload-less (e.g.
   ~Color := enum { Red, Green, Blue }~). Parse the argv string by
   matching it against the variant names.

   - C emitter ~cli_box_expr~: for enum ~E~, emit a dispatch comparing
     the argv text against its variant names. On match construct the
     corresponding enum using its current representation; on mismatch
     report the bad value and exit nonzero. The current helper takes only
     strings and a storage flag, so definition-aware parsing needs access
     to the enum definition through the emitter context. Do not assume
     the whole enum value is represented by its tag alone.
   - interpreter ~parse_cli_arg~: look up the enum def in ~ctx~, match the
     variant name, construct the enum result (mirror how enum literals are
     evaluated).
   - ~validate_cli_main~: accept a parameter when its type resolves to an
     enum declaration all of whose variants are payload-less. Reject payload-carrying
     enums in phase 1 with a clear message (their payloads would need
     parsing too).

*** Phase 2: structs (harder, optional)

   Needs a textual struct-literal grammar for the CLI (e.g.
   ~field=value,field=value~ or a JSON-ish form) plus a parser that
   recurses through field types using the same per-field logic as
   ~cli_box_expr~ / ~parse_cli_arg~. Defer until phase 1 lands and there is
   a concrete use case; the field grammar is the main design decision.
