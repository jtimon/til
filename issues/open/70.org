** WIP #70 Constfolder: emit recursively serializable compile-time values

  The original issue predates value-backed globals, typed raw interpreter
  storage, namespace data globals, configurable enum tags, and the current
  mode registry. Its ~max_u64~, ~MODE_SCRIPT~, and ~core_modes~ examples no
  longer exist, and its old ~Value.Struct~ / ~Value.Enum~ implementation
  notes no longer describe the compiler.

*** Current contract

  Fold pure, target-correct expressions whose results are recursively
  serializable. Borrowed references, function pointers, ~Dynamic~, opaque
  runtime pointers, and values whose meaning depends on pointer identity are
  not serializable constants. "Any compile-time-known expression" was too
  broad: compile-time evaluation and representation as a target C value are
  separate requirements.

*** Already complete

  - Primitive, Str, nested POD-struct, no-payload enum, and payload-enum
    pure-call results fold through ~raw_to_expr~.
  - Nested enum payloads recurse through ~raw_to_expr~ and are covered by
    ~test_nested_enum_payload_return_fold~.
  - Ordinary top-level globals use value storage and generated ~extern~
    declarations ([[./104.org][#104]]).
  - Namespace data has flattened C names, file-scope definitions, and
    dependency-ordered runtime initialization (for example ~U8.MAX~ becomes
    ~U8_MAX~).
  - The handwritten-C const-parameter blocker was fixed independently at
    the ext boundary. General generated-C const propagation is not a
    prerequisite for this issue.

*** Remaining work

  - Fold Vec/Array/Map-valued pure calls and macros. Evaluation is no longer
    the primary blocker: the constfolder explicitly skips these results,
    and ~raw_to_expr~ has no target-neutral representation for their backing
    buffers.

*** Representation for collections

  Existing AST literals and constructors are sufficient for scalars, Str,
  POD structs, and enums. They cannot represent a collection's typed backing
  buffer after collection literals have been desugared, while retaining raw
  EvalHeap bytes would preserve host pointers/layout and outlive the heap
  that owns them.

  Add one post-typecheck internal AST value: a precomputed sequence carrying
  its concrete type, capacity, stable ordinal, and recursively converted
  element children. Constfolder produces it; the interpreter materializes a
  fresh runtime collection; C codegen emits a typed static template and
  clones that template for owned locals. A Map remains its existing struct
  constructor containing precomputed key/value Vecs. This creates no cache,
  file format, generated directory, dependency, or alternate source tree.
