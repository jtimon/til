** WIP #272 Garbager system: single ownership authority, no manual memory outside core

*** Current assessment (master 7b20f9811)

The leak-era inventory and experiments below are historical. They must not
be reapplied as pending fixes. The constfolder and REPL audits below found
and fixed owned-argument leaks on recovered aborts, plus a global-replacement
leak exposed by instrumenting the REPL smoke test. This issue remains WIP
for the remaining runtime/FFI ownership-boundary audit.

Use the placement rule already recorded in
[[../fixed/302.org][#302]]: manual memory belongs in destructors,
allocators, the machinery implementing the ownership model, and documented
FFI islands. The garbager decides the lifetimes of ordinary til-owned
values. The interpreter executes that contract and reclaims storage it
creates to represent the program. Its malloc/free calls are not wrong
solely because they live outside core. The old absolute ban below predates
that correction; a runtime/FFI exemption still needs a concrete ownership
contract, not just a Dynamic-typed pointer.

*** Constfolder ownership audit: completed slice

Traced ~expr_to_known_raw~, ~is_known~, ~add_known_call_arg~,
~try_eval_call~, ~raw_to_expr~, and evaluation-scope cleanup:

  - Literal primitives allocate a block; reading a known primitive first
    loads its inline word and re-boxes it for ~is_known~'s uniform result
    contract. The caller loads the value and frees that block once after
    conversion. That free is necessary: ~raw_result_drop~ on a primitive
    word deliberately frees nothing.
  - Known aggregates are independent owned clones. Binding them in the
    temporary evaluation scope transfers the block; owned callee parameters
    can move it onward and mark the source binding moved. Borrowed reads
    keep the source owner. Rebuilt Exprs copy value data rather than keeping
    pointers into these temporary blocks.
  - Ordinary unknown arguments fail the ~all_comptime~ gate before call
    evaluation. The internal argument-miss exits also drop any earlier
    bound arguments and release the temporary scope before returning None
    or reporting a required-macro error.
  - Result conversion failure does not skip cleanup: ~raw_to_expr~ returns
    None, then ~try_eval_call~ drops the owned result, drops its temporary
    bindings, and releases the scope. An enum containing a struct with an
    owned Str field exercised this branch in a debugger probe.

The real defect was deeper in comptime abort unwinding. ~is_known~ cloned
two owned Str arguments, the call moved them into its own scope, and panic
aborted before the scheduled deletes ran. ~scope_free~ freed only their
outer slots, orphaning the c_str buffers; cleanup of the caller's evaluation
scope could not reach arguments it had already moved away. With literal
owned arguments, the probe produced an ordinary LeakSanitizer report of
35 bytes in two allocations through ~is_known~ -> ~heap_clone~.

The first fix made ~scope_free~ drop still-owned nested payloads when a scope
exits during an aborted comptime evaluation. The REPL follow-up below extends
that recovery rule. Borrowed, moved, raw-allocation,
static-callable, and already-released payload cases keep their ownership
rules. Normal execution still leaves program destruction to the AST; this
is exception unwinding, not a return to unconditional deep scope teardown.

The abort is a failed optional evaluation, not a typer error or a crash of
the compiler. ~h_exit~ records ~eval_aborted~; ~try_eval_call~ cleans up and
returns None, keeping the call for runtime. Required macro evaluation would
instead report an error. The constfolder optimizes expressions inside proc
and test definitions, but never evaluates a proc call as a constant.

Regression in ~test/constfold.til~ now uses three named tests:
~test_constfold_abort_owned_args~, ~test_constfold_abort_branch_locals~, and
~test_constfold_abort_after_release~. Each has an explicitly runtime-only
proc guard (with ~noop_proc~) returning false. Known func calls inside the
guarded branches are nevertheless attempted during expression folding;
~cf_abort_if_nonempty~ reaches ~exit(1)~ and abandons those attempts. The
regression uses no print/panic-message path. The calls remain in emitted C,
the runtime guards prevent their execution, and the tests also assert the
funcs' successful empty-input paths. The third case explicitly deletes a
local's payload with call_free=false before abort, checking that unwinding
respects ~payload_released~ and does not destroy it twice.

The named tests run successfully under interpretation and compiled
execution. ~test/constfold.c~ now contains their bodies, runtime guards,
remaining abort calls, and registrations, rather than only unused procs
that disappear during scavenging.

Focused verification: debugger counters confirmed successful result
conversion, failed aggregate conversion, and a recovered abort. The
unknown-argument fixture was excluded by the outer comptime gate, as the
source trace predicts. The fixed abort probe no longer reports the 35-byte
leak; its live-byte probe matches the empty control. Residual live bytes in
the controls/conversion probe were traced with LeakSanitizer roots disabled
to typer global borrow-memo sets and CLI arrays, not constfolder temporary
results. Those numbers are diagnostic evidence, not a new leak baseline
or a claim that all live allocations at process teardown are zero.

The initial full-ASAN verification passed 498/498. The expanded regression
was then compiled with an ASAN build of pre-fix master's checked-in boot
compiler: it reported 136 bytes in six leaked allocations, with five
allocations traced through ~is_known~ -> ~heap_clone~ and another from
branch-local formatting. The fixed compiler translated the same source
without a normal LeakSanitizer error. This before/after comparison checks
that the regression actually exposes the missing unwind cleanup.

Final verification on the rebased source: ~make clean && make test~ passed
496/496 under full ASAN. All three named abort-cleanup tests passed, and
the regenerated ~test/constfold.c~ includes the guarded calls and test
registrations.

*** REPL abort and global replacement: completed slice

The runtime REPL uses the same ~eval_aborted~ state to recover from a failing
exit, but the first cleanup fix required ~constfold_active~. A piped session
with a proc taking two owned strings reached panic, printed its message,
survived the failed turn, and preserved an earlier string binding. At process
shutdown LeakSanitizer reported 29 bytes in two leaked argument buffers.
The proc call was runtime execution, not constant folding.

~scope_free~ now handles an aborted evaluation when either ~constfold_active~
or ~repl_session~ is set. Ordinary successful execution keeps the slot-only
teardown rule; borrowed, moved, raw-allocation, static-callable, and already-
released payload cases retain their existing ownership exclusions. The
focused owned-argument session no longer reports that LeakSanitizer error.

Regression: ~test/repl_ownership.til~ exercises owned-argument panics through both
the incremental delta path and the import-driven full-load path. It checks
that subsequent turns run, earlier bindings retain their contents, and the
tail after the failing call does not execute. The driver now takes the
compiler selected by the suite's existing ~--til-bin~ option, so full-ASAN
testing actually runs the REPL child under ASAN instead of always spawning
~bin/til~. A nonzero child exit fails the driver and shows its captured output.

That instrumentation exposed another ownership defect: refreshing help data
overwrote the owned ~__til_info_blob__~ and ~__til_docs_blob__~ globals without
dropping their old payloads. The smoke test retained 301901 bytes in two
documentation buffers after the abort leak was fixed. In a smaller session,
repeated help-data refreshes leaked an additional pair at each replacement.
The emitted C also assigned to those globals without old-value deletes.

Root cause: ~flag_outer_assign_rebinds~ excluded globals because their slots
outlive the function body. Slot lifetime does not extend the lifetime of the
payload being overwritten. The garbager now records ~save_old_delete~ for
the same aggregate rebind shapes on globals as on enclosing function locals;
ref targets keep their existing borrow-rebind rule. Both the interpreter
and C backend consume that AST decision. The doc library needs no manual
cleanup calls. Read-only scope parameters lost their now-redundant ~mut~
qualifier as required by the typer.

~test/globals.til~ pins function-driven global replacement with an observable
destructor count, plus Str replacement whose RHS borrows the old global.
The destructor-count assertion fails before the fix. With both fixes, the
ASAN-driven REPL smoke test passes without the documentation-buffer report;
both panic paths survive and preserve their earlier binding.

Verification: ~make clean && make test_two_pass~ passed 495/495, including
~repl_help~ and both backends of ~test/globals.til~. This is a ~Two-pass:~
change because the garbager's recorded global cleanup changes emitted C.

*** Historical investigation (2026-06)

Architectural cleanup driven by the 2026-06 leak-hunting sessions. The
leaks were fixed point-by-point, but several fixes (and pre-existing
code) violate the intended layering. The principles, as stated by Jorge:

  - ~Dynamic~ is just ~void*~ in C. A Dynamic value does NOT imply a
    malloc'd box; it is only a pointer. Error messages / checks that say
    "raw malloc'd memory typed Dynamic" conflate the two.
  - ~ref~ must never be malloc'd. (There may already be a typer error
    for this; verify and extend coverage.)
  - ~malloc~ / ~free~ / raw pointer surgery belong ONLY in the core
    collections (Str, Array, Vec, Set, Map) and the C bridge. Nothing in
    parser/initer/typer/loader/builder/interpreter/dispatch should call
    them directly.
  - ~delete~ is called manually only from other ~delete~ implementations
    (the destructor tree). Every other delete is the garbager's job.
  - The builder and the interpreter must not invent clone/malloc/delete
    calls; when they do, they paper over garbager gaps and create
    double-free/leak coupling. The garbager is the single authority for
     where a value dies (Mojo-style ASAP, see doc/concepts/ownership.org's
    "Relation to Mojo").

*** Known violations / smells to remove (inventory, not exhaustive)

  - ~Expr.replace_with~ (core/ast.til): added to fix the in-place
    rewrite leaks (move() overwrites). It works, but it is a manual-
    memory primitive in disguise. The cleaner shape is rewriting via the
    parent: ~parent.children.set(i, own new_expr)~ (Vec.set already
    deep-deletes the old element). Audit the 6 call sites; most have the
    parent at hand. Sites that rewrite a node they only have a ~ref~ to
    (init_substitute_idents' walk) need the walk to carry the parent.
    Then delete replace_with and the move()-onto-managed typer error can
    point at children.set instead.
  - ~ext_dispatch_ffi~ scalar boxes + boxed_flags array (dispatch.til):
    hand-rolled malloc/flag/free. Works, but the marshaling layer should
    own a typed buffer abstraction instead.
  - Interpreter Value model: make_str_value / shallow_copy_value /
    borrow_value memcpy aliasing; scope_free cannot deep-delete Struct
    payloads because returning a local hands out an UNFLAGGED alias of
    the cell payload (see NOTE in scope_free; deep-delete attempt
    segfaults the compile pipeline). This is the dominant remaining leak
    (make_str_value ~8.8K, eval_call ~5K, widen_numeric ~3.4K on
    strings.til interpret). Fix = give returns a move/borrow contract
    (null the cell on return-of-local, or flag the alias borrowed), then
    scope_free can deep-delete and the manual Enum-only special case
    dies.
  - builder.til / interpreter.til: audit for emitted clone/malloc/delete
    that compensate for garbager behavior (e.g. emit_as_ptr's
    malloc-copy wrap for own+stack_local; the POD-enum clone shortcut
    interactions documented in garbager.til). Each is either a garbager
    gap or dead compensation.
  - free(own p) on a Dynamic local at PROGRAM scope emits invalid C
    (`*_oa = malloc(sizeof(void))` own-box). Builder bug, reproduced
    2026-06-10; works inside proc bodies.

*** Garbager structural weaknesses (the bug class behind the leaks)

  - Liveness/transfer tracking is STATEMENT-INDEX based (decl_index /
    last_use / own_transfer as I32 indexes into one body's children),
    not path-based. Every fixed bug was this model leaking at a path the
    indexes cannot express: conditional transfer (sinking), transfer
    after early exits (this week's fix), hoisted-view aliasing (#238 /
    #250 taint), FieldAccess-base FCalls (never had an index at all
    until hoisted). A per-path (CFG) liveness pass would subsume the
    accumulated special cases. Mojo does ASAP destruction on a real CFG
    with use-def chains; doc/concepts/ownership.org has the references.
  - The garbager only sees one body at a time and trusts hoisting to
    surface every owned temp as a named local. Any expression shape the
    hoister misses is invisible (the f().field class). Inverting the
    contract -- garbager walks expressions, not just statements -- would
    remove the hoist coupling.
