:PROPERTIES:
:CUSTOM_ID: til.src.self.lexer.Vec__SourceDiagnostic.new

:END:

Create a new empty Vec for elements of type T. Lazy: no allocation
until the first push -- an empty Vec is (data=NULL, count=0, cap=0),
and the grow sites below seed cap 0->1 on the first insert. This keeps
the many containers that stay empty (e.g. the unused maps in a fresh
Scope) allocation-free, which is the dominant per-call interpreter cost.

* Vec__SourceDiagnostic.with_capacity
:PROPERTIES:
:CUSTOM_ID: til.src.self.lexer.Vec__SourceDiagnostic.with_capacity
:group: Compiler frontend
:END:

Create an empty Vec pre-sized for ~n~ elements, so pushing up to ~n~
items reallocs zero times. Use at call sites where the final length is
known up front (cloning a Vec of known length, building a fixed arg
list, ...) to avoid the 1->2->4->...->n grow-and-realloc churn that
~new()~ + repeated ~push~ pays. n=0 behaves like new(): lazy-empty,
no allocation (the grow sites seed cap 0->1 on the first insert).

* Vec__SourceDiagnostic.take
:PROPERTIES:
:CUSTOM_ID: til.src.self.lexer.Vec__SourceDiagnostic.take
:group: Compiler frontend
:END:

Take the contents out: the returned Vec owns self's buffer and
self is left lazy-empty. No element is copied or cloned.

This is how a struct FIELD hands its contents over
(~mut old := body.children.take()~): a field cannot be an ~own~
argument or receiver, because the callee would then free the
ADDRESS OF THE FIELD -- the compiler dies with "free(): invalid
pointer" compiling itself. Everything the caller can give away
uses the two move forms below instead.

* Vec__SourceDiagnostic.move_to
:PROPERTIES:
:CUSTOM_ID: til.src.self.lexer.Vec__SourceDiagnostic.move_to
:group: Compiler frontend
:END:

Give self's contents to ~dest~, which drops whatever it held.
SELF is consumed, so the receiver is the owned one and the call
spells the type out: ~Vec(T).move_to(own src, dest)~.

The three fields move as BYTES on purpose:
~dest.data = self.data~ drops dest's old pointer (right) and then
~self.data = 0~ drops the pointer dest just adopted -- a double
free, which is what the emitted C does with field assignment.
Blanking the source leaves a genuinely valid lazy-empty Vec, so
a later push on it allocates afresh instead of reallocating a
buffer that now belongs to someone else.
