    Vec__Token.new

    Group
    Compiler frontend

    Create a new empty Vec for elements of type T. Lazy: no allocation until the first push -- an empty Vec is (dataNULL, count0, cap=0), and the grow sites below seed cap 0->1 on the first insert. This keeps the many containers that stay empty (e.g. the unused maps in a fresh Scope) allocation-free, which is the dominant per-call interpreter cost.

    func () returns Vec__Token

    Vec__Token.with_capacity

    Group
    Compiler frontend

    Create an empty Vec pre-sized for n elements, so pushing up to n items reallocs zero times. Use at call sites where the final length is known up front (cloning a Vec of known length, building a fixed arg list, ...) to avoid the 1->2->4->...->n grow-and-realloc churn that new() + repeated push pays. n=0 behaves like new(): lazy-empty, no allocation (the grow sites seed cap 0->1 on the first insert).

    func (shallow n: USize) returns Vec__Token

    Vec__Token.take

    Group
    Compiler frontend

    Take the contents out: the returned Vec owns self's buffer and self is left lazy-empty. No element is copied or cloned.

    This is how a struct FIELD hands its contents over (mut old := body.children.take()): a field cannot be an own argument or receiver, because the callee would then free the ADDRESS OF THE FIELD -- the compiler dies with "free(): invalid pointer" compiling itself. Everything the caller can give away uses the two move forms below instead.

    func (mut self: Vec__Token) returns Vec__Token

    Vec__Token.move_to

    Group
    Compiler frontend

    Give self's contents to dest, which drops whatever it held. SELF is consumed, so the receiver is the owned one and the call spells the type out: Vec(T).move_to(own src, dest).

    The three fields move as BYTES on purpose: dest.data = self.data drops dest's old pointer (right) and then self.data = 0 drops the pointer dest just adopted -- a double free, which is what the emitted C does with field assignment. Blanking the source leaves a genuinely valid lazy-empty Vec, so a later push on it allocates afresh instead of reallocating a buffer that now belongs to someone else.

    func (own self: Vec__Token, mut dest: Vec__Token)

    Vec__Token.move_from

    Group
    Compiler frontend

    Take other's contents, dropping whatever self held. OTHER is consumed -- it is the value being emptied, so it is the owned argument: dest.move_from(own src).

    func (mut self: Vec__Token, own other: Vec__Token)

    Vec__Token.unsafe_get

    Group
    Compiler frontend

    Unchecked element access: return a reference to the element at index i with NO bounds check. The caller must prove i < len(). This is the unchecked core that get wraps; for-in uses it directly because its _fi < len() termination test already proves the index in bounds (issue #284).

    Vec__Token.truncate

    Group
    Compiler frontend

    Drop the elements from index n to the end, freeing each via elem_delete, and set count to n (the survivors [0, n) are left untouched). Panics if n exceeds len. This is the container home for a pop-and-free-the-tail loop shrinking a Vec back to a mark.

    func (mut self: Vec__Token, shallow n: USize)

    Vec__Token.unsafe_set

    Group
    Compiler frontend

    Overwrite the element at index i without a bounds check, dropping the old value. Caller guarantees i < self.count; the write-side mirror of unsafe_get (issue #284).

    func (mut self: Vec__Token, shallow i: USize, own val: Token)
