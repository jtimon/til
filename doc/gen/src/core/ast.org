:PROPERTIES:

:END:

The contained value; PANICS on None, ala Rust's unwrap. For the
~if o.is_none() { ... }~ + ~o.unwrap()~ idiom, where the caller
has already handled absence and unwrapping cannot fail. Prefer
a ~switch~ when both arms do real work, and ~unwrap_or~ when a
default is meaningful -- reach for this only when None is
unreachable by construction, so it fails loudly if that ever
stops being true.

* Option__Expr.take
:PROPERTIES:
:CUSTOM_ID: til.src.core.ast.Option__Expr.take
:group: Core
:END:

The contained value, MOVED out; PANICS on None, like unwrap.
unwrap only BORROWS self, so for an owned payload it must hand
back a deep clone; this consumes the Option instead, so the
payload's bytes move and only the enum shell is freed (#321).
Use it wherever the caller takes ownership of what the Option
held -- an ~Option(Expr)~ returned by an AST helper, say, where
a clone would copy a whole subtree and break node identity.

* LiteralNumData.is_float
:PROPERTIES:
:CUSTOM_ID: til.src.core.ast.LiteralNumData.is_float
:group: Core
:END:

Does the literal's TEXT spell a float? The lexer accepts a fractional
part ('.' then a digit) and an exponent (e/E, optional sign, digits)
only on the non-prefixed decimal path, so a 0x/0b/0o literal is an
integer even though hex digits include 'e' and 'E'. Callers that infer
a type FROM a literal need this; a literal that narrows from context
(declaration or parameter type) keeps that type instead.

* member_name_of
:PROPERTIES:
:CUSTOM_ID: til.src.core.ast.member_name_of
:group: Core
:END:

Reverse index lookup shared by every *_name_at accessor: the name whose
stored position is ~pos~, None for a position no entry points at (one
shadowed by a later duplicate name). The three *_name_at wrappers
unwrap it: their call sites all walk positions the def itself reports
and use the name unchecked, so a miss means the index and the decl Vec
disagree, and unwrap says so loudly instead of handing back a null Str.

Instantiating Option in this unit needed two prerequisites: the #303
noreturn seed made order-independent (seed_noreturn_chain, loader.til),
since Option.unwrap ends in ~case: panic~ and core.til imports ast
before exit; and the borrowed-Str call-shape fix, since
this is the first Option(ref Str) interpreted code calls.

#+begin_src til
func member_name_of(idx: Map__Str_USize, pos: USize) returns shallow Option__ref_Str
#+end_src

* Vec__Declaration.move_to
:PROPERTIES:
:CUSTOM_ID: til.src.core.ast.Vec__Declaration.move_to
:group: Core
:END:

Give self's contents to ~dest~, which drops whatever it held.
SELF is consumed, so the receiver is the owned one and the call
spells the type out: ~Vec(T).move_to(own src, dest)~.

The three fields move as BYTES on purpose:
~dest.data = self.data~ drops dest's old pointer (right) and then
~self.data = 0~ drops the pointer dest just adopted -- a double
free, which is what the emitted C does with field assignment.
Blanking the source leaves a genuinely valid lazy-empty Vec, so
a later push on it allocates afresh instead of reallocating a
buffer that now belongs to someone else.

* Vec__USize.take
:PROPERTIES:
:CUSTOM_ID: til.src.core.ast.Vec__USize.take
:group: Core
:END:

Take the contents out: the returned Vec owns self's buffer and
self is left lazy-empty. No element is copied or cloned.

This is how a struct FIELD hands its contents over
(~mut old := body.children.take()~): a field cannot be an ~own~
argument or receiver, because the callee would then free the
ADDRESS OF THE FIELD -- the compiler dies with "free(): invalid
pointer" compiling itself. Everything the caller can give away
uses the two move forms below instead.

* Vec__USize.move_to
:PROPERTIES:
:CUSTOM_ID: til.src.core.ast.Vec__USize.move_to
:group: Core
:END:

Give self's contents to ~dest~, which drops whatever it held.
SELF is consumed, so the receiver is the owned one and the call
spells the type out: ~Vec(T).move_to(own src, dest)~.

The three fields move as BYTES on purpose:
~dest.data = self.data~ drops dest's old pointer (right) and then
~self.data = 0~ drops the pointer dest just adopted -- a double
free, which is what the emitted C does with field assignment.
Blanking the source leaves a genuinely valid lazy-empty Vec, so
a later push on it allocates afresh instead of reallocating a
buffer that now belongs to someone else.

func Vec__USize.move_to(own self: Vec__USize, mut dest: Vec__USize)
