* Declarations

Til uses name-first declarations. The two basic forms are:

#+begin_src til
name := expression
name : Type = expression
#+end_src

~:=~ asks Til to infer the type from the expression. Use ~: Type =~ when the
declaration needs an explicit type. After a mutable name has been declared,
plain ~=~ assigns a new value to it.

This unified, name-first shape resembles Jai and Odin: the name comes before
the value that defines it, and the right-hand side says whether the declaration
is data, a function, a struct, or an enum. Til also has Rust-like choices in
this area: local bindings are immutable by default, mutation is explicit, and
enums may carry typed payloads.

** Values and mutability

An inferred immutable value needs no declaration keyword:

#+begin_src til
answer := 42
message := "hello"
#+end_src

Add ~mut~ when the binding will be assigned again:

#+begin_src til
mut count := 0
count = count.add(1)
#+end_src

The same syntax works with an explicit type:

#+begin_src til
limit : I64 = 100
mut title : Str = "draft"
title = "final"
#+end_src

Locals, parameters, top-level values, and namespace declarations are
immutable by default. Struct fields are the deliberate exception: fields are
mutable by default and ~const~ opts a field out. The complete context-sensitive
rules are in [[file:../concepts/qualifiers.org][the qualifier reference]].

** Functions and procedures

A function is a value declared with a ~func~ expression:

#+begin_src til
double := func(n: I64) returns I64 {
    return n.mul(2)
}
#+end_src

A ~proc~ has the same declaration shape but may perform effects, including
calling other procedures:

#+begin_src til
greet := proc(name: Str) {
    println("Hello, ", name)
}
#+end_src

Both ~func~ and ~proc~ may return values. The distinction is effects, not
whether a value is returned: a ~func~ cannot call a ~proc~. See
[[file:../concepts/functions.org][Function kinds]] for ordinary, external,
core, lazy, macro, and test callables.

** Structs

A struct definition is another right-hand-side value:

#+begin_src til
Point := struct {
    x : I64 = 0
    y : I64 = 0
    const dimensions := 2
}

p := Point(x = 3, y = 4)
#+end_src

Fields use the same name-first forms. Construction names the fields, while
omitted fields use their declared defaults. Unlike local bindings, ~x~ and ~y~
are mutable fields; ~dimensions~ is immutable because it is marked ~const~.

Til generates common operations such as ~clone~, ~delete~, and ~size~ when a
type does not provide its own. The full list is in
[[file:../concepts/auto.org][Auto-generated methods]].

** Enums

An enum uses the same declaration operator. Variants may be plain tags or
carry one typed payload:

#+begin_src til
Token := enum {
    Number: I64
    End
}

number := Token.Number(42)
end_token := Token.End
#+end_src

Variants live under the enum's name. Payload enums support exhaustive
~switch~ and value-producing ~match~ expressions; their detailed behavior is
covered by [[file:../concepts/enums.org][Enum semantics]].

** Visibility

Declarations are public by default. Top-level functions, procedures, structs,
enums, and values are visible to importing files without a qualifier. The
~priv~ keyword opts one declaration out:

#+begin_src til
public_value := 1
priv implementation_value := 2

priv helper := func(n: I64) returns I64 {
    return n.add(implementation_value)
}

public_result := helper(public_value)
#+end_src

A top-level ~priv~ declaration remains usable throughout its declaring file
but is hidden from importers. On a struct field or namespace member, ~priv~ is
stricter: only that struct's own namespace functions may use it, even when
other code is in the same file.

See [[file:../../examples/priv_demo.til][examples/priv_demo.til]] for a worked
example. The complete visibility table and diagnostics are in
[[file:../concepts/qualifiers.org::*Visibility (priv keyword)][the qualifier reference]].

** Ownership qualifiers

Declarations and function signatures can also describe ownership. A plain
parameter borrows, ~mut~ permits writes through the borrow, ~own~ transfers a
value to the callee, and ~ref~ declares an explicit borrowed local, field, or
return. These qualifiers affect lifetime as well as generated representation;
read [[file:../concepts/ownership.org][Ownership and ASAP Destruction]] before
using the lower-level forms.
