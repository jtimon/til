* Errors and Testing

Til makes recoverable errors part of callable signatures. Tests use ordinary
Til code and run through both the interpreter and compiled backend.

** Declaring and throwing errors

Error values are normal types. ~throws~ lists the types a callable may raise,
and ~throw~ raises one:

#+begin_src til
DivideByZero := struct {}

safe_div := func(a: I64, b: I64) returns I64 throws DivideByZero {
    if b == 0 { throw DivideByZero() }
    return a / b
}
#+end_src

An error struct may carry fields when callers need diagnostic data.

** Propagating and catching

A call to a throwing callable must use postfix ~?~ or ~!~. ~?~ marks a call for
local handling or propagation:

#+begin_src til
show_division := proc(a: I64, b: I64) {
    result := safe_div(a, b)?
    catch (_err: DivideByZero) {
        println("cannot divide by zero")
        return
    }
    println(result.to_str())
}
#+end_src

A matching ~catch~ follows the throwing call in the same body. Without a local
catch, the enclosing callable must declare the propagated error in its own
~throws~ list.

Use ~!~ when failure is not recoverable at that call site:

#+begin_src til
answer := safe_div(84, 2)!
#+end_src

The bang form panics if the call throws. Checked indexing uses this behavior:
~values[index]~ is shorthand for a bang call to ~get~.

** Writing tests

~mode test~ makes named ~test()~ declarations entry points:

#+begin_src til
mode test

test_safe_division := test() {
    assert_eq(I64, safe_div(8, 2)!, 4)

    mut caught := false
    _ := safe_div(8, 0)?
    catch (_err: DivideByZero) {
        caught = true
    }
    expect(caught, "division by zero was caught")
}
#+end_src

~assert~ checks a Boolean condition. ~assert_eq~ compares two values of a named
type. ~expect~ accepts a condition and explanatory text, which is useful when a
failure needs context.

Run a test file with:

#+begin_src sh
til test arithmetic_test.til
#+end_src

Til runs the tests through the interpreter and then through a compiled test
executable. A test should therefore describe observable behavior rather than
backend details.

See [[file:../concepts/throws.org][Throw / catch]] for the full propagation and
lowering rules. The generated documentation under
[[file:../gen/index.org][doc/gen/]] lists the operations and error types exposed
by the core and standard libraries.
