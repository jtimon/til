* Current AST Representation Audit

Audit date: 2026-08-20

** Scope

This audit verifies the cleanup tracked by [[file:../../issues/fixed/130.org][#130]] against the current
~Expr~ representation and its principal payloads in [[file:../../src/core/ast.til][src/core/ast.til]].

** Current Shape

~Expr~ has four fields:

- ~node_type : NodeType~
- ~children : Vec(Expr)~
- ~line : U32~
- ~col : U32~

~NodeType~ is the single tagged payload union. Identifiers, literals,
declarations, calls, definitions, field accesses, loop metadata, cases,
matches, and capture blocks carry their data in the corresponding variant.
The former second tag, universal literal/name fields, universal type field,
path, struct name, and rewrite provenance fields are gone.

Source paths belong to compilation units and ~Context~. Per-node source
locations remain line/column pairs because diagnostics use them directly.

** Type Data

There is no universal ~Expr.til_type~. Type data lives where its lifetime and
meaning are defined:

- ~Declaration.til_type~ stores the declaration's semantic type.
- Typed value payloads such as ~FCallData~, ~LiteralNumData~,
  ~FieldAccessData~, and ~MatchData~ store their inferred result type.
- Other expression types are derived through the type-query chokepoint from
  the node payload and the current semantic context.
- Aggregate memory layout is held in ~Context.struct_layouts~, not in
  ~StructDef~ or ~EnumDef~.

This is payload-specific semantic state, not duplicate type storage on every
expression.

** Calls And Functions

~FCallData~ has eight fields. ~does_throw~ and ~is_bang~ are parse facts;
~own_args~, ~ref_args~, and ~splat_args~ are argument bitmaps;
~keep_outer_args~ and ~swap_replace~ record required rewrites; and ~til_type~
is the call's inferred result type. Variadic/keyword positions and counts,
callee signatures, method classification, and noreturn status are derived
from the resolved callee and call children rather than copied into the AST.

~FunctionDef~ is the payload of a function-definition node. Its
~sig : FuncSig~ stores the callable contract; capture, return-alias, and
generated-function metadata remain definition-only. These records are consumed
across typing, ownership analysis, and emission. ~namespace_decl~ is the sole AST
borrow remaining in these audited records: it points to the owning top-level
namespace declaration, is stable for the AST lifetime, and avoids storing
duplicate aggregate/member names on every definition.

The ~FuncSig~ / ~FunctionDef~ split keeps signature re-inference separate from
definition-only state without moving resolved-call facts to a side table.
~FuncSig.eq~ is structural over callable kind, ordered parameter types/
ownership/mutability, return type/ownership, variadic and keyword positions,
and ordered throws. Parameter names, docs, defaults, analysis flags, and
~return_shallow_explicit~ are not semantic identity; the last field records
parser provenance for diagnostics.

** Definitions And Bindings

- ~StructDef~ stores declaration-ordered fields and namespace members, their
  name indexes, C/interface metadata, and no runtime value or layout size.
- ~EnumDef~ stores one ~VariantDef~ record per variant. The former parallel
  variant payload/type/const/tag/ref collections are gone.
- ~Declaration.default_value~ is an owned ~Option(Expr)~. Runtime values live
  in interpreter environments rather than declarations.
- ~TypeBinding~ contains no ~func_def~ or ~struct_def~ Expr borrow. Definition
  Exprs live in scope-owned maps and are resolved through scope lookups.
- Field and aggregate layout facts live in ~FieldLayout~ / ~StructLayout~
  records owned by ~Context.struct_layouts~.

** Conclusion

The concrete cleanup identified by #130 is complete. ~Expr~ is a compact
four-field node around one tagged payload; runtime state, aggregate layout,
parallel enum metadata, copied call-resolution facts, and dangerous
definition back-references have all moved to their owning representations.
The remaining payload fields are syntax, semantic results, or cross-phase
facts with current readers.
