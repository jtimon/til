* Lessons learned

** Private mementos

  - Keep private, session-local notes under ~doc/bots/local_memento/~, not
    under ~tmp/~.
  - ~tmp/~ is wiped by ~make clean~, so it is the wrong place for notes
    meant to survive a build/test cycle.
  - Do not remind Jorge to push. Pushes are handled manually by humans in
    local sessions, and the reminder adds noise instead of value.

** Bootstrap interface migrations

  - If a source interface changes but old boot output still names the
    old entrypoint, use staged commits instead of trying to force the
    whole rename in one shot.
  - Use an ABC 3-commit ladder for pure source-level interface changes:
    A adds a temporary compatibility entrypoint such as ~new_newi~,
    B switches the public name, and C removes the temporary alias.
  - Use a 4-commit ladder when builder-generated raw C also spells the
    old public constructor name. Add an internal string-based helper
    first (for example ~new_type_name~), switch the raw C emission to
    that helper, then do the public-name flip and final cleanup.
  - Issue #173 used this pattern successfully for ~Set.new~,
    ~Map.new~,
    ~Vec.new~,
    and ~Array.new~.
  - Prefer lettered stages like A/B/C over numbered stages like 1/2/3
    in docs and commit messages. The labels keep their meaning even if
    bootstrap compatibility needs an extra commit in the middle.

** Type-token special cases

  - The ~dyn_type_to_str~ / type-token path is sensitive to whatever
    enum name old ~til_boot~ hardcodes into pass-1 rewrites and
    generated C.
  - If a cosmetic rename changes that enum's source-level name, a
    transitional alias can unblock the bootstrap compiler while keeping
    the new public spelling available to user code.

** REM comments

  - Keep ~REM~ comments when they still say something true.
  - They are low-cost breadcrumbs for the next session and often point
    directly at the weird bootstrap or ownership constraint that would
    otherwise need rediscovery.

** Host-specific code and CI

  - A branch chosen by ~host_os()~ is not covered by anything until a run
    actually takes it. ~test/repl_pty.til~ shipped with a BSD/macOS
    ~script~ invocation that no session had ever executed -- only the
    linux branch had run -- and both mac jobs went red the day it landed.
    "Selected by host_os" is not coverage; if the branch cannot be run
    where the work happens, say so in the commit instead of assuming.
  - After landing anything host-specific, READ the workflow results. That
    same failure was visible in the first CI run after the commit and was
    found days later, by opening the run rather than by anything in the
    repo pointing at it. Nothing notifies a session; go and look.
  - Do not assert on kernel-owned state. The mac failure was ~stty -g~
    compared before and after the REPL, differing in one bit: ~PENDIN~,
    which Darwin raises when input arrives with echo off and keeps across
    ~tcsetattr~. A raw-mode editor sets it by construction and no program
    can put it back, so the assertion could never pass. Compare the
    settings the code owns, and mask the ones it does not (~PENDIN~,
    ~FLUSHO~).

** Master vs worktree

  - For long serial bootstrap ladders where later commits depend on
    earlier ones landing immediately, doing the sequence directly on
    ~master~ can be less painful than carrying a long-lived worktree
    branch that must be rebased repeatedly.

** Remote sessions: git recovery and the shell hook

  - ~no-shell-antipatterns.sh~ blocks every command line containing
    ~git stash~, including ~pop~ and ~list~. If a stash happens anyway,
    recover it without naming the command:
    ~git diff refs/stash^1 refs/stash > tmp/recover.patch~, then
    ~git apply tmp/recover.patch~.
  - The same hook's ~tail -f~ check also fires on ~tail -1 && git push
    --force-with-lease~ (it scans past ~&&~ to the ~-f~ of ~--force~) and
    on any first line merely mentioning that text, e.g. as a grep
    pattern. Put the push, or the search, on its own command.
  - The auto-mode permission check refuses ~git rebase --skip~ and
    ~git checkout -B~. When a rebase stops on a commit master already
    carries (re-committed by the merge script), resolve each conflict to
    master's side; if nothing differs from ~HEAD~ any more, commit the
    next piece of work at that stop and ~git rebase --continue~.

** Generic signatures: test each spelling on its own

  - A ~func<G>~ generic and a ~func(G: Type, ...)~ generic that spell the
    same parametric type (~FnOf(G)~, ~Box(G)~) share ONE parser-lifted
    placeholder (~FnOf__G~). A test file declaring both proves only that
    the pair works: the #417 and #423 regression tests passed while
    ~func<G>~ alone still failed. Exercise each spelling in a file
    without the other.
